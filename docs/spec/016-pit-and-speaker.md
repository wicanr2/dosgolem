# 016：PIT 與 PC 喇叭（語音擷取）

狀態：`READY`

## 1. 要解決的問題

智冠《三國演義》最常被提到的特色是 **PC 喇叭語音**。它不是音效卡，
是拿一個位元的喇叭線路播數位取樣：把 8253 的**通道 0**（系統計時器）
重新設成幾千赫，在 IRQ0 的處理常式裡每次送出一個位元。

dosgolem 原本兩件事都沒有：

- 埠 `0x43`／`0x40` 的寫入只被記進 `PortLog`，**不影響 IRQ0 的頻率**。
  程式把分頻值改成 100（約 11.9 kHz）之後，dosgolem 仍然照
  `DefaultIRQ0Every` 每 165,000 道指令送一次——播一秒的語音要等
  一億八千萬道指令，而且取樣間距全錯。
- 埠 `0x61` 的喇叭位元沒有被當成波形收集。

## 2. 原版怎麼播（`L0`）

證據在開機鏈第二層（`DATA0.GRP`，dump `workplace/dump/code-000400.bin`，
基底 `0x400`）。段基底是線性 `0x5C40`，所以段內位移 ＝ 線性 − `0x5C40`。

### 2.1 開始播放（線性 `0x5cc5`，段內 `0x0085`）

```
mov  ax,0xFFFF
mov  cs:[0x1c],ax        ; 播放中旗標
mov  ax,0x3508
int  0x21                ; 取 int 08h 舊向量
mov  cs:[0x20],bx
mov  cs:[0x22],es
in   al,0x21
or   al,1
out  0x21,al             ; 先遮蔽 IRQ0
…
mov  bx,0x20             ; 0000:0020 ＝ int 08h 的向量
mov  ax,0xD7
mov  [bx],ax             ; 直接寫向量，不走 int 21h AH=25
mov  ax,cs
mov  [bx+2],ax
mov  al,0x36
out  0x43,al             ; 通道 0、先低後高、模式 3、二進位
mov  ax,cs:[0x1e]        ; ← 分頻值，就是說明書的「語音速度」
out  0x40,al
mov  al,ah
out  0x40,al
in   al,0x21
and  al,0xFE
out  0x21,al             ; 放行 IRQ0
sti
ret
```

`cs:[0x1e]` 就是 `README.DOC` 說的「語音功能可調整（1–30000，
16 MHz 機種約 100）」。分頻值越大 → 取樣率越低 → 慢機器才跟得上。

### 2.2 每一次 IRQ0 送一個位元（線性 `0x5d17`，段內 `0x00D7`）

```
mov  cx,cs:[0x36]        ; CH ＝ 目前這個位元組，CL ＝ 已經送幾個位元
xor  ax,ax
rcl  ch                  ; CF ← CH 的 bit7
rcl  ah                  ; AH bit0 ← CF
rcl  ah                  ; AH bit1 ← 同一個位元
in   al,0x61
and  al,0xFC
or   al,ah
out  0x61,al             ; 喇叭的 bit0/bit1 一起等於那個取樣位元
inc  cl
cmp  cl,8
jne  存回
sub  cl,cl
mov  bx,cs:[0x30]        ; 資料指標
mov  ax,cs:[0x32]        ; 資料段
mov  es,ax
inc  bx
mov  cs:[0x30],bx
mov  ch,es:[bx]          ; 取下一個位元組
cmp  bx,cs:[0x34]        ; 到結尾了嗎
jne  存回
call  停止
存回:
mov  cs:[0x36],cx
…
mov  al,0x20
out  0x20,al             ; EOI
iret
```

所以波形是 **1 位元 PCM，最高位先送**，一個位元組八個取樣。

### 2.3 停止（線性 `0x5d9f`）

清旗標、遮蔽 IRQ0、`out 0x43,0x36` 之後把分頻值寫回 `0`（＝65536），
也就是還原成 18.2 Hz。

## 3. 契約

### 3.1 PIT 通道 0

- 埠 `0x43`（控制字）：只認**通道 0**（bit7–6 ＝ 00）。
  存取模式（bit5–4）支援 `01`（只低位）、`10`（只高位）、`11`（低後高）。
  其他通道的控制字照舊只記進 `PortLog`。
- 埠 `0x40`（通道 0 資料）：依存取模式收一或兩個位元組組成分頻值。
  `0` 代表 65536。
- 分頻值換成指令數：

  ```
  IRQ0Every = DefaultIRQ0Every × 分頻值 ÷ 65536
  ```

  `DefaultIRQ0Every`（165,000）對應分頻值 65536，也就是 18.2065 Hz，
  所以這條式子等於「維持每秒約 300 萬道指令的機器速度」。

- **下限 `MinIRQ0Every`（64 道指令）**。分頻值可以小到 1
  （約 1.19 MHz），照算會變成每兩道指令一次中斷——處理常式自己
  跑不完，機器會卡死在中斷裡。**卡死看起來像當掉不像設定太快**，
  所以下限要有，而且被夾到時要記一次
  （`Machine.IRQ0Clamped`），不能安靜地夾。

### 3.2 喇叭

- `Machine.Speaker` 是取樣序列，每一筆是 `{Step, Level}`；
  `Level` 是埠 `0x61` 的 bit1（喇叭資料線）。
  **只在值改變時記一筆**，重複寫同一個值不佔位置。
- `Machine.SpeakerGate` 記 bit0（PIT 通道 2 的閘門）。
  嗶聲走「通道 2 產生方波 ＋ 閘門打開」，語音走「閘門關著、
  直接切 bit1」——兩條路要分得出來，否則嗶聲會被當成語音收進波形。
- `oracle.Speaker()` 回那份序列；`oracle.SpeakerWAV(w, rate)`
  把它算成 8 位元單聲道 WAV。

  換算用的是**指令數對時間**：每秒指令數 ＝
  `DefaultIRQ0Every × 1193182 ÷ 65536`。這個常數是模型不是量測，
  改 `IRQ0Every` 不影響它——它定義的是「這台虛擬機跑多快」。

### 3.3 8259 的遮蔽（埠 `0x21`）

原版在改分頻值前後各遮蔽／放行一次 IRQ0。**這一版把 OCW1 的
bit0（IRQ0）與 bit1（IRQ1）接起來**：被遮蔽時中斷掛起不送，
放行時補送一次。

不接的話，遮蔽期間送進去的中斷會在程式還沒把向量與分頻值設好的時候
跑進處理常式——那是一段用到還沒初始化的變數的碼，結果不固定。

⚠ **埠 `0x21` 一定要讀得回自己寫進去的值。** 遮蔽的標準寫法是
「讀 → `or` → 寫回」，而 `In8` 對沒實作的埠回 `0xFF`：讀回 `0xFF`
再寫回去，就把**全部**中斷關掉了，包括鍵盤。症狀是之後按什麼都沒反應，
而畫面照樣在動——看起來像遊戲卡住，不像中斷被自己關掉。
開機值是 `0x00`（全部放行）。

### 3.4 快照

平面式 VRAM、喇叭序列、通道 0 的分頻值、`IRQ0Every` 與 8259 的遮罩
都進 `Snapshot`／`Restore`。

**平面式 VRAM 原本沒進快照**，而 `Machine.Mem` 只有 A0000 的線性檢視
——兩份是不同的資料。還原了線性那一份、平面留著後來畫上去的東西，
`IndexedEGA` 解出來的畫面就是兩次執行混在一起的，**而那張圖看起來
完全正常**，只是內容不對。快照本來就是拿來「同一個起點跑很多變體」的，
這種汙染會一路帶進每一個變體。

## 4. 驗收

1. 單元測試：合成一小段程式，設分頻值、切 `0x61`，檢查
   `IRQ0Every` 變了、`Speaker` 收到預期的位元序列、WAV 長度正確。
2. **正對照要拿原版**：把《三國演義》驅動到會出聲的地方
   （其他 → 8 語音 打開，音效也要開），確認 `Speaker` 非空、
   分頻值落在說明書講的 1–30000。
3. **負對照**：開場（`-steps 1500000000`）一個 `0x61`／`0x43`／`0x40`
   都不該寫——實測就是如此，只有 EGA 的六個埠。語音預設關閉，
   所以「沒收到聲音」在那裡是正確答案，不是功能沒接上。
