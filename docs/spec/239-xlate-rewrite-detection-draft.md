# 239 — 疊字層的改寫偵測

狀態：**CONFORMED**（2026-09-27：四輪獨立審查後 READY；§4 驗收 1–3 已跑，第 4 項由其他分支自行處理）
日期：2026-09-27
前置：[`202-translation-overlay`](202-translation-overlay.md) §2.3（逐格指紋、錨定格）。

## 1. 動態缺口

《Buck Rogers》舊選單家族在第 24 列先顯示 `Choose a FUNCTION `（已覆繪成中文），
原版接著在同一位置改印 `Pick Character `。兩串的第 8 格都是 `A`，那一格指紋不變；
其餘錨定格在同一次 `Frame` 被標成透明，但「錨定格**全部**失效」不成立，舊疊字只剩第 8 格
留在畫面上，用背景色把新字串的 `A` 蓋掉（畫面成 `PICK CH RACTER`）。
收據：Buck repo 讀檔路徑 `gld1`／`gld3`（2026-09-27）；關掉其他家族後仍重現，
舊選單家族單獨輸出（`-overlay-rgba-out`）同一格不同，已證實。

## 2. 契約

### 2.1 失效原因的區分

- 每一格記錄它變透明的原因：`Add`／`Clear` 的覆蓋（`cover`），或 `Shown` 指紋連續不同
  （`changed`）。快照一併保存；舊快照沒有這個欄位時一律當 `cover`（不觸發本規格）。
- 本規格只看原因為 `changed` 的錨定格。另一個框經 `Add`／`Clear` 蓋住一段所造成的透明格
  不計入。

### 2.2 移除條件（在 202 既有規則之後判斷）

每次 `Frame` 標記透明之後，對有錨定格的 `Shown` 疊字：

- 令 C = 本次 `Frame` 新變成 `changed` 透明的錨定格集合（以呼叫前後的透明狀態做差集，
  不是累積的透明格）。C 為空時不判斷。
- 把「仍有效的錨定格」依位置分成連續段。若存在某一段，長度不超過 2 格，而且它的左鄰與
  右鄰錨定格（跳過非錨定格）都屬於 C，則整筆移除，原因 `rewrite`。
- 若仍有效的錨定格總數不超過 2 格，且 C 的格數至少是仍有效錨定格數的兩倍，也整筆移除
  （`rewrite`）。（修訂：原本只要求「C 非空」，會讓只有 2–3 格的短疊字在只變 1 格時就整筆
  移除，違反 202 的局部遮蓋保護；由 202 既有測試 `TestInvalidateAfterThreeFrames`、
  `TestAnchorsGoneDropsWholeStamp` 發現。）
  （同字巧合落在行首或行尾時，第一條看不到兩側。）

### 2.3 依據與限度

- 「兩串文字在同一格同一個字」是巧合，通常只有一兩格；「另一個框蓋住一段」會留下一整段
  連續的有效格。2 格的上限與「同一幀」的要求都是**設計選擇**，不是從語料反推的門檻。
- 已知可能誤判的情境（假說，目前沒有樣本）：兩個不同來源在**同一幀**分別改寫同一行的左右
  兩段，而中間只剩 1–2 格未變。此時整筆移除，未被改寫的 1–2 格露出原版英文——
  寧可露出原文，不留遮罩。
- **已知漏抓（由條件 2 的算式直接推得，確定，不是假說）**：同字巧合落在錨定序列的最左或
  最右端時只能靠條件 2。設錨定格總數 N、仍有效 V，條件 2 需 N ≥ 3V 才觸發（V=1 需 N≥3，
  V=2 需 N≥6）。低於這個數時，「只有 2 個錨定格、一格局部變化」與「整段改寫、邊界巧合留一格」
  在格數上無法區分；本規格選擇不誤傷 202 的局部遮蓋保護，代價是這類短疊字的邊界巧合不移除，
  仍會留下一格遮罩。單元測試以「預期不移除」記錄此限制。
- 同一行逐字改寫、各格在不同幀達到 3 次失效時，條件只看「本次新變透明的格」，
  先失效的格不會被當成 C；最後一批格子失效的那一幀才可能觸發。這種情況可能晚幾幀才移除，
  不會提早。前提是同一次改寫的各格在同一次 `Frame` 一起跨過門檻（dosgolem 在機器停下來時
  才呼叫 `Frame`，改寫通常在兩次呼叫之間完成）；若日後遇到跨很多幀逐字慢速改寫的路徑，
  要重新驗證是否退化成永遠不觸發。

## 3. 不做什麼

- 不改 202 的逐格 3 次門檻、錨定格定義、`Clear`／`Add` 行為。
- 不處理沒有錨定格的疊字。

## 4. 驗收

1. 單元測試：
   - 改寫：`Choose a FUNCTION ` → `Pick Character ` 型態（中間一格同字）移除；
     同字在行首、行尾各一例移除；有效錨定格恰 2 格、本幀新失效格離得很遠也移除（刻意）。
   - 另一個框（`Clear`）從左、從右、中間各蓋一段：不移除，未蓋到的格照常顯示。
   - 指紋變化造成的一整段失效（蓋住右半）、左半有效超過 2 格：不移除。
   - 逐格在不同幀失效：不提早移除。
   - 已知限制：2 個錨定格的短疊字整段改寫、邊界同字，預期不移除。
   - 快照往返保存透明原因；舊快照當 `cover`。
2. `xlate` 與 dosgolem 全部既有測試通過。
3. Buck repo：讀檔路徑第 24 列不再殘缺；`phase254-live-families-parity` 七個腳本與上一輪相同。
