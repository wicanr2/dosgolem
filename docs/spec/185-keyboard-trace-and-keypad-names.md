# 185 — 鍵盤軌跡與數字鍵盤具名鍵

狀態：**READY**
日期：2026-09-09
前置：[`008`](008-bios-keyboard-injection.md)（`int 16h` 的按鍵注入）

---

## 1. 為什麼要做

《Pool of Radiance》的建角選單對送進去的方向鍵**完全沒有反應**，而三個既有
訊號全部正常：

| 觀測 | 值 |
|---|---|
| `int 16h AH=00` 回的字組 | `5000h`（掃描碼 `50h`、ASCII `00h`）——正確 |
| `KeysConsumed` | 每一步都加一——程式讀走了 |
| 逐幀比對五次 `Down` | `0, 0, 0, 0, 0` 個像素；下一個 `Return` 改了 990 個 |

**三個訊號都說「沒問題」，而畫面說「沒作用」。** 現有的計數答不出「是誰讀走
的、讀到什麼、它在哪一行」，所以每一輪都只能重送一次鍵再看畫面——那是抽樣，
不是量測（`rich2/CLAUDE.md` 的學習迴圈）。

追下去的答案與 dosgolem 無關（原版的選單元件把主鍵盤 `1`..`9` 當方位鍵，
擴充鍵在那一支被吞掉），但**要走到那個答案需要兩件工具**：一條「誰讀走了
哪個鍵」的軌跡，以及一組能明確表達「數字鍵盤的 2」的鍵名。

## 2. 契約

### 2.1 鍵盤軌跡：擴充既有的 `KeyReads`

`DOS` 早就有 `KeyReads []KeyRead`（「餵進去的鍵不見了的時候，看不出是誰吃
的」），但它只記 `Via` 與一個 ASCII byte，而且 `int 16h` 那條路**只有 Stdin
的分支在記**——BDA 環形緩衝與 `Keys` 佇列這兩條（方向鍵唯一能走的路）
一筆都沒有。所以不另建型別，補齊既有的那一份：

1. `KeyRead` 加 `Word`（完整字組）。**方向鍵這類沒有 ASCII 的鍵只看 `Key`
   會全部長成 0**，分不出是哪一個鍵。`int 21h` 那幾條沒有掃描碼，維持 0。
2. `KeyRead` 加 `CS`／`IP`（取走的當下）與 `CallerCS`／`CallerIP`
   （呼叫端的返回位址，從 `SS:BP` 那一層回溯）。
3. `int 16h AH=00h`／`AH=10h` 的**三條取走路徑都記**，`Via` 分別是
   `int16-AH00-bda`、`int16-AH00-queue`、`int16-AH00-stdin`。
4. **只記真的取走的那幾次。** `AH=01h` 的輪詢一秒鐘上百萬次，記它等於
   把訊號淹掉（`008` §2 量到 166 萬次）。

**為什麼回溯的是 `[BP+2]`／`[BP+4]` 而不是堆疊上的 `int` frame**：
`int` frame 只會指回 BIOS 呼叫點（Turbo Pascal 的 `ReadKey` 內部那一行），
每一次都一樣，答不出「哪一個選單在讀」。RTL 的 `ReadKey` 不動 `BP`，
所以那時的 `BP` 仍是**呼叫端**的 frame——實測 Pool：`c`、`1`、`Down`
三個鍵回溯到同一個 `1E03:02D9`，對回 overlay-26 的 `02D4` 一次命中。
這條回溯**依賴呼叫端有 `push bp; mov bp,sp`**（Turbo Pascal 一律有），
別的編譯器不成立時回溯值會是垃圾——所以它是線索，不是斷言。

### 2.2 數字鍵盤具名鍵

`namedKeys` 加一組 `KP0`..`KP9`、`KPDot`，送 **NumLock 關閉時**的掃描碼與
`ASCII 0`：

| 名字 | 掃描碼 | 對應 |
|---|---|---|
| `KP7` `KP8` `KP9` | `47h` `48h` `49h` | Home／Up／PgUp |
| `KP4` `KP5` `KP6` | `4Bh` `4Ch` `4Dh` | Left／Center／Right |
| `KP1` `KP2` `KP3` | `4Fh` `50h` `51h` | End／Down／PgDn |
| `KP0` `KPDot` | `52h` `53h` | Ins／Del |

`Up`／`Down`／`Left`／`Right` 已經是 `48h`／`50h`／`4Bh`／`4Dh`，與
`KP8`／`KP2`／`KP4`／`KP6` 同碼；**兩組都留著**，因為腳本要表達的是意圖
（「按方向鍵」還是「按數字鍵盤的 2」），而 `47h`／`49h`／`4Fh`／`51h`／`4Ch`
本來就沒有名字可用。

## 3. 驗收

- 送三個鍵、程式讀走三個，`KeyReads` 就多三筆；`Word` 與送進去的字組一致，
  方向鍵那一筆是 `5000h` 而不是 `Key = 0`。
- `Via` 分得出鍵是從哪一條出口走的。
- `KeyNamed("KP2")` 與 `KeyNamed("Down")` 的字組相同；`KeyNamed("KP1")`
  是 `4F00h`；不認得的名字仍回 false。
