# 013 — 滑鼠事件回呼（int 33h AX=000Ch）

狀態：READY（已實作＋單元測試＋原版對拍驗證）
日期：2026-09-06
適用：`internal/dos`（通用層；不含任何 per-binary 位址）

## 1. 為什麼需要它

`int 33h` 有兩條把輸入交給程式的路：**輪詢**（`AX=3` 問座標與鍵狀態、
`AX=5/6` 問按下與放開的累計次數）與**事件回呼**（`AX=000Ch` 登錄一個
far handler，驅動在事件發生時直接 call 進去）。

**程式可以只走其中一條，而兩條的失敗長得一模一樣。** 《銀河英雄傳說III SP》
的 `GIN3PS.EXE` 主選單就是這個情形：

| 觀測 | 數字 | 意義 |
|---|---|---|
| `AX=0003` | 245,446 次 | 一直在問座標——游標會跟著動 |
| `AX=0003` 回報「按著」 | 12,520 次 | 按鍵狀態**確實送進去了** |
| `AX=0005` | 1,051,434 次，但全在 `#50,368,552` 以前 | 那是前一支 `OPEN.EXE` 在用 |
| `AX=000C` | 1 次，遮罩 `001F`、handler `36AD:021D` | 主選單登錄了回呼 |

游標會動、按鍵狀態問得到、按下的統計也留著沒人領——畫面卻毫無反應。
補上回呼之後，同一組輸入序列立刻推進到下一個畫面。

## 2. 介面

`AX=000Ch`：`CX` ＝ 事件遮罩、`ES:DX` ＝ handler。遮罩與回呼時 `AX` 的旗標同一套：

| 位元 | 事件 |
|---|---|
| 0x01 | 游標移動 |
| 0x02 / 0x04 | 左鍵按下／放開 |
| 0x08 / 0x10 | 右鍵按下／放開 |
| 0x20 / 0x40 | 中鍵按下／放開 |

回呼時：`AX` ＝ 事件旗標、`BX` ＝ 目前鍵狀態、`CX`／`DX` ＝ 虛擬座標
（`CX` 同樣要乘上 `XScale`，見 spec 012 §2）、`SI`／`DI` ＝ mickey 位移。
handler 以 `retf` 返回。

## 3. 怎麼實作（`internal/dos/mouseevent.go`）

`DOS.MouseEvent(flags)` 在 **CPU 指令邊界**被呼叫，做四件事：

1. 遮罩不合、沒登錄 handler、或已在回呼中 → 不做事（不重入）。
2. 存下暫存器、段、`IP`、`Flags`（**只存這些**——整份複製 `cpu.CPU` 會把
   `IntHook`、`Model` 這類設定也一起倒回去）。
3. 往程式自己的堆疊推一組 far 返回位址，指向 stub 段第 `0FFh` 格；
   那一格的內容是 `CD FF`（spec 011 §3 的逐向量 stub）。
4. 設好 `AX`/`BX`/`CX`/`DX`/`SI`/`DI`，`CS:IP` 跳進 handler。

handler 的 `retf` 會跳到哨兵那一格，執行 `int 0FFh` 落回中斷分派，
`cbReturn` 把第 2 步存的狀態裝回去，控制權就回到被打斷的那道指令。

**用既有的 stub 當哨兵，不必在 CPU 挖新鉤子**：`0FFh` 沒有任何程式會用，
而 stub 段本來就每一號都有一格。

## 4. 呼叫端的責任

注入輸入的那一層（`cmd/probe` 的 `-clicks`、`oracle` 的 `Click`）在改完
`Mouse.X/Y/Buttons` 之後要跟著送對應的旗標。**只改狀態不送事件，
對只走回呼的程式等於什麼都沒做。**

## 5. 驗收

- 單元測試 `TestMouseEventCallsHandlerAndReturns`：登錄 handler → 送左鍵
  按下 → CPU 跳進 handler、參數正確 → 執行 `retf` → 暫存器與 `CS:IP` 復原。
- 單元測試 `TestMouseEventRespectsMask`：遮罩不含該事件時不得跳。
- 原版對拍：`GIN3.COM` 同一組輸入序列，補回呼前後畫面不同
  （前：主選單原地不動；後：進入下一個畫面）。

## 補充（2026-09-07）：只改座標不算移動

`-mouse-x`／`-mouse-y`／`-mouse-at` 原本只寫 `Mouse.X`／`Mouse.Y`，
**沒有送 `EvMove`**。遊戲的游標是靠事件回呼畫的，所以那樣做的結果是：
舊位置那隻游標不會被擦掉，新位置也不會畫出來——畫面上留著一隻停在
原地的游標，看起來像「滑鼠根本沒動」。

`-clicks` 一直都有送（它在按下前 200,000 道指令先送一次 `EvMove`），
兩邊行為不一致。現在 `-mouse-at` 也送。

**影響到的收據**：11 份主選單 hover 量測（`hov170`…`hov295`）內容改變，
重跑後主選單的逐位元組對拍仍然通過。
