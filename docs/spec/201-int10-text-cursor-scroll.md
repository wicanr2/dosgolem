## 1. 規則

BIOS 資料區（`0040:xxxx`）的欄位，名稱沿用 DOSBox-X `int10.h`：

| 位移 | 名稱 | 意義 |
|---|---|---|
| `4Ah` | `NB_COLS` | 欄數（word） |
| `4Ch` | `PAGE_SIZE` | 一頁的位元組數（word） |
| `4Eh` | `CURRENT_START` | 目前顯示頁在視訊記憶體裡的起點（word） |
| `50h`＋頁×2 | `CURSOR_POS` | 每頁一組：先欄、後列（各 1 byte），共 8 頁 |
| `60h` | `CURSOR_TYPE` | 游標形狀（word） |
| `62h` | `CURRENT_PAGE` | 目前顯示頁 |
| `84h` | `NB_ROWS` | 列數 − 1 |

「文字模式」指目前模式（`0040:0049`）為 `00h`–`03h`，畫面在 `B800:0000`。單色模式 `07h` 不在範圍。

### 1.1 `AH=02h` 設游標位置（所有模式）

`DH` ＝ 列、`DL` ＝ 欄、`BH` ＝ 頁。把 `DL` 寫到 `50h+BH*2`、`DH` 寫到 `51h+BH*2`。
不檢查範圍（DOSBox-X 為了 Bad Dude 把列的範圍檢查關掉了）。硬體游標（CRTC `0Eh`／`0Fh`）不在範圍。
`BH > 7` 時 DOSBox-X 只記 log、照樣寫；本規格同樣照寫，位址落在 `60h` 之後也不擋。

### 1.2 `AH=03h` 取游標位置與形狀（所有模式）

`DL` ← `50h+BH*2`、`DH` ← `51h+BH*2`、`CX` ← `60h` 的 word；`AX` 不動。

開機時 `60h` 設為 `0607h`（DOSBox-X 在 mode set 呼叫 `INT10_SetCursorShape(6, 7)`）。

### 1.3 `AH=06h`／`07h` 捲動視窗（文字模式）

`CH`,`CL` ＝ 左上列、欄；`DH`,`DL` ＝ 右下列、欄；`AL` ＝ 行數；`BH` ＝ 填空白用的屬性。
`AH=06h` 往上捲、`AH=07h` 往下捲。頁固定是目前顯示頁：起點 ＝ `B800:0000` ＋ `CURRENT_START`。

1. 左上列 > 右下列、或左上欄 > 右下欄：什麼都不做。
2. 右下列 ≥ 列數時夾到列數 − 1；右下欄 ≥ 欄數時夾到欄數 − 1。
3. `AL` 當有號 8 位元（DOSBox-X 以 `int8_t` 傳入）；`AL ＝ 0`，或 `|AL|` 大於視窗列數，整個視窗填空白。
4. 否則往上捲：第 `r` 列（從上而下）複製自第 `r+AL` 列，最下面 `AL` 列填空白；
   往下捲：第 `r` 列（從下而上）複製自第 `r−AL` 列，最上面 `AL` 列填空白。複製只限左欄到右欄。
5. 填空白 ＝ 每格寫 word `BH<<8 | 20h`。

**與 DOSBox-X 的差異**：`|AL|` 大於視窗列數時 DOSBox-X 的迴圈起點會以 8 位元回繞，複製到視窗外；
本規格改為清整個視窗（IBM BIOS 技術手冊對 `AL` 超過視窗高度的行為沒有規定，清視窗是不寫出視窗外的最小選擇）。

**非文字模式**維持現狀（不動記憶體）；圖形模式的 BIOS 捲動不在本規格範圍。

### 1.4 `AH=08h` 讀游標處的字元與屬性（文字模式）

`BH` ＝ 頁；`BH ＝ FFh` 表示目前顯示頁。位址 ＝ `B800:0000` ＋ 頁 × `PAGE_SIZE` ＋（列 × 欄數 ＋ 欄）× 2，
列、欄取該頁的游標位置。`AX` ← 該位址的 word（`AL` 字元、`AH` 屬性）。非文字模式維持現狀（記錄未實作）。

### 1.5 `AH=09h`／`0Ah` 在游標處寫字元（文字模式）

`AL` ＝ 字元、`BL` ＝ 屬性、`BH` ＝ 頁、`CX` ＝ 次數。從該頁游標位置開始寫 `CX` 格，欄到欄數時換到下一列第 0 欄；
**游標不前進**。`09h` 寫字元與屬性，`0Ah` 只寫字元、屬性位元組不動。
非文字模式維持現狀（不動記憶體）。

### 1.6 不在範圍

`AH=00h` 設模式時清畫面與重設游標、`AH=01h` 游標形狀、`AH=05h` 切換顯示頁、`AH=0Eh` 把字元寫進畫面
（目前只收進 `Console`）、單色模式 `07h`、圖形模式的字元輸出與捲動。這些維持現狀。

## 2. 觸發案例

Borland C++ 2.0 的 conio（`directvideo = 1`）直接寫 `B800`，但游標位置靠 `AH=03h` 讀、`AH=02h` 寫，
清畫面與多列捲動交給 `AH=06h`／`07h`。dosgolem 原本把 `02h`／`03h`／`06h`／`09h`／`0Ah` 全部當成空操作：
`AH=03h` 永遠回 `DX` 原值，conio 以為游標一直在左上角，測試程式在 4 列視窗裡印 4 行字，
結果全部疊在第 1 列（`xDDDDDDDDD`），其餘列是 0。

## 3. 驗收

1. 測試：`AH=02h` 寫進 `0040:0050+頁×2`、`AH=03h` 讀回同值且 `CX ＝ 0607h`；
   反面對照：頁 1 的游標不影響頁 0。
2. 測試：`AH=06h` 在 4×20 視窗捲 1 列，最上列內容變成原第 2 列，最下列是 `BH` 屬性的空白，視窗外不動；
   `AL ＝ 0` 清整個視窗；右下角超出畫面時被夾住；`AH=07h` 方向相反。
3. 測試：`AH=09h` 寫 `CX` 格跨列、游標不動；`AH=0Ah` 屬性不變；`AH=08h` 讀回。
4. 測試：mode 13h 下 `AH=06h`／`09h` 不改 `B800` 的內容。
5. `tools/go.sh test ./...` 全綠。
6. Borland C++ 2.0 的 conio 測試程式（`window(1,1,20,4)`、印 4 行再印 `x`）在 dosgolem 裡，
   `gettext` 讀回的畫面是每列一行字、最後一列是捲動後的結果，不再全部疊在第 1 列。
