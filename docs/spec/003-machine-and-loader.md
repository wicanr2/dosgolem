## 1. 記憶體佈局

一塊平坦的 1 MB，加上幾個要**由我們自己填**的區域。
`rich2/docs/re/005` 那一輪的教訓是：**沒填的區域不會報錯，
只會讓程式讀到 0 然後走進另一條路**。

| 範圍 | 內容 | 狀態 |
|---|---|---|
| `0000:0000`–`0000:03FF` | 中斷向量表 | 要填 |
| `0040:0000`–`0040:00FF` | BIOS 資料區 | **要填**，`rich2/docs/re/005` 卡在這裡過 |
| `0050:…` | DOS 的雜項 | 未定 |
| PSP ＋ 程式 | MZ 載入之後 | 要建 |
| `A000:0000`–`A000:F9FF` | mode 13h 畫面（320×200）| 要給 |
| `B800:…` | 文字模式畫面 | 未定 |

### 1.1 BIOS 資料區：`0040:0010` 是決定性的那一格

`rich2/docs/re/005`「缺的是 BIOS 資料區」：模擬器完全沒建 BDA、
`0040:0000`–`0040:00FF` 全是 0 的時候，**BASIC 的 `SCREEN 13` 回
Illegal function call**。溯源四步到底：錯誤訊息的呼叫端 → `0x10934` 的
`push 1 / push 0Dh / push 2`（`0Dh` ＝ 13 ＝ mode 13h）→ runtime 的
`0x306A0` → `mov al, ds:410h`。

> **`0040:0010` 是裝置旗標（equipment flags），BASIC 拿它判斷顯示卡。**
> 讀到 0 就判定顯示卡不對。

建完整份 BDA 之後遊戲整個跑起來，資產一路載到 `SAVE_7.DSK` 與 `RICHA.RIX`。

**這一格的形狀就是「沒建的東西不會抱怨，只會給 0，而 0 是合法值」**
（`docs/spec/004` §1.3）。BDA 的其餘欄位照標準填，缺一格就少一個
「安靜地錯」的機會。

## 2. 中斷向量

**每一個向量都要指向一個合法位址**，否則取向量的程式會拿到 `0000:0000`
跳過去執行垃圾（`rich2/docs/re/005` §3.2）。

> ### `[HARD]` 但**不能全部指向同一個 `IRET`**
>
> 滑鼠偵測**直接讀 `0000:00CC`**（不走 `int 21h AH=35h`），
> 判準是「是不是 0:0」與「**指到的第一個位元組是不是 `CFh`**」。
> 兩個都命中就判定「沒有滑鼠驅動」，**而且不報錯**——
> `rich2/docs/re/005` 花了一輪才找到，逐行出處在 `rich2/docs/re/182` §2。
>
> 解法：`int 33h` 的 stub 開頭放 `90 CF`（`nop; iret`）。
> 其他向量要不要比照，未定——**但這一條已經是明確要求，不是猜測**。

## 3. MZ 載入器

輸入是**已經解包**的 `RUN_full.EXE`（`rich2/CLAUDE.md` §4.1：
`RUN.EXE` 是雙層打包 `LZEXE93(EXEPACK(本體))`，兩層都要先解）。

**本專案不做解包。** 解包工具在 `rich2/tools/`，產物由呼叫端給進來。
理由：解包只做一次，做在執行器裡等於每次跑都重做一遍，
而且會讓「載入器對不對」與「解包對不對」兩個問題混在一起。
