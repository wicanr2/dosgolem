# 210 — 保護模式 CMC 進位旗標反轉

狀態：**CONFORMED**（僅通用 CPU 指令形狀）
日期：2026-10-01

## 證據與邊界

固定 MOO2 1.31 `ORION2.EXE` SHA-256 `4e11be14217b4aafa1839f333bf5eba037f98b0c44e9e4752c96c464c260419f`；dosgolem 已綁定 DPMI 的合成環境探針在第 760 步、**dosgolem 重定位 LE 線性位址** `0x1515CA`，原始 opcode `F5` 失敗即關閉。DOSBox-X 2026.07.02 SDL2 heavy debugger、映像 `fd2-dosbox-x:debug-0d7b272b` ID `sha256:659e8abbf93646f59a1586341769bd4b8f3cd1c707859d7a5de4c56e4672b582`，在其 **CS:EIP** `0180:003755CA → 0180:003755CB` 擷取 `EFLAGS=0202h → 0203h`，EAX／EBX／ECX／EDX 與段、堆疊值不變。兩工具位址分開記錄，不能把相同低位數字視為獨立證據。由版控 `apps/moo2/tools/startup_probe_131.py --cmc` 重生的私有 `workplace/dosbox-moo2-dpmi/cmc-registers.json` SHA-256 `a77196163f3432ffb787d577d5f761c6f78b8f0877a76dbd2b6c34dec958fe36`。

[Intel® 64 and IA-32 架構軟體開發手冊第 2A 卷](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf) 定義 `F5` 為 `CMC`：只反轉 EFLAGS 的 CF，其餘旗標不變。原版樣本證實進入 CF=0 時變成 CF=1；CF=1 反向情形依公開 CPU 契約與獨立測試驗證。證據等級：此指令已證實；MOO2 完整啟動、PSP／環境可比性及玩家路徑仍未知。

## 擬議實作與驗收

在既有 32 位 CPU `CLC`／`STC` 控旗區增加無前綴 `F5`，只將 `EFlags` 的 CF 位元反轉，不觸及其他旗標、寄存器或記憶體；EIP 前進 1。現有未支援前綴繼續失敗即關閉。

測試 CF=0／1 兩側、其他旗標、寄存器、記憶體與 EIP；在固定 1.31 真檔但合成 DOS 環境的診斷中越過此點、記錄下一停點；`go test ./internal/cpu386 ./internal/machine -count=1` 與 `go test ./... -count=1` 通過。此結果不能替代正常玩家路徑的正式 dosgolem 對拍收據。

## 證據審查

固定雜湊的原版兩側斷點顯示只改 CF，與原始 `F5` 及 Intel 指令定義吻合；dosgolem 失敗點亦命中相同 opcode。這些證據足以核准**無前綴的通用 CPU 指令切片**為 READY。合成 PSP／環境與正式玩家畫面的未知仍保留，不核准任何玩法對齊聲明。

## 驗收結果

`go test ./internal/cpu386 ./internal/machine -count=1` 與固定原檔輸入的 `go test ./... -count=1` 通過。合成測試核對 CF 由 0 到 1、再由 1 到 0，其他旗標、寄存器、記憶體不變，16 位前綴拒絕。已綁定 DPMI 的固定原檔合成環境診斷越過第 760 步，下一停點為第 762 步、dosgolem 重定位 LE 線性 `0x1515CD` 的 `21 C8`。此結果僅驗收通用 CPU 切片。
