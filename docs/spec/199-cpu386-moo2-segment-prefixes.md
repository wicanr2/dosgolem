# 199 — MOO2 啟動鏈的段覆寫指令形狀

狀態：**CONFORMED**（僅限下列兩種 CPU 指令形狀）  
日期：2026-09-30

固定輸入為 MOO2 1996 版 `Orion2.exe`，SHA-256 `7ae2ac2e5904ca330009af2827279d889906b0b9b7a8854c38eb707a56e955b5`；以 [197](197-bound-mz-le-file-base.md) 的內嵌 MZ 基址載入。下述步數依暫掛 FD2 專屬 DOS 服務層的**隔離診斷**取得；該服務層的 selector 與環境並非 MOO2 實測值，步數不能當原版啟動或玩家路徑收據。

診斷第 45 步、dosgolem LE 線性位址 `0x1100B2` 的 bytes 是 `66 26 8C 1D ED 01 11 00`：`MOV ES:[0x001101ED],DS`，只寫 16 位元，ES 描述子決定實際線性位置；若描述子界限不足，整個 word 拒絕寫入。這是通用 `8C /r` 在 operand-size 及 ES 段覆寫下的絕對位址形狀。

越過後，診斷第 50 步、線性位址 `0x1100CF` 的 `3E BA 50 A1 1C 00` 是帶 DS 前綴的 `MOV EDX,0x001CA150`。此指令沒有記憶體運算元，DS 前綴不改變立即數、旗標或其他暫存器。實作只接受此 `3E BA` 形狀；其餘未支援的 DS 前綴組合仍失敗即關閉。

驗收：`go test ./internal/cpu386 ./internal/machine` 通過，合成測試分別覆蓋 ES 與 DS 使用不同 base、word 寫入寬度、越界拒絕，以及 DS 前綴對立即數 MOV 無作用。隔離診斷越過兩點，於第 65 步、線性位址 `0x1100FA` 停在 `28 C0 AA AA...` 的未支援 opcode `28`。下一正式閘門仍是獨立建立 MOO2 的 DOS 服務契約；不得將此診斷標為正式對拍。
