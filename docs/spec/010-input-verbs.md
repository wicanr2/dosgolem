# 010 — 輸入動作補齊：右鍵、瞬按、原地按、觀測

日期：2026-09-05
狀態：**READY**

---

## 1. 為什麼要做

五格對拍走的是「移到某點、按左鍵」這一種動作。要往戰術畫面、
彈出選單與 AI 行為走，現有的動作不夠：

| 缺的 | 為什麼非有不可 |
|---|---|
| **右鍵** | 原版的「取消／退回」是右鍵（臥龍傳專案 `docs/re/53` §3）。沒有它就退不出任何視窗 |
| **瞬按** | 彈出選單用長按會**當場選走第一列**。臥龍傳專案 `docs/playtest/54` 量過：`click;press` 在同一點按兩下會這樣，改成 5–60 ms 的瞬按才打得開選單 |
| **原地按** | 既有的擷取腳本大量用 `click:x,y;press`（移過去、再按一次）。要能照抄 |
| **讀原版的變數** | 這是不用 DOSBox 的重點。畫面只回答「長什麼樣」，行為要問記憶體 |
| **攔呼叫** | 「AI 選了哪個指令」不必從畫面猜——攔住分派器，它自己會說 |

## 2. 瞬按為什麼是規格不是參數

`Click` 預設按住兩百萬道指令。那個值是給**按鈕**用的：遊戲輪詢
`int 33h` 的頻率低，按太短會整個被跳過。

但**彈出選單相反**：選單開起來的那一瞬間如果按鍵還按著，
下一次 `AX=5` 輪詢會用當時的游標位置立刻選一列——而框外的游標
被夾到第 0 列，於是「第二列以後永遠點不到」。

⇒ 兩種目標要兩種按法，而且**沒有一個值兩邊都對**。
所以 `tap` 是一個獨立的動作，不是 `click` 的參數預設值。

## 3. 動作表

`apps/wolong/cmd/shot` 的腳本語法補上：

| 動作 | 語意 |
|---|---|
| `rclick:X,Y` | 移到 (X,Y) 按右鍵 |
| `press` | **原地**按左鍵，不移動 |
| `rpress` | 原地按右鍵 |
| `tap:X,Y[,N]` | 移到 (X,Y) 瞬按左鍵，按住 N 道指令（預設 20 萬）|
| `peek:OFF:N` | 印出 `ds:OFF` 起 N 個 byte（十六進位偏移）|
| `clock` | 印出遊戲日期（已有）|

`oracle` 這一層補 `Button(n)` 這個 `ClickOpt`，與既有的 `Hold`／`Hover`／
`Settle` 同一組。

## 4. 觀測：`Regs` 與 `watch`

`OnCall(addr, fn)` 已經有了，缺的是「進到那一支的時候暫存器是多少」。
補 `Oracle.Regs()`。

`shot` 補一個旗標 `-watch <IDA 線性位址>[,…]`：每次 CS:IP 走到那裡就印一行

```
#12345678 呼叫 1A2B3 AX=0003 BX=0000 CX=000C DX=0001 SI=… DI=… 來自 1F2A0
```

⚠ **這是取樣不是完整追蹤。** 一個位址一行，跑四千萬道指令可能印幾萬行；
要看某一支就只掛那一支，不要一次掛十個。

## 5. 怎麼驗

| 項目 | 驗收 |
|---|---|
| 右鍵 | 單元測試：`Button(1)` 之後 `AX=5 BX=1` 要看到一次按下，`BX=0` 要是 0 |
| 瞬按 | 按住長度真的變短（`Hold` 有傳下去）|
| 原地按 | `press` 不改變游標座標 |
| `peek` | 讀出來的日期與 `clock` 一致（同一份資料兩條路） |
| `watch` | 掛在一個**已知會被呼叫**的位址上要印得出東西——⚠ 掛在沒人呼叫的位址上印不出東西，與「沒接上」長得一模一樣，所以正對照要用已知的那一支 |
| 整體 | 五格對拍不得回歸 |
