# 194 — 交換使用者中斷向量（int 33h AX=0014h）

狀態：READY（已實作＋單元測試＋原版對拍驗證）
日期：2026-09-10
適用：`internal/dos`（通用層；不含任何 per-binary 位址）

## 1. 為什麼需要它

規格 [`013`](013-mouse-event-callback.md) 做了 `AX=000Ch`（登錄事件回呼），
但**登錄不只有一支 API**。`AX=0014h` 是「交換」版本：一次做完設定新的、
取回舊的兩件事，讓程式可以在自己的 handler 裡鏈回前一個，或在收工時原樣裝回去。

**用 `0014h` 的程式一次都不會叫 `000Ch`**，所以只做 `000Ch` 等於完全沒做。
《Dungeon Master》DOS 版就是這樣：

| 觀測（4 億道指令） | 數字 |
|---|---|
| `AX=000Ch` | **0 次** |
| `AX=0014h` | 5 次 |
| `AX=0003h`（輪詢座標） | 3 次 |

`AX=0003h` 只有 3 次，代表游標與命中判定**整條都靠事件回呼**。
`0014h` 落進 `default` 分支（`d.note`）時，`m.Handler.Set` 永遠是 `false`，
注入的移動與點擊全部排進佇列沒人領——畫面停在入口選單，
而 probe 報「程式還活著」、指令照跑、畫面照在。

⚠ **這一族的失敗是靜默的。** 沒實作的服務清單裡它只是一列
`int 33h AH=00 AL=14`，而症狀是「點了沒反應」——與座標算錯、
與遊戲根本沒讀滑鼠，三者的畫面表現一模一樣。

## 2. 介面

Microsoft Mouse Programmer's Reference（2nd edition, 1991）：

| 方向 | 暫存器 | 意義 |
|---|---|---|
| 入 | `CX` | 新的事件遮罩 |
| 入 | `ES:DX` | 新的 handler |
| 出 | `CX` | **舊的**事件遮罩 |
| 出 | `ES:DX` | **舊的** handler |

遮罩位元與回呼時 `AX` 的旗標同一套（見 `013` §2）。

語意等同「先讀出目前這一組、再照 `000Ch` 設定新的一組」，
所以實作共用同一份狀態，不另外開欄位。

## 3. 邊界

- **`CX=0` 一樣是停用**，與 `000Ch` 同（`013` §3）。停用之後 `Handler.Set`
  為 `false`，佇列裡還沒派送的事件不再派送。
- **沒登錄過時回什麼**：`CX=0`、`ES:DX=0000:0000`。真驅動回的是驅動自己的
  預設常式位址，但那個位址在我們這裡不存在——回 0 讓「程式把舊值裝回去」
  這條路等價於停用，而不是跳進一段不存在的碼。
  程式若真的 `call` 那個位址會停在 `0000:0000`，那是**看得見的失敗**，
  比跳進垃圾好。
- `ES` 是**輸出**：要在寫 `DX` 之前把舊的 `Handler.Seg` 放進去，
  順序寫反的話回傳的是呼叫端剛剛傳進來的那一份。

## 4. 驗收

1. 單元測試：登錄 A → 用 `0014h` 換成 B，回傳的是 A；再換回 A，回傳的是 B。
2. 單元測試：沒登錄過時 `0014h` 回 `CX=0`、`ES:DX=0`，而且新的那一組生效。
3. 原版對拍：《Dungeon Master》DOS 版入口畫面點 ENTER，
   畫面推進到下一頁（收據見 dungeon_master 專案的
   `docs/verification/dosgolem-dm-boot-20260910.md`）。
