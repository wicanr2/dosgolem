# 195 — 子目錄的路徑解析

狀態：READY（已實作＋單元測試＋原版對拍驗證）
日期：2026-09-10
適用：`internal/dos/files.go` 的 `resolve`

## 1. 為什麼需要它

`resolve` 到目前為止**只認 basename**（`004` §「檔名解析」、`009-scratch-writes` §、
`007-exec-ems` §）。這個取捨有明確的理由，而且要留著：遊戲常組出
`A:\<垃圾>\DATA.PAK` 這種多磁片版殘留的路徑，目錄部分對不上硬碟安裝版
（`rich2/docs/re/006` §5）。

但它對**真的把資料放在子目錄的遊戲**是失效的。《Dungeon Master》DOS 版的
硬碟安裝版把三個資料檔放在 `data\` 底下：

```
dm.exe  selector  fires  vga  ibmio  swoosh  anim  title
data\GRAPHICS.DAT  data\DUNGEON.DAT  data\SONG.DAT
```

主引擎 `fires` 開的是 `data\graphics.dat`，而 `resolve` 拿 `graphics.dat`
去 Root 的頂層找——不在那裡。症狀：

| | 沒有子目錄解析 | 有子目錄解析 |
|---|---|---|
| 找不到的檔 | `data\song.dat`、`data\graphics.dat`、`DATA\GRAPHICS.DAT` | 無 |
| `fires` 的離開碼 | 255（開不了圖形檔就收工） | 還在跑 |
| 畫面 | 停在片頭標題，16,647 非零像素 | **入口選單**，31,487 非零像素 |

⚠ **只認 basename 的失敗看起來不像檔案問題。** 遊戲不檢查開檔結果就往下跑，
最後停在某個等事件的迴圈；probe 報「程式還活著、畫面在、指令照跑」。
唯一的線索是「找不到的檔」那一列，而它排在輸出的中後段。

## 2. 規則

`resolve(name)` 依序試，先中的先回：

1. **完整路徑**（本規格新增）：把 `name` 正規化之後，在 `Scratch`、`Root`
   底下逐段大小寫不分地解析。
2. **basename**（既有行為，一個字都不改）：`Scratch` → `Root` 的頂層，
   大小寫不分，再試 8.3 截斷。

順序不能顛倒：先試完整路徑才能讓 `data\GRAPHICS.DAT` 對到子目錄那一份；
而完整路徑失敗時退回 basename，`A:\<垃圾>\DATA.PAK` 那條救援原封不動。

**正規化**：

- 去掉磁碟機代號（`C:`）——我們只有一個 Root，磁碟機代號沒有意義。
- `\` 一律當成分隔符（DOS 用 `\`，Go 用 `/`）。
- 開頭的分隔符去掉：`\DATA\X.DAT` 與 `DATA\X.DAT` 都相對於 Root。
  真 DOS 的絕對路徑相對於磁碟機根目錄，而我們的 Root 就是那個根目錄。
- **`.` 略過、`..` 讓整條路徑不合格**（回空，退回 basename）。
  不能讓遊戲組出來的路徑走出 Root——那是拿模擬器當檔案總管。
- 空的一段（`DATA\\X.DAT`）略過。
- 只有一段時等價於 basename，但仍走第 1 條（結果相同，不必特判）。

**逐段解析**：每一段先直接 `Stat`，不中就 `ReadDir` 大小寫不分地比。
中間段必須是目錄、最後一段必須是檔案；不合就整條失敗。
中間段**不做 8.3 截斷**——截斷是 FAT 對**檔名**的限制，
目錄名照樣受限但遊戲組出來的目錄名本來就是短的，
多一層猜測只會讓「找到了但是別的檔」變得可能。

## 3. 目前磁碟機（`int 21h AH=0Eh`）

DM 在啟動時叫 `AH=0Eh AL=02h`（選 C:），這一支之前落在「沒實作」。
它與路徑解析是同一件事的兩面：程式宣告它期待的磁碟機，之後組出來的路徑
就會帶 `C:` 前綴。

- `DL` ＝ 磁碟機（0 ＝ A），存進 `d.Drive`（`AH=19h` 讀的就是這一格）。
- 回傳 `AL` ＝ 磁碟機數量。回 `3`（A、B、C）——**不是 1**：
  回 1 的話遊戲會判定沒有硬碟。
- **不驗證磁碟機存不存在。** 我們只有一個 Root，任何磁碟機都對到它；
  §2 的正規化本來就把磁碟機代號丟掉。

## 4. 邊界

- **不做多磁碟機。** `009-scratch-writes` §5 的「`Scratch` 只有一個」照舊。
  磁碟機代號被丟掉，不是被解析。
- **不做真的目前目錄。** `AH=3Bh`（`chdir`）維持既有語意（記下 `d.Dir`、
  標記目錄是假的）；本規格的相對路徑一律相對於 Root，不接 `d.Dir`。
  接上去要先讓 `chdir` 真的驗證目錄存在，那是另一輪。
- **寫入不放寬。** `AllowFileWrites` 的比對照舊用 basename（`004` §）。

## 5. 驗收

1. 單元測試：子目錄裡的檔案用 `data\X.DAT`、`DATA\x.dat`、`C:\data\X.DAT`
   三種寫法都開得到。
2. 單元測試：`..` 回空；目錄部分對不上時退回 basename（既有行為不變）。
3. 單元測試：`AH=0Eh` 設過之後 `AH=19h` 讀得到同一個值，`AL` 回 3。
4. 原版對拍：《Dungeon Master》DOS 版「找不到的檔」清空，畫面推進到入口選單
   （收據見 dungeon_master 專案的 `docs/verification/dosgolem-dm-boot-20260910.md`）。
