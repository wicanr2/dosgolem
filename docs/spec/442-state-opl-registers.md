# 442 — 狀態檔保存 OPL 暫存器，混音器從暫存器起播

狀態：**READY**
日期：2026-10-18
前置：[`439-state-pit-port-divisor`](439-state-pit-port-divisor.md)、[`440-mixer-cd-audio`](440-mixer-cd-audio.md)
案例：三國志V（san5）從狀態檔接續後的音效

---

## 1. 為什麼要做

`Machine` 有 OPL 的暫存器檔（`oplRegs`）、兩組索引（`oplReg`）與計時器旗標，狀態檔都沒存。
`-load-state` 之後三者都是 0：`OPLRegs()` 讀到的不是程式寫過的值，計時器狀態埠的讀值也變了；
混音器的合成器從空白開始，狀態檔之前就在發音、之後沒有再寫的聲部聽不到。`440` §3 把後者列為 remake-owned，
到期條件是狀態檔加入 OPL 暫存器。

對三國志V 的實際影響很小（量測：`wicanr2/san5-remake` 的 `docs/re/014-san5-audio.md`）：從 4 億道指令的狀態檔接續跑到第一個音效，
prime 與不 prime 的混音逐位元組相同。三國志V 每個音效都重寫整組音色暫存器；開機時 FMOPL2 寫的 `01h = 20h`（波形選擇）在
`audio/nukedopl` 本來就沒有作用，因為它照 OPL3 的行為不看這個位元。本規格補的是機器狀態的正確性，以及跨狀態檔持續發音的聲部。

## 2. 語意

### 2.1 狀態檔

- 狀態檔多四個欄位：`OPLIndex [2]uint8`（兩組的暫存器索引）、`OPLRegs [2][256]uint8`（暫存器檔）、
  `OPLTimers uint8`（位元 0 計時器 1 啟動、1 計時器 2 啟動、2 計時器 1 遮罩、3 計時器 2 遮罩）。讀回時照原樣設回。
- 不改版本號。舊狀態檔讀進來是零值，行為與以前相同。

### 2.2 `Mixer.PrimeOPL(bank0, bank1 [256]uint8) int`

- 把暫存器檔寫進合成器，讓合成器的暫存器與機器一致。只寫值不為 0 的暫存器（開機後的合成器暫存器本來就是 0），
  計時器暫存器 `02h`、`03h`、`04h` 不寫。
- 順序：第二組的 `05h`（OPL3 NEW 位元）先寫；接著第一組、再第二組，各自依位址遞增，但 `B0h`–`B8h`（key-on 與頻率高位）
  留到該組最後。位址換算沿用 `240` 的 `oplAddr`。NEW 位元（第二組 `05h` 的位元 0）沒設時，第二組除了 `05h` 都不寫：
  那時第二組的位址對到第一組，重寫會蓋掉第一組的值。
- 寫入走與事件相同的 `WriteRegBuffered`，在下一次 `Render` 產生第一個樣本之前生效。回傳寫入筆數。
- 合成器的內部相位、包絡與 LFO 計數不在暫存器檔裡，不還原。

### 2.3 呼叫端

- `probe -dump-mix-wav` 與 `cmd/play` 在掛上混音器時呼叫 `PrimeOPL(m.OPLRegs(0), m.OPLRegs(1))`。從開機跑時暫存器全是 0，不寫任何東西，
  輸出與以前逐位元組相同。

## 3. 已知差異

| 項目 | 本實作 | 來源 | 分類 |
|---|---|---|---|
| 合成器內部狀態 | 相位、包絡、LFO 從頭開始 | 實機晶片連續運轉 | remake-owned。狀態檔存讀之間正在發音的聲部會從 attack 重來；到期條件：需要逐樣本對拍跨狀態檔的聲音時 |
| `oplPresent` | 不存，照命令列 `-adlib` | 狀態檔之前就是如此 | 不變 |
| 波形選擇開關（`01h` 位元 5） | 合成器不看，波形選擇永遠有效 | YM3812 沒開時只有正弦波 | 既有行為（`audio/nukedopl` 照 OPL3），本規格不改。開了這個位元的程式（如三國志V）結果相同 |

## 4. 驗收

1. `internal/machine` 的 `TestStateKeepsOPLRegisters`：寫幾格暫存器（含第二組與計時器控制 `04h`）後存讀，`OPLRegs`、索引與狀態埠讀值相同。
2. `audio/mixer` 的 `TestPrimeOPLRestoresVoice`：手寫一個發音中聲部的暫存器檔，`PrimeOPL` 後 `Render` 有聲音；不 prime 時靜音。
   `TestPrimeOPLSkipsZeroAndTimers`：全 0 的暫存器檔寫 0 筆；只有 `02h`–`04h` 有值時寫 0 筆；NEW 位元沒設時第二組的其他暫存器不寫。
3. 負對照：狀態檔不設回 `oplRegs`，第 1 條必須失敗；`PrimeOPL` 改成什麼都不寫，第 2 條的第一個測試必須失敗（2026-10-18 手動確認後還原）。
4. 三國志V：從開機存的狀態檔（4 億道，遊戲主畫面之前）接續跑到 4.7 億道，`-dump-mix-wav` 寫出起始暫存器 38 筆。
   與從開機跑的同一段相比，逐樣本相同 88.4%，10 毫秒 RMS 包絡的相對誤差 3.3%（合成器內部狀態不還原，見 §3）；
   不 prime 的建置輸出與 prime 的逐位元組相同（理由見 §1）。
