# 規格031：EOB1 LEVEL1首次場景放回

狀態：**CONFORMED**

## 證據與契約

由規格030的正常持石狀態，再點同一原版DOS current-left安全點`(44,110)`，等待原版完成
場景重畫後將游標移到`(300,190)`：

- 人工檢視可見左近區再次出現兩件地面物品，游標由持有石塊恢復為一般箭頭；
- 底部既有`ROCK TAKEN.`訊息保持不變，放回不新增訊息；
- 固定時序下第一人稱安全矩形SHA-256為
  `4cf790c278d6a9115094c61eebacf894d13ad12a118403ed25056c42523352d2`，完整320×200色號為
  `9ce3f36cf412325f991ef4bf542361661376e840fb1fcc17436c1cb99028d9f3`；
- 鍵盤port `60h`讀取仍為84次，沒有混入鍵盤捷徑。

`ToLevel1FirstDrop`必須由冷啟動完成四人建角、PLAY及規格030拾取，再透過正式滑鼠callback
放回；不能載入存檔、注入物品或直接修改queue。放回後先跑2,000,000道指令，再移開游標，
使安全矩形不含箭頭覆蓋。

## 相位勘誤

原版地面物件具有時間相位；即使把游標移到相同位置，入口等待時間不同也會得到不同色號雜湊。
因此「放回後逐像素等於零操作入口」不是原版契約。雜湊只固定本adapter的精確輸入與時序，
玩法契約是物品重新出現在場景、手持游標清空且不產生新訊息。remake若在自身固定tick下恢復
入口frame，可保留為內部確定性，不得據此宣稱DOS逐像素parity。

## 來源與限制

來源、按鈕矩形與`clickedSceneDropPickupItem` consumer沿用規格030。此規格閉合第一件石塊的
拾取→放回雙向玩家交易，不外推內部item ID、circular queue bytes、其他位置或投擲行為。
原版截圖只供本機人工檢視，不提交或散布。
