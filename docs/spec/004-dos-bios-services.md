# 004 — DOS 與 BIOS 服務

狀態：**DRAFT**（規格未定案，**不要照這一份動手**）
日期：2026-09-04
既有實作可參考：`rich2/tools/dosemu.py`（unicorn 版）

## 1. 兩條貫穿全部的原則

這兩條是 `rich2/docs/re/005` 用整整一輪換來的，先寫死：

> ### 1.1 未實作的服務**只宣告成功，不碰呼叫端沒要求改的暫存器**
>
> 第一版對所有沒實作的 `int 21h` 功能都寫 `AX = 0`。那害死了「設中斷向量」
> 的迴圈——它拿 `AX` 當計數，被清成 0 之後 `AH` 就變 0，
> 而 `AH=00h` 正好是「結束程式」，於是程式在第 10 個呼叫就自殺了。

> ### 1.2 未實作的服務**會說謊，而且沒有痕跡**
>
> 所以每一個沒實作的功能號都要**記一筆**（功能號、呼叫端 CS:IP、次數）。
> 「跑不動」與「跑得動但行為不對」要能分開，靠的就是這份清單。

## 2. `int 21h`（未定案）

已知一定要有的（`rich2/docs/re/005`）：

| AH | 服務 | 備註 |
|---:|---|---|
| `19h` | 取目前磁碟 | |
| `25h`／`35h` | 設／取中斷向量 | 取向量**必須**回合法位址（`003` §2）|
| `2Ch` | 取時間 | |
| `3Dh`／`3Eh`／`3Fh`／`42h` | 開／關／讀／seek | 遊戲的資料檔都走這條 |
| `47h` | 取目前目錄 | |
| `4Ah` | 調整記憶體區塊 | **探測語意**，見 `003` §4 |
| `4Ch` | 結束 | |

`AH=3Fh` 讀 handle 0 是 BASIC 的 `INKEY$` ——**鍵盤輸入走這條**，
不是 `int 16h`（`rich2/docs/re/005`「輸入路徑」）。

**完整清單要用執行期統計產生**，不要照手冊列一份猜的。

## 3. `int 10h`（未定案）

`rich2/docs/re/005` §12：`RUN.EXE` 開機時跑一整套顯示卡偵測，
模擬器對 `int 10h` 一律放行、不設回傳值時，程式讀到垃圾就判定
「環境不支援」然後退出——**而且退出訊息不走 `int 21h`，所以主控台攔截收不到**。

至少要有：`AH=00h` 設模式、`AH=0Fh` 取模式、`AH=12h` 的子功能、
`AH=1Ah` 顯示卡組合碼。

## 4. `int 33h` 滑鼠（未定案）

`rich2/docs/re/005`：偵測通過之後遊戲會發 `AX=0/2/3/7/8`，
其中 `AX=7`／`AX=8` 設的範圍是 **X 0–639、Y 0–199**——
mode 13h 的標準慣例是「水平虛擬座標 ＝ 實際像素 ×2」。

⚠ **那一輪停在「點色塊沒反應」**：`AX=3` 確實輪詢到了正確的座標與按鍵狀態，
畫面卻不動；線索是遊戲呼叫過 `AX=2`（隱藏游標）卻**從沒呼叫 `AX=1`**。
那個不對稱要先查清楚。

## 5. 計時器（未定案）

`0CED:41A8(n)` ＝ 等 `n / 70.187` 秒（`rich2/docs/re/154`），也就是 PIT 的分頻。
要對到原版就得照抄 PIT 與 `int 08h`／`1Ch` 的頻率。
**`~/cht/dosbox` 是現成的參考實作**，讀它比自己推便宜。
