## 1. 三條貫穿全部的原則

這三條是 `rich2/docs/re/005` 用好幾輪換來的，先寫死：

> ### 1.1 未實作的服務**只宣告成功，不碰呼叫端沒要求改的暫存器**
>
> 第一版對所有沒實作的 `int 21h` 功能都寫 `AX = 0`。那害死了「設中斷向量」
> 的迴圈——它拿 `AX` 當計數，被清成 0 之後 `AH` 就變 0，
> 而 `AH=00h` 正好是「結束程式」，於是程式在第 10 個呼叫就自殺了。

> ### 1.2 **有些服務的「失敗」才是正確答案**
>
> 1.1 那條有一個致命的例外。`AH=4Ah`（setblock）是**記憶體探測**：
>
> ```asm
> 56C4  bx = 0FFFFh    ; 故意要求 0FFFFh 段
> 56C7  ah = 4Ah
> 56C9  int 21h
> 56CC  jae 錯誤       ; ★ 成功就跳「錯誤」
> 56CE  ah = 4Ah       ; 用 DOS 在 BX 回的實際大小再要一次
> 56D0  int 21h
> 56D3  jb  錯誤       ; 這次失敗才算錯誤
> ```
>
> 一律清 CF 報成功的話，**第一次呼叫就掉進錯誤路徑**。
> `rich2/docs/re/005` 連續三輪調 MCB 佈局都無效，就是因為問題不在 MCB。
> 正解：`want > avail` 時**設 CF**，並在 `BX` 回可用大小。

> ### 1.3 沒建的東西不會抱怨，只會給 0——而 0 是合法值
>
> 裝置旗標是 0、時間是 0、目錄字串是 0，每一個都會被下游當成真的資料用下去。
> 所以每一個沒實作的功能號都要**記一筆**（功能號、呼叫端 CS:IP、次數）。
> 「跑不動」與「跑得動但行為不對」要能分開，靠的就是這份清單。

### 1.2.1 `AH=4Ah` 成功之後 `freeSeg` 要跟著走——判準是**目前行程**的 PSP

`AH=4Ah` 把區塊撐大之後，那段記憶體就歸這個行程所有，`AH=48h` 不能再把它
配出去。判準是「調整的是不是**目前行程**的區塊」，不是「是不是主程式的 PSP」。

只認主程式 PSP 的話，EXEC 起來的子行程撐大自己的區塊之後 `freeSeg` 停在
它的映像結尾，接下來的 `AH=48h` **把子行程自己的記憶體再配一次出去**。
配到的緩衝區落在它的堆疊上，讀個檔就把堆疊上的返回位址換成檔案內容，
`retf` 跳到一個看起來很像程式碼的位址，然後在資料裡一路執行下去——
中間沒有任何一步會報錯。

> 實測（源平合戰 `OPEN.EXE`，`yuan/workplace/boot-20260906-05`／`06`）：
> `AH=4Ah` 撐到 8340 段（PSP `080F`，擁有到 `28A3`），`AH=48h` 卻從 `1A50`
> 配下去，`LOGO.GP` 的 8,043 bytes 蓋掉 `18A3:3832` 的返回位址，
> `retf` 跳進常駐驅動的資料表。修正後配置從 `28A5` 開始，開場 logo 正常畫出。

### 1.2.2 `AH=49h` 要真的把記憶體收回來

bump 配置器不夠用。DOSJP 先在常規記憶體要 **17,896 段（286 KB）**讀
`JIS.FNT`、搬進 XMS、再 `AH=49h` 還回來；不收的話那塊記憶體永遠佔著，
`OPEN.EXE` 的第四次 `AH=48h`（2,500 段）就失敗——然後它走記憶體不足的
路徑，飛到某個資料區去執行，中間沒有任何一步報錯。

實作範圍（照量測，不多做）：

- 記住每一塊 `AH=48h` 配出去的區塊；`AH=49h` 用 `ES` 對回去。
- 還回來的如果是**頂端**那塊，水位（`freeSeg`）直接降回去。
- 不是頂端就記成一個洞，下一次 `AH=48h` 先用 first fit 找洞，
  夠大就切一塊出來。
- **不合併相鄰的洞**：目前的語料只有「配一塊大的、用完還回來」這一種
  形狀。要合併等有需要再做，現在做等於憑空猜。
- `ES` 不是我們配出去的（程式自己的 PSP 區塊、重複釋放）就收下不做事，
  **不製造假的洞**。

> 實測（源平合戰，`yuan/workplace/boot-20260906-07`）：修正前官方鏈
> （`DOSJP` → `Genpei.com`）在 170,995 道飛掉；修正後跑滿 2,000 萬道
> 仍在執行，開場 logo 與繞過 DOSJP 那條路一致。

## 2. `int 21h`（**READY**）

### 2.1 服務入口是向量指向的 trampoline，不是只給 IntHook 攔

`dos.handle` 的既有規則是「程式裝了自己的向量就放行」——但**常駐程式
（TSR）會 chain 到舊向量**：它攔 `int 21h`、處理自己認得的功能號，
其餘 `call far [舊向量]` 丟回給 DOS。舊向量若指到一個什麼都不做的
`IRET` stub，**所有 DOS 服務在 TSR 落腳的瞬間全部陣亡**——而且不回錯，
open 只是安靜地不回來（源平合戰的 DOSJP 就是這樣：它掛走 int 21h 之後
自己的 `AH=3Dh` 開檔再也到不了 DOS，卡在讀檔迴圈，AX 還停在 3D00h）。

解法：服務型中斷的向量指向 StubSeg 裡的 **trampoline**——
`CD Fx / CF`（發一個保留向量當陷阱，回來就 IRET）。IntHook 認得
陷阱向量並分派到真正的服務；TSR chain 回舊向量時就走到這裡。
真機上「DOS 的 int 21h entry」就是一段這樣的位址，這不算作弊。

| 服務 | 向量目標 | 陷阱向量 |
|---|---|---|
| `int 21h` | StubSeg:60h | `int F2h` |
| `int 10h` | StubSeg:64h | `int F3h` |
| `int 15h` | StubSeg:68h | `int F4h` |

出處 `rich2/docs/re/005` §10／§11 與「現況」那幾節——那一輪把 `RUN.EXE`
跑到資產全部載完（`DATA.PAK`／`PART1.PAK`／`SAVE_7.DSK`／`RICHA.RIX` 都開了），
所以這張表是**跑出來的**，不是照手冊列的。

| AH | 服務 | 備註 |
|---:|---|---|
| `19h` | 取目前磁碟 | |
| `25h`／`35h` | 設／取中斷向量 | 取向量**必須**回合法位址（`003` §2）|
| `2Ch` | 取時間 | |
| `3Dh`／`3Eh`／`3Fh`／`42h` | 開／關／讀／seek | 遊戲的資料檔都走這條 |
| `47h` | 取目前目錄 | |
| `48h` | 配置記憶體 | bump 配置器；`avail` **要夾在 0**，見 §1.3 |
| `49h` | 釋放記憶體區塊 | **真的要收**：頂端降水位、其餘記成洞給 first fit 用，見 §1.2.2 |
| `4Ah` | 調整記憶體區塊 | **探測語意**：`want > avail` 要**設 CF** 並在 `BX` 回可用大小，見 §1.2；成功時要真的改界線，若調整的是**目前行程**的區塊，`freeSeg` 要跟著移到區塊之後，見 §1.2.1、§1.3 |
| `4Bh` | EXEC／載入 overlay | `AL=00h` 執行、`AL=03h` 只載入，見 `007` §2 與 §2.5；`AL=01h` 尚未實作 |
| `4Ch` | 結束 | |

缺檔診斷除了保留原始檔名，也保存呼叫當下的 `CS:IP`、`DS:DX`、`SS:BP` 與最多八層
BP 鏈；每層同列返回 `CS:IP`、附近 16 bytes 及前四個 stack 參數。這些欄位只提供可回查的
執行期定位，不會把推測性函式語意寫進 oracle。

檔案 handle 依 PSP 預設 20-entry JFT 配置：0～4 保留，open 取 5～19 中最低可用 entry，
close 後立即可重用；表滿以 CF=1、AX=4 失敗。不得單調遞增 handle，否則長時間執行會讓
原版 C runtime 的 handle metadata 固定表越界。

### 1.4 handle 號碼要重用，而且有上限

真 DOS 從 JFT 挑第一個空位，所以「開→關→開」拿到的是同一個小號碼，
一個程式同時開得起 20 個（要更多得用 `AH=67h`）。

只增不減的話開關幾十次之後號碼就爬到 20 以上，而遊戲常拿 handle 當自己那張
表的索引。**症狀完全不像 handle 的問題**：《武士傳說》的表存著「這個 handle
上次 seek 到哪」，越界之後新開的檔繼承了別人的位置，於是該發的 `AH=42h`
整個沒發——解壓器從檔案開頭讀到目錄本身，程式停在走不完的字典鏈裡，
看起來像 LZW 解壓器寫錯了。

檔案軌跡（`FileOps()`）要記開、關與**失敗的呼叫**。原本 handle 無效就直接
返回不留紀錄，於是「對錯的 handle seek 之後照樣讀」這個形狀在軌跡裡看起來像
根本沒呼叫 seek。

### 1.3 記憶體服務回報成功還不夠，界線要真的動

`AH=4Ah` 成功之後 bump 指標必須跟著走，**增與減都是**：

```
迴圈： bx=1 / ah=48h / int 21h / jc 收工     ; 配 1 段
       bx=0FFFFh / ah=4Ah / int 21h / jc 重試 ; 撐到最大
       es:[0]=cx / cx=es / jmp 迴圈           ; 串成鏈
```

這是「把所有記憶體配光」的標準慣用法（`KOL.EXE` 的 `0110:209F`…`20BC`）。
擴大只報成功而不吃掉後面的空間，迴圈**永遠不會結束**——它一路配到程式
自己的映像上，那句 `mov es:[0], cx` 於是把自己的碼改掉了
（`int 21h` 變成 `int 19h`）。症狀是**程式碼莫名其妙被寫壞**，
看起來像模擬器把記憶體寫爛，而不像配置器算錯。

反過來，縮小之後那段空間在真 DOS 是還回去的。`KOL.EXE` 配光之後縮回四段、
緊接著就要那四段；不還的話它判定記憶體不夠，主控台只留一行
`run-time error R6006`。

bump 配置器沒有 MCB 鏈，所以**只有最後一塊（或程式自己的 PSP）能縮放**；
動到中間那塊只報成功，不移動界線。

`avail` 一定要夾在 0：直接寫 `MemTop - seg` 的話，指標越過 `MemTop` 之後
uint16 環繞成 `0FFFFh`，配置就**永遠成功**——那個迴圈會配到 `0FFFFh` 段
再繞回低位，把整台機器的記憶體覆蓋掉。

`AH=3Fh` **讀 handle 0 要回一個 byte，不能回 EOF**——回 EOF 的話程式會死在
`0x16cb:0x4be8`（`rich2/docs/re/005`「死點修掉了」）。

`AH=3Fh` 讀 handle 0 是 BASIC 的 `INKEY$` ——**鍵盤輸入走這條**，
不是 `int 16h`（`rich2/docs/re/005`「輸入路徑」：`int 16h` 全程只被呼叫
20–40 次，閒置期間完全沒動；`AH=3Fh` 讀 handle 0 實測 42 次／100 切片）。

**檔名是執行期組出來的**，前面帶著路徑前綴（`A:\…\256.PAT`），
所以靜態在映像裡找不到引用是必然的（`rich2/docs/re/006` §5）。

檔名解析因此按 basename、大小寫不分，**而且要截成 FAT 的 8.3**（主檔名前 8 個
字元、副檔名前 3 個）。KOL 傳 `steedpics` 進來，真 DOS 開到的是 `STEEDPIC`。
不截的話這裡回「找不到檔」，而程式多半不檢查開檔結果——KOL 是一路跑進沒有映射
的記憶體才停，**看起來像模擬器壞了，其實只是檔名沒對上**。截斷只在原名找不到時
才試，所以 `DATA.PAX` 不會因此開到 `DATA.PAK`。

**這張表不是封閉的**：沒列到的功能號要照 §1.3 記一筆，不要靜靜地放行。

### 2.1 一般檔案寫入覆蓋層（CONFORMED）

- `AH=40h`預設仍只記錄寫入企圖並回成功，絕不修改Root；既有oracle行為不變。
- 只有呼叫端明確以`AllowFileWrites`列出單一basename，而且該檔已存在於Root、以DOS寫入模式
  開啟時，才把bytes寫到目前handle位置。拒絕路徑、子目錄、缺檔與非一般檔案。
- 呼叫端必須把Root指向可丟棄覆蓋層；原版來源不得啟用。EOB1正式可寫測試另用
  `EOB1_ORACLE_WRITABLE_EXE／ROOT`，不重用一般唯讀環境變數。
- 單元測試固定預設不落地、允許後落地及路徑逃逸拒絕；EOB1正常Save Game另固定九段寫入交易。

## 3. `int 10h`（**READY**）

`RUN.EXE` 開機時跑一整套顯示卡偵測。模擬器對 `int 10h` 一律放行、
不設回傳值時，程式讀到垃圾就判定「環境不支援」然後退出——
**而且退出訊息不走 `int 21h`，所以主控台攔截收不到**
（`rich2/docs/re/005` §12）。

那一套偵測序列共 7 個呼叫：

| 功能 | 要回什麼 |
|---|---|
| `AH=0Fh` 取目前模式 | `AL` ＝ 模式、`AH` ＝ 欄數、`BH` ＝ 顯示頁 |
| `AH=1Bh AL=02h` 取 VGA 功能／狀態表 | 在 `ES:DI` 填一份 |
| `AH=12h` EGA／VGA 替代選擇 | ⚠ **子功能選擇子在 `BL`，不是 `AL`**——查 `AL` 的話那個分支永遠不成立 |
| `AH=EFh` 特殊顯示卡偵測 | |
| `AH=11h AL=30h` 取字型資訊 | 在 `ES:BP` 回字型指標 |
| `AH=05h` 設顯示頁 | |
| `AH=03h` 取游標位置 | |
| `AX=1012h` 設DAC色彩區塊 | `BL`起始色號、`CX`色數、`ES:DX`指向6-bit RGB三元組 |

EOB1 `START1.EXE`正常`44Y`路徑在載入`EOB.EXE`後以`AX=1012h`、`BX=0000h`、
`CX=0100h`、`ES:DX=4BF8:0005`上傳完整256色調色盤。只填像素索引而吞掉這個服務，
會得到64,000個非零色號但整張PNG全黑；這是已觀察的正常玩家路徑阻塞。

另外要有 `AH=00h`（設模式，遊戲設的是 **mode 13h**）與 `AH=1Ah`（顯示卡組合碼）。

> `rich2/docs/re/002` §4 記著遊戲會寫 `out 3CDh`（Tseng ET4000 的 bank switch），
> 所以偵測到的卡種可能影響後續路徑——DOSBox 那邊設 `machine=svga_et4000`
> 就是這個理由（`rich2/docs/playtest/001` §1）。
> **先讓它認得出 VGA**，真的走進 ET4000 的路再說。

## 4. `int 33h` 滑鼠（**READY**，出處 `rich2/docs/re/182`）

**滑鼠走標準 `int 33h`。** 先前懷疑「`RUN.EXE` 照 `RICH.JOY`／`JOYMOUSE.CFG`
自己讀埠」已經推翻——全檔連 `JOY`／`CFG`／`MOUSE` 三個字串都沒有，
那兩個設定檔是 `JGAME.EXE`／`JS3.EXE` 自己的事。

### 4.1 偵測：直接讀向量表，不走 `int 21h AH=35h`

```asm
DS = 0 ; SI = 0CCh              ; 向量 33h × 4
BX = [0000:00CC]                ; 位移
DS = [0000:00CE]                ; 段
CL = [DS:BX]                    ; ★ 讀向量指到的第一個位元組
IF 段 = 0 AND 位移 = 0 → 沒有滑鼠
IF CL = 0CFh          → 沒有滑鼠      ; ★ IRET
ELSE                  → 有滑鼠
```

> ### `[HARD]` 不能把所有向量都指到同一個 `IRET`
>
> 兩個判準都會命中，遊戲判定「沒有滑鼠」，**而且不報錯**——
> `rich2/docs/re/005` 在這裡卡了一整輪。
> `int 33h` 的 stub 開頭要放 `90 CF`（`nop; iret`），
> 或任何第一個位元組不是 `CFh` 的東西。

### 4.2 要實作的子功能

| `AX` | 做什麼 | 備註 |
|---:|---|---|
| 0 | 重置／偵測 | 初始化時呼叫一次 |
| 1 | 顯示游標 | **全檔沒有呼叫端**，可以不做（見 4.3）|
| 2 | 隱藏游標 | 初始化時無條件呼叫一次 |
| 3 | 讀位置與按鍵 | `CX` ＝ **虛擬座標**（像素 ×2）、`DX` ＝ 像素；`BX` bit0 左鍵、bit1 右鍵 |
| 7 | 設 X 範圍 | 遊戲設 0–639 |
| 8 | 設 Y 範圍 | 遊戲設 0–199 |

**X 除以 2 是遊戲的包裝層做的**（`3EFB6` 的 `shr ax,1`），不是我們要做的事——
`AX=3` 照標準回虛擬座標就好。

### 4.3 游標不必畫

`AX=1`（顯示游標）**全檔 0 個 far call 呼叫端**。畫面上那隻小手是遊戲
自己畫的，不是 DOS 驅動的游標。所以模擬器不必實作游標繪製。

（`rich2/docs/re/005` 把「呼叫過 `AX=2` 卻從沒呼叫 `AX=1`」記成線索，
以為是走進了另一條路徑——不是，那就是原版的行為。）

## 5. 計時器

> **原本這一節寫「時序等 M2」，那個估計是錯的——MVP-B 就需要計時器中斷。**
> 沒有它，`RUN_full.EXE` 停在防拷畫面的這個形狀上（執行期 `3014:167F`
> ＝ 線性 `406BF`）：
>
> ```
> cmp cx, cs:[1727h]
> jg  −5              ; 等計數器追上 CX
> ```
>
> `cs:1727h` 由程式自己的 ISR 遞增。中斷不送 ＝ 值永遠不變 ＝ 死迴圈，
> **而且畫面看起來是對的**——文字動畫停在第一個字，像是「還沒畫完」。

### 5.1 現行模型：指令數，不是時間

`machine.IRQ0Every`（預設 165,000 道指令）每隔固定指令數送一次 IRQ0。
18.2 Hz ＝ 55 ms，以 DOSBox 預設的 3,000 cycles/ms 換算約 165,000 道。

**用指令數當時鐘是刻意的**：對拍要決定性，同一組輸入永遠得到同一個畫面。
代價是動畫速度與真機不同，而且調色盤循環動畫的**相位**對不上原版
（MVP-B 實測差 2，見 `docs/spec/001`）。

三個實作細節，每一個的反面都不會報錯：

1. **`IF=0` 期間的 tick 要掛起來，不能丟。** 初始化有大量 `CLI`，
   當場丟掉的話那一段的 tick 全部消失。
2. **BIOS 的預設動作是向量 8 指向的一段 stub 程式碼**（推進
   `0040:006C`、轉呼 `int 1Ch`），tick 永遠走 `Interrupt(0x08)`。
   程式裝了自己的 `int 08h` 時存下的「舊向量」就是這段 stub，
   chain 回去 BIOS 行為就還在；不 chain 的話 BDA 計數與 1Ch 停下來，
   與真機一致。
   （舊版反過來做：「程式裝了 08h 就不做 BIOS 的事」。結果 FMDRV.COM
   掛走 08h 之後 OPEN.EXE 掛在 1Ch 的動畫計數永遠不動，開場死在
   GRPDRV 的重畫迴圈——源平合戰，`docs/spec/008` §4。）
3. **`0040:006C` 一定要推進。** 有些程式直接讀它算時間，不裝任何 ISR。
   跨日重置（`0040:0070`）不做——24 小時才到，對拍跑不到。

### 5.2 還沒做：週期精確

`0CED:41A8(n)` ＝ 等 `n / 70.187` 秒（`rich2/docs/re/154`），也就是 PIT 的分頻。
要讓動畫速度與調色盤相位都對到原版，得照抄 PIT 的分頻與 `int 08h`／`1Ch`
的實際頻率。**`~/cht/dosbox` 是現成的參考實作**，讀它比自己推便宜。
排在 M2。
