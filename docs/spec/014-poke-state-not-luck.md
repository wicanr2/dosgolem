# 014 — 對拍要固定狀態，不要靠亂數

狀態：READY
日期：2026-09-06

## 原則

需要某個局面才能對拍時，**直接把記憶體改成那個局面**，不要用
「換個亂數種子再跑一次」或「一直跑到它出現」。

理由是收據的可重現性：靠運氣得到的狀態，換一版執行器（哪怕改對了）
就可能不再出現，收據跟著作廢；而對不上的時候也分不清是 remake 錯了，
還是這一次抽到不一樣的數。直接寫進去的狀態則是輸入的一部分，
跟按鍵序列一樣可以完整記進收據裡。

## 介面

程式化用 `oracle.WriteU8`／`WriteU16`／`WriteBytes`（`oracle/write.go`）。

命令列用 `cmd/probe` 的 `-poke`：

```
-poke "<位址>@<步數>=<hex bytes>[;…]"
```

位址寫法與 `-peek` 相同（`lin:<hex>`、`ds:<hex>`、`<seg>:<off>`、IDA 位址），
步數是「跑到第幾道指令時寫進去」，用 `@` 分隔——位址本身就有冒號，
拿冒號當分隔的話 `0040:0049=07` 會被當成「IDA 位址 0040、步數 49」
而且不報錯，然後安靜地寫到別的地方去。寫入時會印一行，收據裡看得到。

例：

```
-poke "0040:0049@100000=07;lin:400@150000=AA BB"
```

## 邊界

改記憶體是**診斷與固定狀態**用的，不是遊戲規則的替代品。收據必須把
`-poke` 的完整內容記進 metadata；沒有記下來的注入等於沒有發生過。
