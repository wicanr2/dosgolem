## 1. 定位

`Opendat.gp` 有 **853 KB**，`Enddat.gp` 有 1,013 KB，`Kaodata.gp` 有 484 KB。
這些都放不進 640 KB 的常規記憶體，而 1994 年的 DOS 遊戲把它們放進
**EMS**（LIM/EMS 4.0，`int 67h`）——透過 64 KB 的 page frame 一次映
四個 16 KB 頁。

XMS（`011`）解決的是「字型倉庫」，EMS 解決的是「遊戲資料倉庫」；
兩者的介面完全不同，DOS 程式常常兩個都用。

## 3. 實作範圍

### 3.1 偵測：向量指向一個帶簽章的 driver header

DOS 程式偵測 EMS 的標準做法是讀 `int 67h` 向量指的**段**，檢查該段
`+0Ah` 起的 8 個位元組是不是 `EMMXXXX0`（那是 EMM 驅動的裝置名，
device driver header 的名稱欄位）。

所以 `int 67h` 的向量指向 `EMSSeg:0000`，那一段放：

| 位移 | 內容 |
|---|---|
| `00h` | `CD F6h`／`CFh`——陷阱向量 ＋ IRET（與 `004` §2.1 同型） |
| `0Ah` | `"EMMXXXX0"` |

### 3.2 服務（經 `int F6h` 分派）

| AH | 功能 | 實作 |
|---:|---|---|
| `40h` | Get Status | `AH=0` |
| `41h` | Get Page Frame Segment | `BX` ＝ page frame 段 |
| `42h` | Get Page Counts | `BX` ＝ 未配置頁數、`DX` ＝ 總頁數 |
| `43h` | Allocate Pages | `BX` ＝ 頁數 → `DX` ＝ handle |
| `44h` | Map Handle Page | `AL` ＝ 實體頁 0–3、`BX` ＝ 邏輯頁、`DX` ＝ handle |
| `45h` | Release Handle | `DX` ＝ handle |
| `46h` | Get Version | `AL` ＝ `40h`（4.0） |
| `47h`／`48h` | Save／Restore Page Map | 存／還原四個實體頁的對應 |
| `4Bh` | Get Handle Count | `BX` ＝ 目前 handle 數 |
| `4Ch` | Get Pages for Handle | `BX` ＝ 該 handle 的頁數 |
| `58h` | Get Mappable Physical Address Array | `AL=00` 寫陣列到 `ES:DI`（每項 ＝ 段 ＋ 實體頁號）、`AL=01` 只回項數；`CX` ＝ 4 |

回傳慣例是 **`AH` ＝ 0 成功、非 0 是錯誤碼**（`80h` 內部錯、`83h` handle
無效、`87h` 頁數不足、`8Ah` 邏輯頁超範圍、`84h` 沒有這個功能）。
`AL` 不是狀態欄位——**不要照 DOS 的 CF 慣例回**。

### 3.3 頁面內容放哪裡

page frame 是 **`D000h` 段**的 64 KB（`D0000`–`DFFFF`）：那段位址在
1 MB 空間裡沒有別的用途，程式對它的讀寫就是普通記憶體存取，不必攔。

邏輯頁的內容放 Go 端（`map[handle][][]byte`，每頁 16 KB）。`AH=44h`
映射時：**先把目前佔著那個實體頁的邏輯頁寫回**，再把新的複製進來。
不做寫回的話，程式「換頁再換回來」會拿到舊資料，而且完全不報錯。

`AH=45h` 釋放時同樣要把還映著的頁寫回，再丟掉 handle。

## 4. 這份規格**不做**什麼

- EMS 4.0 的其餘進階功能：`AH=4Eh`／`4Fh`（page map 的其他形式）、
  `AH=50h`（map multiple）、`AH=51h`（realloc）、`AH=53h`–`57h`
  （具名 handle、搬移／交換）、`AH=5Ah`（raw pages）。
  遇到就記一筆並回 `AH=84h`。
- **不做 page frame 以外的映射**（EMS 4.0 允許把頁映到常規記憶體）。
- 不做 handle 0（系統 handle）的特殊語意。
