# 189 — A20 閘門與 HMA 的定址

狀態：**READY**（量測證據見 §2）
日期：2026-09-10
前置：[`011-xms.md`](011-xms.md)（XMS 的 HMA 與 A20 服務）、
[`003-machine-and-loader.md`](003-machine-and-loader.md) §2（記憶體佈局）

---

## 1. 定位

`cpu.Addr(seg, off)` 回傳前做 `& 0xFFFFF`，把每一個 `段:偏移` 位址遮成
8086 的 20 條位址線。

**那個環繞是匯流排的行為，不是 CPU 的。** 8086 只有 20 條位址線，所以
`FFFF:0010` 自然折回 `0000:0000`；286 之後多出來的第 21 條線由主機板上的
A20 gate 控制，打開之後同一組 `段:偏移` 指向的是線性 `0x100000`——1 MB
之上那 64 KB−16，也就是 HMA。把遮罩寫死在 CPU 的位址計算裡，等於把閘門
焊死在關的位置：`SetA20(true)` 之後行為一模一樣。

後果不只是「偵測不到 A20」。`internal/dos/xms.go` 已經完整實作了 HMA 這
條路——`AH=00h` 回報 `DX=1`（HMA 存在）、`AH=01h` 讓程式配置它、
`AH=03h`–`06h` 開關 A20——而且那裡的註解寫著：

> **拿到 HMA 就要能定址**：A20 沒開的話 1 MB 之上環繞回 0，程式寫進去的
> 東西會蓋掉中斷向量表。

實際情況是那個災難**無條件發生**：程式問到 HMA 存在、配置它、開了 A20，
接著往 `FFFF:xxxx` 寫的每一個位元組都落在 `0000:xxxx`。

## 2. 量測

2026-09-10 在 `f7fd296` 的樹上量的：

| 動作 | 結果 |
|---|---|
| `SetA20(true)` 後線性讀 `0x100010` | `AA`（`Machine.Read8` 的 HMA 分支有效） |
| `cpu.Addr(0xFFFF, 0x0020)` | `0x10`（真機 A20 開時應為 `0x100010`） |
| 執行 `mov es:[bx], 0xCC`，`ES:BX ＝ FFFF:0020` | HMA 沒變（還是 `AA`），`0x10` 變成 `CC` |
| 那一刻的 `0x10..0x13` | `CC 00 80 00` |

最後一列是 `int 04h` 的向量。**寫進 HMA 的位元組落在中斷向量表上**，而且
不會有任何錯誤。

`Machine.Read8`／`Write8` 早就有 HMA 分支，但它的條件是位址 `≥ MemSize`，
而經過 `cpu.Addr` 的位址永遠 `< MemSize`——那條分支只有拿線性位址直接
呼叫（測試、工具）時才進得去。

## 3. 真機的行為

| A20 | `FFFF:0010` 落在 | 程式怎麼用這件事 |
|---|---|---|
| 關 | 線性 `0x000000` | 8086 相容。程式寫 `0000:0000` 再讀 `FFFF:0010`，值一樣就知道沒有 A20 |
| 開 | 線性 `0x100000` | HMA 的第一個位元組。`DOS=HIGH`、XMS 的 `Request HMA` 都是要這一段 |

`段:偏移` 算出來的最大值是 `0xFFFF × 16 + 0xFFFF ＝ 0x10FFEF`，正好是
1 MB 加上 64 KB−17：HMA 的大小（`HMASize ＝ 0x10000 - 16`）就是這麼來的。

## 4. 設計

**位址計算回 21 位，環繞交給匯流排。**

- 新增 `cpu.Linear(seg, off) uint32`，回 `seg<<4 + off`，**不遮**。
- CPU 內部真正做記憶體存取的六個地方改用它：`read8`／`write8`
  （`cpu.go`）、operand 的讀寫（`modrm.go`）、`moffs` 與 `XLAT`
  （`ops.go`）。
- `cpu.Addr` 維持遮 20 位不動。它的另外八十幾個呼叫端算的是「線性位址」
  給工具與比對用，處理的都是 1 MB 以下的一般情況；改它的語意要動的面太
  大，而且那些地方沒有 A20 的概念。
- `Machine.Read8`／`Write8` 不必改：`hmaAddr` 已經在最前面，A20 關著時
  它回 false，接著的 `a &= 0xFFFFF` 就是 8086 的環繞。

**取指令的快路徑要在 A20 開著時關掉。** `CPU.Code` 直接索引 `Mem[]`
（1 MB），而 HMA 不在裡面。判準表在 `Machine.syncCodeFastPath`。

**執行護欄要放行 HMA。** `oracle`、`cmd/probe`、`cmd/scenetime` 用
「`CS:IP ≥ A0000` ＝ 飛掉了」當護欄。A20 開著時 HMA 的位址是
`0x100000` 以上，會被判成飛掉。條件改成「`A0000 ≤ 位址 < 1 MB`」，
1 MB 以上放行。

### 為什麼不讓 CPU 認識 A20

CPU 那一層的規則是「不認識 DOS、不認識畫面、不認識檔案」
（[`006-layering.md`](006-layering.md)）。A20 gate 是 PC 主機板上的
東西，不是 8086 的一部分——把它做成 CPU 的欄位，等於讓下層知道上層的
平台細節。位址算出來交給匯流排，由匯流排決定看不看得見第 21 條線，
分層與真機的形狀一致。

## 5. 影響面

`段:偏移` 位址 `≥ 1 MB` 只在 `seg ≥ 0xFFF1` 時出現得了。程式一般不會
把段暫存器設在那裡，除非它就是要碰 HMA。所以 A20 關著時行為完全不變
（`Read8`／`Write8` 的遮罩接手），A20 開著時只有落在 `0x100000` 以上的
那些存取改變去向——而那正是要修的。

## 6. 驗收

1. A20 開著：`段:偏移` 的讀、寫、取指令都到得了 HMA；`FFFF:0010` 與
   線性 `0x100000` 是同一個位元組。
2. A20 關著：`FFFF:0010` 與 `0000:0000` 是同一個位元組（8086 環繞）。
3. XMS 那條路：`Request HMA` → 用 `段:偏移` 寫 → 讀回拿得到寫進去的值，
   而中斷向量表沒有被動到。
4. 既有測試全過，CPU 語料全過（`docs/spec/002` §5）。
