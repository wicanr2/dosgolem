# 243 CGA 圖形模式的 INT 10h 視窗捲動與清除、調色盤選擇

狀態：DRAFT（審查中）。本規格補 `internal/dos/bios.go` 的 `int 10h` 在 CGA 圖形模式（04h、05h）缺的兩組服務：`AH=06h`／`07h`（捲動視窗、清除視窗）與 `AH=0Bh`（背景色與調色盤選擇），並公開 CGA 四色的 RGB 表。其他視訊模式的行為不變。

## 1. 為什麼要做

現況：`bios.go` 對 `AH=06h` 收下就好（`case 0x02, 0x03, 0x05, 0x06, 0x09, 0x0A:`，沒有動作），`AH=07h`、`AH=0Bh` 落入 `default` 只記一筆 `note`。使用 BIOS 清除視窗的 CGA 程式，在這裡視窗內的舊像素不會被清掉，畫面與真機不同；執行期疊字與對拍都以畫面為準，這個差異會直接進入驗收。

證據（私有研究，本規格不含原版素材）：一個 CGA 模式 04h 的程式在 60M 步內呼叫 13 次 `AH=06h AL=0 BH=0`，以視窗矩形內非零像素數量測，呼叫前後完全相同（多組矩形：前後都是 7256、14602、6079 個非零像素），`Unimplemented()` 為空。程式端靜態有 `AH=0Bh` 的呼叫點（`BH=1`，`BL=0` 與 `1`），本機動態路線未走到。

## 2. 範圍

| 項目 | 內容 |
|---|---|
| 納入 | 模式 04h 與 05h（320×200，每像素 2 位元，40×25 個 8×8 字元格）：`AH=06h`、`AH=07h`、`AH=0Bh`；CGA 色彩選擇暫存器狀態；`oracle.CGAPalette()` |
| 不納入 | 文字模式的捲動（保持現狀）；模式 06h（640×200 單色）；模式 05h 的色彩爆發關閉造成的色相差異（05h 暫用與 04h 相同的色表，標未驗證）；寫 `3D9` 埠（本規格不攔截 I/O，只由 BIOS 服務寫入同一個狀態） |
| 不變量 | 其他模式與其他 `AH` 的行為不變；本規格只在模式為 04h 或 05h 時動作 |

## 3. 行為

視訊記憶體版面（`oracle.CGA4` 已採用）：第 `y` 條掃描線在 `B800:((y/2) × 80 + (y%2) × 2000h)`，每位元組 4 個像素（高位元在左），一個字元格橫向 2 位元組、縱向 8 條掃描線。

### 3.1 `AH=06h`（上捲）、`AH=07h`（下捲）

輸入：`AL` 行數、`BH` 填色位元組、`CH`／`CL` 視窗左上的列、欄、`DH`／`DL` 視窗右下的列、欄（字元格座標）。

1. 視窗矩形夾到螢幕：列 0 至 24、欄 0 至 39。夾完後上緣大於下緣或左緣大於右緣就不動作。
2. `AL = 0`，或 `AL` 不小於視窗高度（列數）：整個視窗以 `BH` 填滿（每個位元組寫 `BH`，與 IBM PC BIOS 在圖形模式的填色一致）。
3. 其他：上捲時視窗內每個字元格列往上移 `AL` 列（像素資料逐條掃描線複製，只動視窗橫向範圍的位元組），底部 `AL` 列以 `BH` 填滿；下捲反向，頂部 `AL` 列以 `BH` 填滿。複製方向要避免來源與目的重疊時被覆蓋（上捲由上往下複製，下捲由下往上複製）。
4. 不改暫存器，不改游標。

### 3.2 `AH=0Bh`

CGA 色彩選擇暫存器（`ColorSelect`，8 位元，位元定義同 `3D9` 埠）：

| 位元 | 意義 |
|---|---|
| 0 至 3 | 背景（色號 0）的顏色（16 色之一） |
| 4 | 前景（色號 1 至 3）使用高強度 |
| 5 | 調色盤選擇：0 為綠、紅、棕；1 為青、洋紅、白 |

`BH = 0`：`ColorSelect = (ColorSelect & 0xE0) | (BL & 0x1F)`（`BL` 的 bit 4 是強度）。`BH = 1`：`ColorSelect = (ColorSelect & 0xDF) | ((BL & 1) << 5)`。其他 `BH` 值：維持原行為（記一筆 `note`）。

模式 04h、05h 由 `AH=00h` 設定時，`ColorSelect` 重設為 `30h`（調色盤 1、高強度、背景黑），與 IBM PC BIOS 設模式後的值一致。

### 3.3 RGB 表

16 色 CGA RGB（`oracle.CGAPalette()` 內部使用）：0 黑 `(0,0,0)`、1 藍 `(0,0,170)`、2 綠 `(0,170,0)`、3 青 `(0,170,170)`、4 紅 `(170,0,0)`、5 洋紅 `(170,0,170)`、6 棕 `(170,85,0)`、7 淺灰 `(170,170,170)`、8 深灰 `(85,85,85)`、9 淺藍 `(85,85,255)`、10 淺綠 `(85,255,85)`、11 淺青 `(85,255,255)`、12 淺紅 `(255,85,85)`、13 淺洋紅 `(255,85,255)`、14 黃 `(255,255,85)`、15 白 `(255,255,255)`。

`CGAPalette()` 回傳 `[4][3]uint8`：色號 0 是背景色（`ColorSelect & 0x0F`）；色號 1、2、3 依 `ColorSelect` 的 bit 5 與 bit 4 取：調色盤 0 為綠、紅、棕（強度時為淺綠、淺紅、黃），調色盤 1 為青、洋紅、淺灰（強度時為淺青、淺洋紅、白）。模式不是 04h 或 05h 時回傳預設值（調色盤 1 高強度、背景黑）。

## 4. 實作位置

- `internal/machine/cga.go`：常數（版面）、`CGAScroll(top, left, bottom, right, lines int, down bool, fill byte)`、`ColorSelect` 狀態與 `SetColorSelect`、色表。
- `internal/dos/bios.go`：`case 0x06, 0x07` 與 `case 0x0B`；模式 04h、05h 之外維持原樣（`0x06` 收下，`0x07`、`0x0B` 記 `note`）。`AH=00h` 設 04h、05h 時重設 `ColorSelect`。
- `oracle/oracle.go`：`CGAPalette()`。

## 5. 驗收

1. 單元測試（`internal/machine`、`internal/dos`，期望值寫字面值）：
   - 清除：視窗內全部位元組成為 `BH`，視窗外一個位元組都不變（含視窗左右緣相鄰位元組、上下緣相鄰掃描線、交錯 bank）。
   - 上捲 1 列與 3 列、下捲 1 列：內容位移的位元組位置與底部（頂部）填色；視窗外不變。
   - `AL` 大於或等於視窗高度等同清除。
   - 夾邊：右下角超出 `(DL = 79, DH = 24)` 時等同夾到 `(39, 24)`；上緣大於下緣不動作。
   - 非 CGA 模式（mode 13h）：`AH=06h` 不動視訊記憶體，`AH=07h`、`AH=0Bh` 仍記 `note`。
   - `AH=0Bh`：`BH=0` 設背景並保留高 3 位元，`BH=1` 設調色盤並保留其他位元；`AH=00h` 設 04h 後 `ColorSelect = 30h`。
   - `CGAPalette()`：預設值、調色盤 0／1、有無強度、背景色變更，共 8 組字面值。
2. 負對照：把 `AH=06h` 恢復成「收下就好」，清除與捲動的測試應失敗；把 `AH=0Bh` 的 `BH=1` 位元寫錯位置（寫 bit 4），調色盤測試應失敗。
3. 同狀態收據（有原版時）：一個 CGA 程式的清除視窗呼叫之後，視窗矩形內位元組全為 `BH`（動態取樣，與修改前的非零像素數對照）；缺原版時 SKIP，不算驗收。
4. 其他分支與既有收據：`go test ./...` 既有測試不變。

## 6. 未決

1. `BH` 在圖形模式捲動時是否為「原始位元組」：以 IBM PC BIOS 的圖形捲動（填 `BH` 位元組）為準，沒有實機證據；本機程式的所有呼叫 `BH = 0`，兩種解讀無差別。其他 `BH` 值標未驗證。
2. 模式 05h 的色表與模式 06h 的行為。
3. `3D9` 埠寫入是否要同步 `ColorSelect`：需要時另開規格（目前沒有已知的 I/O 寫入者）。
