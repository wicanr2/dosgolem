# 197 — `PUSH SP`：80186 推新值，分界在 80286

狀態：**READY**（Intel 一手文件＋實機語料，見 §2）
日期：2026-09-11
前置：[`002-cpu-8086`](002-cpu-8086.md) §4 第 1 點

---

## 1. 規則

`PUSH SP`（`54`，以及 `FF /6` 以 SP 為運算元）推上堆疊的值：

| 機型 | 推的值 |
|---|---|
| `Model8086` | 已經減 2 之後的 SP（新值） |
| `Model80186` | **已經減 2 之後的 SP（新值）**——與 8086 相同 |
| `Model80386` | 執行前的 SP（舊值）——286 起的行為 |

這一條修正 `002-cpu-8086` §4 第 1 點原本「186 以上推舊值」的分界。
386 的行為不變，既有依賴它的案例（源平合戰的 `sub sp,n`＋`push sp` 暫時物件）不受影響，
那支程式跑在 `machine.New()` 的 `Model80386`。

## 2. 證據

1. **Intel《iAPX 86,88 and iAPX 186,188 User's Manual — Programmer's Reference》（1983，210911-001）**：
   同一份手冊規範 8086／8088 與 80186／80188。PUSH 的運算是
   "(SP) ← (SP) - 2  ((SP) + 1:(SP)) ← (SRC)"——先減 2 再存，來源是 SP 時存的就是新值。
   同一份手冊在 PUSHA 特別註明 "The SP value pushed is the SP value before the first register (AX) is pushed"，
   一般 PUSH 沒有這個特例。
2. **Intel《80C186EC/80C188EC Microprocessor User's Manual》（272047-003）**：指令表的 micro-op 同樣是
   PUSH 先 `(SP) ← (SP) – 2` 再存；PUSHA 才先存 `temp ← (SP)`。
3. **Intel SDM PUSH 條目**："For the Intel® 8086 processor, the PUSH SP instruction pushes the new value …"；
   "For IA-32 processors from the Intel 286 on, the PUSH ESP instruction pushes the value … as it existed before"。
   分界明寫是 286。
4. **Intel AP-485（241618-005）** 的 CPU 識別範例：FLAGS 第 12–15 位元恆為 1 的一類（8086／8088 家族）
   再以 `push sp`／`pop dx`／`cmp dx,sp` 二次確認——這一類預期推新值。
5. **實機語料（SingleStepTests）**：NEC V20 的 `v1_native/54.json.gz` 10,000 筆、8086 的 `v1/54.json.gz`
   2,000 筆，推上堆疊的值**全部等於執行後的 SP**（2026-09-11 下載統計）；80286 語料的 README 寫明
   "The value pushed to the stack is the value of SP before the push"。
   SingleStepTests/80186 目前沒有資料檔，**80186 本身沒有實機語料**，本條靠 1–4 的 Intel 文件支撐。

## 3. 觸發案例

Borland C++ 2.0 的 `BCC.EXE` 啟動時用 `push sp`／`pop ax`／`cmp sp,ax` 分出「8086／80186」與「286 以上」。
舊規則下 `-cpu 186` 被判成 286 以上，接著執行 `mov eax,ebx` 探 386，於 `0x66` 報錯；
照本規格，186 會被正確判成 8086 類，走 8086 路線。

## 4. 驗收

1. `internal/cpu/pushsp_test.go` 的機型表：8086 與 186 推 `0FFE`（新值），386 推 `1000`（舊值），
   `54` 與 `FF F4` 兩條路徑都驗。
2. `tools/go.sh test ./internal/cpu` 全綠（8086 語料路徑不受影響）。
3. `BCC -ms HELLO.C` 在 `cmd/run -cpu 186` 下跑完、回傳碼 0。
