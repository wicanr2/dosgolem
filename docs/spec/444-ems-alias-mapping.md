# 444 — EMS 同一邏輯頁映進兩個實體頁

前置：[`008-ems-paging`](008-ems-paging.md) §3（複製式分頁）

## 1. 規則

LIM EMS 的頁框是同一塊擴充記憶體的窗口。同一個邏輯頁映進兩個實體頁時，
兩個窗口看到同一份內容，經任一窗口寫入都是寫那一頁。

dosgolem 的頁內容存在 Go 記憶體，映射時複製進頁框（`008-ems-paging` §3）。
這個模型在同頁別名時要補兩件事：

| 時點 | 做法 |
|---|---|
| 把邏輯頁 L 映進實體頁 p（`AH=44h`、`AH=50h`） | 先把頁框中其他映著 L 的實體頁寫回，再載入 p |
| 實體頁寫回邏輯頁（換映射、解除映射、釋放、全部寫回） | 只寫回與邏輯頁現存內容不同的 byte |

只寫差異的理由：別名窗口 q 載入後沒被改過的 byte 仍等於舊值。整頁寫回會用
q 的舊值蓋掉經 p 寫入的新值。沒有別名時，未改過的 byte 本來就與現存內容相同，
兩種寫回結果一致。

### 已知限制

兩次映射操作之間，經 p 寫入的內容不會立刻出現在 q。要等下一次映射或寫回。
兩個窗口在同一段期間寫同一個 byte 的不同值時，後寫回者勝。
觸發案例沒有這兩種情形；遇到時要改成頁框直接對映 Go 記憶體。

## 2. 觸發案例

智冠中文版《魔法門 V》`XEEN.EXE`（SHA-256 前綴 `7908828d896c`）播片頭時以
四頁滑動視窗讀 `INTRO.CC`：每組四頁的最後一頁，下一組再映到實體頁 0。
例如第 102225855 道指令 `L11→P0` 時，L11 仍映在 P3。

修改前，P0 載入的是 L11 尚未寫回的舊內容。`1113:2B72` 的解壓迴圈讀到錯誤資料，
輸出超出 64000 bytes 的目的緩衝區 `8E13:0000`，在第 108969975 道指令寫到
`9DF50`，蓋掉緊接其後的 `INTRO.CC` 索引（`9DB5:0002`）。之後 `1113:AB7A`
找不到 `jvc.raw`（id `CA5B`），程式在第 173497385 道指令以離開碼 2 結束。
DOSBox-X 用同一組檔案時，片頭繼續演出到標題畫面。

## 3. 驗收

1. 單元測試：L 映進 P3、經 P3 寫入；L 再映進 P0，P0 讀得到該值；
   之後 P3 換映別頁，經 P0 寫入的值不被 P3 的舊內容蓋掉。反面對照：修改前失敗。
2. `go test ./internal/dos` 全綠。
3. 整合：觸發案例在第 108969975 道指令不再寫到 `9DB50`–`9E48A`，片頭越過 `jvc.raw`。
