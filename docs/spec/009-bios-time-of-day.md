# BIOS 時刻讀取契約

狀態：READY

## 範圍

只補 `INT 1Ah/AH=00h`（讀取 BIOS 時刻）。機器既有的確定性 IRQ0 會以
`DefaultIRQ0Every=165000` 指令推進一次 `0040:006C` 的 32 位元日內 tick，並在
跨日後設定 `0040:0070`。本服務只回讀這份既有狀態，不另建牆鐘。

## 契約

- `CX:DX` 回傳 `0040:006C` 的高／低 16 位元。
- `AL` 回傳 `0040:0070` 的午夜 rollover 值，讀取後清零。
- 其他 `INT 1Ah` 子功能維持未實作記錄；不得假裝成功。
- 結果以已執行指令數決定，因此相同輸入可重播。這是 BIOS 規格近似，不宣稱
  與任一實機逐週期一致。

## 證據與用途

- IBM PC 相容 BIOS 的 `INT 1Ah/AH=00h` 公開介面契約。
- dosgolem `internal/machine/machine.go` 與 `bda.go` 已實作 IRQ0、日內 tick及 rollover。
- EOB1 正常載入存檔後會呼叫本服務三次；原先服務未實作，會讓 `CX:DX` 保留
  呼叫端暫存值。補齊後未實作報告已不再出現 `INT 1Ah`。
- 補齊本服務後，即使再執行五千萬指令，該存檔路徑的第一隻怪物仍未前移；因此
  BIOS 時刻缺口已排除為首戰阻塞的充分原因，不可把本修正冒稱為怪物 AI 修復。

## 驗證

- 單元測試釘住 `CX:DX`、`AL` 與 rollover 讀後清零。
- EOB1 由有效原版存檔正常開門、步行並等待；本服務不再列入未實作報告。怪物
  是否移動須由後續窄範圍證據另行判定。
