# 197 — 滑鼠事件常式要進狀態檔

狀態：READY（已實作＋單元測試＋原版對拍驗證）
日期：2026-09-10
適用：`internal/dos/state.go`

## 1. 為什麼需要它

`dosState` 存滑鼠時只留座標與按鍵統計：

```go
// 滑鼠的座標與按鍵要留，觀測紀錄不留。
s.Mouse = Mouse{X: …, Y: …, Buttons: …, Press: …, Release: …, XScale: …}
```

`Handler`（`AX=000Ch`／`0014h` 登記的事件常式）與座標範圍（`AX=07h`／`08h` 設的）
**都不是觀測紀錄，是狀態**，而它們掉在原本那條分界的另一邊。

症狀是狀態檔展開之後**點擊全部沒反應**，而且沒有任何錯誤：

| | 從頭跑 | 從狀態檔展開 |
|---|---|---|
| 展開時的畫面 | — | **與從頭跑逐像素相同** |
| 點方向鍵的「前」 | 畫面前進一格 | **一個像素都沒變** |
| probe 的「事件常式」那一行 | 有 | **沒有** |

⚠ **畫面對得起來會讓人以為狀態是完整的。** 記憶體、CPU、開著的檔、配出去的
區塊全都還原了，畫面逐像素相同——唯一沒還原的東西剛好不影響畫面，
只影響**之後的輸入**。`cmd/clickgrid` 掃 84 格回報「0 格有反應」，
那個結果與「這一區真的沒有熱區」一模一樣。

## 2. 要存什麼

| 欄位 | 為什麼是狀態 |
|---|---|
| `Handler.Seg`／`Off`／`Mask`／`Set` | 事件往哪裡送、送哪幾種 |
| `MinX`／`MaxX`／`MinY`／`MaxY` | 夾制是遊戲行為的一部分（`Mouse` 的既有註解）；範圍掉了之後注入的座標不再被夾，「點在畫面外」這種邊界測試會得到相反的結論 |

不存的仍然不存：`Polls`、`Sets`、`Calls`、`Events`、`PressQ`、`PressReads`、
`MickeyX`／`MickeyY`。前六個是觀測紀錄；mickey 是「自從程式上次問以來」的累計，
跨行程接續時歸零才是對的——存下來的話展開後第一次 `AX=0Bh` 會拿到
存檔之前累積的位移。

## 3. 相容性

`dosStateVersion` 不動。新欄位在舊檔裡是零值，而零值就是「沒登記過事件常式、
沒設過範圍」——那正是舊檔存下來的實際情形。**舊狀態檔照樣讀得起來，
行為與現在一樣**（點擊沒反應），不是壞掉。

## 4. 驗收

1. 單元測試：登記 handler ＋ 設範圍 → 存 → 讀 → 四個欄位與範圍都回得來。
2. 單元測試：舊檔（沒有這些欄位）讀起來是零值，不報錯。
3. 原版對拍：《Dungeon Master》從狀態檔展開之後點方向鍵的「前」，
   畫面前進一格，與從頭跑點同一個位置的結果逐像素相同。
