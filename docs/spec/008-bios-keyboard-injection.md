## 1. 為什麼要做

第二個案例（SSI《Pool of Radiance》，DOS）**整條輸入路徑走 `int 16h`**，
不是第一個案例的 `int 21h AH=3Fh`。目前 `int16` 是個永遠回「沒有按鍵」的樁，
所以這支程式跑到標題畫面就停在原地——**畫面是對的、程式沒當、什麼都沒壞**，
它只是永遠等不到那一個鍵。

## 2. 量到什麼（`cmd/shots`，2 億道指令，沒送任何鍵）

| 觀測 | 值 |
|---|---|
| `int 16h AH=01`（查有沒有按鍵）| **1,663,979 次** |
| `int 16h AH=00`（阻塞讀鍵）| 0 次 |
| `int 21h AH=3Fh`（讀 handle 0）| 1,633 次，全部是**讀檔**，不是鍵盤 |
| `int 21h AH=2Ch`（取時刻）| 1,663,936 次 |
| 開過的檔 | 103 個，最後三個是 `items`、`title.dax` |
| 最後一個穩定畫面 | 非零像素 35,067／64,000（SSI／AD&D 標題） |
| 停下來的位置 | `CS:IP = 06CB:0281` |

`AH=01` 與 `AH=2Ch` 的次數幾乎相同（差 43）：那是一個
「查時間 → 查鍵盤 → 再來一次」的閒置迴圈，正是「畫面畫完了在等玩家」的形狀。

### 2.1 這推翻了 `internal/dos/bios.go` 的一句註解

那句寫「**遊戲的鍵盤輸入不走這條**——它走 `int 21h AH=3Fh` 讀 handle 0」，
出處是 `rich2/docs/re/005`。**那句話對第一個案例成立，對這一支不成立**：
`rich2` 是編譯後的 MS BASIC（`INKEY$` 走 `AH=3Fh`），Pool 是 Turbo Pascal，
它的 `KeyPressed`／`ReadKey` 就是 `int 16h AH=01`／`AH=00`。

**一個程式的觀測不是平台的通則**——這是同一個坑的第二次
（第一次是 `007` §2.3 的「VRAM 讀取側不必做」）。註解要標明是哪一支程式的觀測。

## 3. 契約

1. `DOS` 多一個 `Keys []uint16` 佇列。每一項是 BIOS 的按鍵字組：
   高位元組是掃描碼、低位元組是 ASCII 碼（`AH:AL`，與 `int 16h AH=00` 的
   `AX` 回傳格式相同）。
2. `int 16h AH=00`／`AH=10h`（阻塞讀鍵）：
   - 佇列非空 → 取出隊首，放進 `AX`。
   - 佇列空 → **回 `AX = 0`**，維持現行行為。
     不阻塞、不當錯誤：這一層沒有「等」的概念，呼叫端會自己再問一次。
3. `int 16h AH=01`／`AH=11h`（查有沒有按鍵）：
   - 佇列非空 → **清 ZF**，並把隊首放進 `AX`（**不取出**）。
   - 佇列空 → **設 ZF**，維持現行行為。
4. `AH=02h`／`AH=12h`（旗標狀態）不變，仍回 0。
5. 每一次 `AH=00h` 實際取走一個鍵時計數（`KeysConsumed`）。
   **「鍵送進去了」與「程式讀走了」是兩件事**，而在畫面上分不出來：
   兩者都是「畫面沒變」。
6. Oracle 側：`SendKey(scan, ascii uint8)` 推一個鍵，
   `Type(s string)` 之外另加 `TypeKeys(s string)` 把可列印字元轉成鍵盤字組，
   `SendKeys(names ...string)` 收 `"Return"`、`"Space"`、`"Esc"` 這種名字。
   `KeysPending()` 與 `KeysConsumed()` 回報佇列狀態。

## 4. 掃描碼表（最小集合）

只放本案例用得到的。**沒列到的不要猜**——猜錯的症狀是「按了沒反應」，
與「沒送到」一模一樣。

| 名稱 | 掃描碼 | ASCII |
|---|---|---|
| `Return` | `1C` | `0D` |
| `Space` | `39` | `20` |
| `Esc` | `01` | `1B` |
| `Backspace` | `0E` | `08` |
| `Up`／`Down`／`Left`／`Right` | `48`／`50`／`4B`／`4D` | `00` |
| `A`..`Z` | 見 `internal/dos/scancode.go` 的表 | 大寫 ASCII |
| `0`..`9` | `02`..`0B`（`1` 是 `02`，`0` 是 `0B`）| ASCII |

字母的掃描碼照 IBM PC 的 set 1（`QWERTY` 列從 `10` 開始）。

## 5. 不做什麼

- **不做鍵盤中斷（IRQ1／`int 09h`）與 `0040:001A` 的 BIOS 緩衝區。**
  這一支程式只透過 `int 16h` 問；直接讀 BDA 緩衝區的程式會看到空的，
  那時再補，不要現在假裝有。
- **不做按鍵的按下／放開時序。** 佇列裡一項就是「一次完整的按鍵」。
- **不做 shift／ctrl／alt 的旗標。** `AH=02h` 仍回 0。
- **不阻塞。** `AH=00h` 在佇列空時回 0，不是等——這一層沒有排程器。
