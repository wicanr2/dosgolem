# 184 — MVP 範圍檢討：要不要為 DOS/4GW 與其他應用擴充

狀態：**DRAFT**（結論待第一批實作與收據回填）
日期：2026-09-07
對照基準：DOSBox-X commit `5fcf624`（2026-08-13）、公開規格（RBIL、LIM EMS 4.0、
XMS 3.0、DPMI 1.0）。逐介面的對照表在 `docs/knowledge-base/`。

## 問題

`001-scope-and-mvp` 定的 MVP 是「把一支 16 位元實模式 DOS 程式跑到可以對拍」。
十條分支合併之後，實際跑過的程式有九支，其中一支（FD2）是 32 位元 DOS/4GW。
問題是：**現在這個範圍撐不撐得住下一支程式**，還是每接一支都要再長一次核心。

## 進度（2026-09-07）

實模式的補洞（批次 1、1b、1c）、DPMI 通用子集（2a）與檔案語意合併（3）
已完成，見下面的表。批次 2b 因為缺原版素材而**刻意暫停**，
理由與恢復條件寫在同一節裡。

### 批次 3 實際做到哪裡

合併的是**語意**，不是整個實作，這一點要講清楚：

- `internal/dosfile` 是唯一一份 DOS 檔案語意：錯誤碼、`AH=3Fh` 的
  「EOF 不是錯誤／讀不滿不是錯誤」、`AH=42h` 的「`CX:DX` 有號、origin 只有
  0／1／2、失敗要退回原位」、handle 從 5 開始配且不重用。
- 32 位元那條（`le_startup.go`）的五支平行實作改成「暫存器搬運 ＋ 呼叫
  共用語意」，自己那份 handle 表刪掉。
- 16 位元那條（`internal/dos/files.go`）**沒有搬**。它的 handle 帶著 PSP、
  寫入權、參考計數、暫存層與一整組觀測清單（`FileOps`／`Reads`／`trace`），
  那些是**政策**不是語意；硬共用只會讓兩邊都變複雜。兩條路共用的是
  上面列的那幾條規則——而它們正是分岔了不會有人發現的那幾條。

順帶把保護模式那一側補成「一支普通的 DOS/4GW 程式跑得起來」的形狀：
`AH=02h`／`09h`／`19h`／`3Eh`／`40h`／`4Ch`。這幾支與 FD2 無關，
換一支程式照用；FD2 專屬的啟動握手（`calls` 計數器 ＋ `PHAR`）原封不動，
`TestPMGeneralServicesDoNotDisturbStartup` 釘住「新服務不會把握手攔走」。

## 結論

分兩半，答案不一樣。

**實模式那一半：不必擴充範圍，只要補洞。** 46 個 `int 21h` 子功能已經涵蓋
C runtime 的主幹；缺的 68 個裡有 9 個會擋住一般程式（`4Fh` Find Next、
`45h`／`46h` dup、`57h` 檔案時間、`59h` 延伸錯誤、`0Ah` 緩衝輸入、
`39h`–`3Bh` 目錄、`56h` 更名、`68h` commit、`5Bh` 建新檔），其餘多半是 FCB 時代
的東西。這是**補洞**，不是改架構——一次一支，各自帶測試。

**保護模式那一半：要擴充，而且是架構問題。** 目前 LE／386／DPMI 這一層是
綁在 FD2 一支上的：啟動握手是 `calls` 計數器加 `PHAR` 判斷、selector 寫死四個值、
DOS 服務在 `internal/machine/le_startup.go` 平行實作了第二份、`int 31h` 只有
一支功能。**換第二支 DOS/4GW 程式，這三樣都要重來。**

不建議走 DOSBox-X 那條路（跑真的 extender）：那要一顆會分頁、會丟例外、
能在 V86 與保護模式間切換的 CPU，成本落在與觀測目標無關的地方。
建議把現在這條路一般化成三塊——細節與規模在
[`knowledge-base/030`](../knowledge-base/030-protected-mode-and-dos4gw.md)：

1. DOS 服務只留一份（`internal/dos` 支援 32 位元呼叫慣例）
2. 描述子表當一等公民（GDT／LDT 模型取代 per-program 閉包）
3. DPMI 通用子集（`int 31h` 的 12 支功能，契約來源是 DPMI 1.0）

### 批次 2b 的前置條件

FD2 的啟動握手目前用兩個閉包冒充 PSP（selector `0028h`）與環境區塊
（selector `0030h`）：`SegmentLoadOK` 放行那兩個 selector，`SegmentRead8`／
`SegmentRead16` 在特定位移回特定值。要換成真的描述子，得讓那兩段有**實際的
backing 記憶體**——也就是 LE 載入器要在映像之上保留位址空間。

**這一步改的正是 FD2 開機時讀的那幾個 byte，而它的收據要有原版執行檔才跑得出來**
（`internal/machine/le_machine_test.go` 沒有 `DOSGOLEM_FD2_EXE` 就 skip）。
在拿得到那支執行檔之前做這個改動，等於改一條驗不了的路徑：改壞了不會有人發現，
直到下一次有人拿原版跑。**所以先不做**，條件是：

1. 手上有 `DOSGOLEM_FD2_EXE`（雜湊見 `081`）；
2. 改動前先跑一次現有的 FD2 軌跡測試取得基準；
3. 改完之後同一份軌跡要一步不差。

**每一批的反面判準**：做完之後，「接下一支程式要改哪些檔」的清單要變短。
沒變短就是這一批做錯了地方。

## 不做的（現在）

- **分頁、例外、V86**：只有跑真的 extender 才需要（路線 A）。
- **VESA（`int 10h AH=4Fh`）**：等有目標程式。
- **真的讀磁區（`int 13h AH=02h`）**：要先有磁碟映像的模型；現在回失敗是誠實的。
- **Sound Blaster／MIDI 的逐週期時序**：`081` 已經說明不以逐週期相同為目標。
- **長檔名（`71h`）、FAT32（`73h`）**：Windows 9x DOS box 才有，年代對不上。

## 為什麼不照 DOSBox-X 的涵蓋面補齊

DOSBox-X 要跑得動 1981 年以來的所有東西，dosgolem 只要跑得動**被觀測的那幾支**
而且**跑得準**。把 114 個 `int 21h` 子功能補滿不會讓對拍更準，只會讓
`Unimplemented` 統計失去訊號——那份統計現在的價值正是「程式踩到了我們沒做的東西」
會**留下痕跡**，而不是安靜地走進錯誤路徑。

判準因此是「**有程式踩到**」，不是「表上有洞」。P1 那九支列在這裡不是因為
DOSBox-X 有，而是因為它們對應到 C 標準函式庫的常用函式，下一支程式踩到的
機率高到值得先做。
