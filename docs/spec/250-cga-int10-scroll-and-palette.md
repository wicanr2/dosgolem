# 250 CGA 圖形模式的 INT 10h 視窗捲動與清除、色彩選擇

狀態：CONFORMED（2026-10-04；實作 commit `ebacf6d`，驗收第 1 至 4 項通過，同狀態收據見 §5.1；READY 於 2026-10-03，第二輪「可實作性」與第三輪「契約一致性」兩輪獨立審查，阻擋項與應改項已修）。本規格補 `internal/dos/bios.go` 的 `int 10h` 在 CGA 圖形模式（04h、05h）缺的兩組服務：`AH=06h`／`07h`（捲動視窗、清除視窗）與 `AH=0Bh`（背景色與調色盤選擇），並公開 CGA 四色的 RGB 表。其他視訊模式的行為不變。同號文件在 dosgolem 是允許的（其他分支也有 250 號文件），引用一律連號碼帶檔名（`250-cga-int10-scroll-and-palette`）。

## 1. 為什麼要做

現況：`bios.go` 對 `AH=06h` 收下就好（`case 0x02, 0x03, 0x05, 0x06, 0x09, 0x0A:`，沒有動作），`AH=07h`、`AH=0Bh` 落入 `default` 只記一筆 `note`。使用 BIOS 清除視窗的 CGA 程式，在這裡視窗內的舊像素不會被清掉，畫面與真機不同；執行期疊字與對拍都以畫面為準，這個差異會直接進入驗收。

證據（私有研究，本規格不含原版素材）：一個 CGA 模式 04h 的程式在 60M 步內呼叫 13 次 `AH=06h AL=0 BH=0`，以視窗矩形內非零像素數量測，呼叫前後完全相同（多組矩形：前後都是 7256、14602、6079 個非零像素），`Unimplemented()` 為空。同一程式的清單捲動以 `AL=1` 呼叫 `AH=06h`（靜態）。程式端靜態有 `AH=0Bh` 的呼叫點（`BH=1`，`BL=0` 與 `1`），本機動態路線未走到。

## 2. 範圍

| 項目 | 內容 |
|---|---|
| 納入 | 模式 04h 與 05h（320×200，每像素 2 位元，40×25 個 8×8 字元格）：`AH=06h`、`AH=07h`、`AH=0Bh`；色彩選擇狀態（放在 BDA）；`oracle.CGAPalette()`；`machine` 匯出掃描線位移函式供 `oracle.CGA4` 與捲動共用 |
| 不納入 | 文字模式的捲動（保持現狀）；模式 06h（640×200 單色）；模式 05h 的色彩爆發關閉造成的色相差異（05h 暫用與 04h 相同的色表，標未驗證）；寫 `3D9` 埠；設模式時清畫面（`SetVideoMode` 對非平面模式不清畫面，維持現狀，與真 BIOS 不同，標未驗證；本機程式從零記憶體啟動，不受影響） |
| 不變量 | 其他模式與其他 `AH` 的行為不變；本規格只在模式為 04h 或 05h 時動作 |

## 3. 行為

視訊記憶體版面（`oracle.CGA4` 已採用）：第 `y` 條掃描線在 `B800:((y/2) × 80 + (y%2) × 2000h)`，每位元組 4 個像素（高位元在左），一個字元格橫向 2 位元組、縱向 8 條掃描線。`machine.CGAScanlineOffset(y int) uint32` 回傳該偏移，`oracle.CGA4` 與本規格的實作都用它（一份常數，不複製）。

### 3.1 `AH=06h`（上捲）、`AH=07h`（下捲）

輸入：`AL` 行數、`BH` 填色、`CH`／`CL` 視窗左上的列、欄、`DH`／`DL` 視窗右下的列、欄（字元格座標）。語意以 DOSBox-X 的 `INT10_ScrollWindow`（`src/ints/int10_char.cpp`）為參照：

1. 先檢查 `上緣 > 下緣` 或 `左緣 > 右緣`，成立就不動作（與 DOSBox-X 同序：先比較，後夾邊）。再把右下角夾到螢幕：列 0 至 24、欄 0 至 39（DOSBox-X 只夾右下角，不夾左上角）。夾邊後視窗已不存在（左上角在螢幕外，上緣大於夾邊後的下緣或左緣大於夾邊後的右緣）時不動作：DOSBox-X 此時迴圈走出界外的列，屬未定義行為，這裡定為不動作。因為有這個後置檢查，「先比較後夾邊」與「先夾邊後比較」兩種次序的可觀察行為相同。
2. 填色：取 `BH` 的低 2 位元，複製到一個位元組的 4 個像素（`BH & 3` 為 `c` 時填 `c × 0x55`）。本機程式的所有呼叫 `BH = 0`，兩種解讀（原始位元組或色號複製）無差別；`BH` 為其他值時採 DOSBox-X 的色號複製語意，標「未以真機驗證」。
3. `AL = 0`，或 `AL` 不小於視窗高度（列數）：整個視窗以填色填滿。（`AL` 大於視窗高度時 DOSBox-X 以 8 位元計數，行為未驗證；本機程式從未如此呼叫，這裡定為清除。）
4. 其他：上捲時視窗內每個字元格列往上移 `AL` 列（逐條掃描線複製，只動視窗橫向範圍的位元組），底部 `AL` 列以填色填滿；下捲反向，頂部 `AL` 列以填色填滿。複製要避免來源與目的重疊時被覆蓋（上捲由上往下複製，下捲由下往上複製）。
5. 不改暫存器，不改游標。寫入走 `Machine.Write8`（不直接寫 `Mem`，以保留寫入觀察者的通知）。

### 3.2 `AH=0Bh`

色彩選擇暫存器不新增 `Machine` 欄位，**存放在 BDA `0040:0066`**（`bda.go` 已把它初始化為 `30h`）。BDA 位於 `Mem` 內，`Snapshot` 與 `SaveState` 自動涵蓋，不需改存態版本。位元定義同 `3D9` 埠：

| 位元 | 意義 |
|---|---|
| 0 至 3 | 背景（色號 0）的顏色（16 色之一） |
| 4 | 前景（色號 1 至 3）使用高強度 |
| 5 | 調色盤選擇：0 為綠、紅、棕；1 為青、洋紅、白 |

`BH = 0`：`[0040:0066] = ([0040:0066] & 0xE0) | (BL & 0x1F)`。`BH = 1`：`[0040:0066] = ([0040:0066] & 0xDF) | ((BL & 1) << 5)`。其他 `BH` 值：維持原行為（記一筆 `note`；DOSBox-X 對非 0 的 `BH` 一律走調色盤選擇，標未驗證）。模式不是 04h、05h 時維持原行為。

模式 04h、05h 設定時，`[0040:0066]` 重設為 `30h`（調色盤 1、高強度、背景黑）：重設放在 `Machine.SetVideoMode`（不放在 `bios.go` 的 `AH=00h` 分支，因為測試與其他呼叫端會直接呼叫 `SetVideoMode`），且在通知 `onModeChange` 之前完成，使觀察者看到新狀態。

### 3.3 RGB 表

16 色 CGA RGB（`oracle.CGAPalette()` 內部使用）：0 黑 `(0,0,0)`、1 藍 `(0,0,170)`、2 綠 `(0,170,0)`、3 青 `(0,170,170)`、4 紅 `(170,0,0)`、5 洋紅 `(170,0,170)`、6 棕 `(170,85,0)`、7 淺灰 `(170,170,170)`、8 深灰 `(85,85,85)`、9 淺藍 `(85,85,255)`、10 淺綠 `(85,255,85)`、11 淺青 `(85,255,255)`、12 淺紅 `(255,85,85)`、13 淺洋紅 `(255,85,255)`、14 黃 `(255,255,85)`、15 白 `(255,255,255)`。

`CGAPalette()` 回傳 `[4][3]uint8`：色號 0 是背景色（`[0040:0066] & 0x0F`）；色號 1、2、3 依 bit 5 與 bit 4 取：調色盤 0 為綠、紅、棕（強度時為淺綠、淺紅、黃），調色盤 1 為青、洋紅、淺灰（強度時為淺青、淺洋紅、白）。模式不是 04h 或 05h 時回傳預設值（調色盤 1 高強度、背景黑）。

## 4. 實作位置與注意事項

- `internal/machine/cga.go`：`CGAScanlineOffset`、`CGAScroll(top, left, bottom, right, lines int, down bool, fill byte)`、`ColorSelect()`／`SetColorSelect()`（讀寫 BDA）、色表。`SetVideoMode`（`bda.go`）在 04h、05h 時重設色彩選擇。
- `internal/dos/bios.go`：把 `0x06` 從舊的收下列移出（否則編譯錯誤：重複 case），新增 `case 0x06, 0x07` 與 `case 0x0B`；非 04h、05h 時 `0x06` 收下、`0x07` 與 `0x0B` 記 `note`（`note` 的鍵含 `AL`：`d.note(0x10, fn, al(c))`，測試用同一個 `AL` 查）。
- `oracle/oracle.go`：`CGAPalette()`；`CGA4RGB() []uint8`（回 320×200×3 的 RGB，由 `CGA4()` 的色號與 `CGAPalette()` 換算，前端與收據共用同一個入口，不各寫一份）；`CGA4` 改用 `machine.CGAScanlineOffset`，既有 `CGA4` 測試不變。

## 5. 驗收

1. 獨立向量：以另一種語言（Python，Docker 內）依 DOSBox-X 的 `INT10_ScrollWindow`、`CGA4_CopyRow`、`CGA4_FillRow` 語意重現，對隨機視窗與行數（含 `AL = 0`、`AL` 等於視窗高度、跨 bank 的奇偶列、視窗貼邊）產生期望位元組向量，存成 Go 測試的字面值（TSV 或 Go 表）。測試的初始資料每條掃描線互異（位元組 = `f(y, x)`），使複製方向、bank 位移、每格寬度錯誤都不會因填充值相同而通過。
2. 單元測試（`internal/machine`、`internal/dos`，期望值寫字面值）：
   - 清除：視窗內全部位元組成為填色，視窗外一個位元組都不變（含視窗左右緣相鄰位元組、上下緣相鄰掃描線、交錯 bank）。
   - 上捲 1 列與 3 列、下捲 1 列：內容位移的位元組位置與底部（頂部）填色；視窗外不變。
   - `AL` 等於或大於視窗高度等同清除；`BH` 非 0（低 2 位元複製）。
   - 夾邊：右下角超出 `(DL = 79, DH = 24)` 時等同夾到 `(39, 24)`；上緣大於下緣不動作。
   - `CGAScroll` 寫入的位元組由 `oracle.CGA4()` 讀回，與預期像素相同（版面一致性）。
   - 非 CGA 模式（mode 13h）：`AH=06h` 不動視訊記憶體，`AH=07h`、`AH=0Bh` 仍記 `note`。
   - `AH=0Bh`：`BH=0` 設背景並保留高 3 位元，`BH=1` 設調色盤並保留其他位元；`SetVideoMode(0x04)` 後 `[0040:0066] = 30h`，且重設發生在 `onModeChange` 通知之前。
   - `CGAPalette()`：預設值、調色盤 0/1、有無強度、背景色變更，共 8 組字面值；`CGA4RGB()`：以一張已知色號畫面（四個色號各一塊）對照 `CGAPalette()` 的字面 RGB。
   - 存態往返：`AH=0Bh` 改色後 `SaveState`、`LoadState`，`CGAPalette()` 不變。
3. 負對照：把 `AH=06h` 恢復成「收下就好」，清除與捲動測試應失敗；複製方向反向、奇數 bank 位移寫錯（不加 `2000h`）、每格寬度寫成 1 位元組，各自對應的測試應失敗；把 `BH=1` 的位元寫到 bit 4，調色盤測試應失敗；把色彩選擇改存在新的結構欄位，存態往返應失敗。
4. 同狀態收據（有原版時）：一個 CGA 程式的清除視窗與清單捲動（`AL=1`）呼叫，以同樣參數餵給 Python 重現，視窗內位元組逐一相同；缺原版時 SKIP，不算驗收。
5. 其他分支與既有收據：`go test ./...` 既有測試不變。
