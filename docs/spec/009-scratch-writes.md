# 009 — 寫檔：唯讀的原版目錄 ＋ 可寫的暫存層

狀態：**READY**
日期：2026-09-07
前置：[`004`](004-dos-bios-services.md) §2（`int 21h`）、
[`008`](008-bios-keyboard-injection.md)（鍵送得進去之後才會走到要存檔的地方）

---

## 1. 為什麼要做

`AH=40h` 目前只把「程式想寫幾個位元組」記進 `Wrote` 就回報成功，
`AH=3Ch`（建檔）根本沒有分派，落在「未實作但宣告成功」那條。
對第一個案例（`rich2`，MVP-B 不需要存檔）那樣就夠。

第二個案例走到建角就卡住：《Pool of Radiance》把新人物寫成
`<名字>.CHA`／`.SPC`／`.ITM` 並把名字追加進 `CHARLIST.TXT`，
接著 `A)DD CHARACTER TO PARTY` **從 `CHARLIST.TXT` 讀名單**。
寫入被吞掉之後那份名單永遠是空的，所以：

- 按 `A` 之後畫面**一個像素都沒變**（量到的兩張雜湊完全相同）；
- 空隊伍的選單裡沒有 `BEGIN ADVENTURING`，於是走不到地圖與第一人稱畫面。

**症狀完全不指向寫檔**：看起來像「按鍵沒送到」或「選單沒反應」，
而鍵是送到了、也被讀走了（`KeysConsumed` 有增加）。

## 2. 契約

1. `DOS.Scratch` 是可寫的暫存目錄。**預設空字串，行為與現在完全相同**
   （寫入記進 `Wrote`、回報成功、不落地）。第一個案例不受影響。
2. `Scratch` 非空時：
   1. `resolve` **先找 `Scratch`，再找 `Root`**。暫存層蓋過原版目錄。
   2. `AH=3Ch`（建檔）在 `Scratch` 下建立／截斷該檔，回一個可讀寫的 handle。
   3. `AH=3Dh`（開檔）的存取模式在 `AL` 的低兩位：`0` 唯讀、`1` 唯寫、
      `2` 讀寫。要寫的模式若檔案只存在於 `Root`，**先整份複製到
      `Scratch`** 再以讀寫開啟。唯讀模式維持現狀。
   4. `AH=40h` 對可寫 handle 真的寫進去；其餘（stdout／stderr／唯讀 handle）
      維持現狀。
   5. `AH=41h`（刪檔）只刪 `Scratch` 底下的；`Root` 裡的檔案**永遠不動**。
3. **`Root` 在任何情況下都不被寫入。** 原版素材唯讀是硬規則
   （`CLAUDE.md`），而且容器裡它就是 `ro` 掛載——真的寫下去只會拿到
   EACCES，那個錯誤訊息不會告訴任何人原因。
4. `Wrote` 照舊記每一次寫入，**寫成功也記**。它是「程式想存什麼」的紀錄，
   不是「失敗清單」。

## 3. 不做什麼

- **不做目錄操作**（`AH=39h` 建目錄、`3Ah` 刪目錄）。Pool 只在同一層寫檔。
  `AH=39h` 被叫過 5 次，仍走「宣告成功」那條。
- **不做檔案屬性、時間戳、rename。** 沒量到有人用。
- **不做多磁碟機**：`Scratch` 只有一個，`resolve` 照舊只認 basename。
