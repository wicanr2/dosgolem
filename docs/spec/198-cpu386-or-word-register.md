# 198 — MOO2 啟動鏈的 16 位暫存器 OR

狀態：**CONFORMED**（只限 `66 09 /r` 的 `mod=11` 形狀）
日期：2026-09-30

固定 MOO2 1.31 `ORION2.EXE` SHA-256 `4e11be14217b4aafa1839f333bf5eba037f98b0c44e9e4752c96c464c260419f`，以 [197](197-bound-mz-le-file-base.md) 正確載入。暫以 FD2 專屬 DOS 服務層作**診斷**，在真入口第 36 步、dosgolem LE 線性位址 `0x110076` 停於 `66 09 CA 74 02 ...`；這不是 MOO2 正式服務收據。x86 指令 `66 09 CA` 是 `OR DX,CX`，只修改 DX 的低 16 位，EFLAGS 的 CF／OF 清零，SF／ZF／PF 依 16 位結果更新；未定義 AF 不作精確要求。後續 `74 02` 消費 ZF，因此位寬與旗標會改變啟動分支。

只新增無 segment／repeat 前綴的 `66 09 /r`、`mod=11`；既有 32 位 `09 /r` 及其他未支援形狀保持失敗即關閉。合成測試覆蓋保留高 16 位、零結果與負號／同位性旗標、未支援 memory 形狀；真檔診斷只用於確認越過 `0x110076` 並記錄下一停點，不聲明玩法對拍。原版檔案唯讀且不提交。

驗收：`go test ./internal/cpu386 ./internal/machine` 通過；使用 FD2 專屬服務層的可丟棄 MOO2 探針越過 `0x110076`，在第 45 步、`0x1100B2` 停於 `66 26 8C 1D ED 01 11 00`（16 位元 segment store 尚未支援）。該服務層具 FD2 專屬 selector／環境，45 步僅是診斷範圍，不是 MOO2 正式啟動或玩家路徑收據。
