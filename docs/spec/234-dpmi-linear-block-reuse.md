# 234 — DPMI 線性區塊釋放與重用

狀態：**CONFORMED**（僅 DPMI 線性區塊回收；MOO2 玩家路徑未對拍）
日期：2026-10-01
範圍：dosgolem `INT 31h/AX=0501h、0502h` 的通用線性記憶體服務。只修正合成執行器的可用位址回收，不改 MOO2 玩法與正式記憶體需求。

## RE／平台證據

- **已證實，原始輸入與執行器位址空間**：官方 1.31 `ORION2.EXE` SHA-256 `4e11be14217b4aafa1839f333bf5eba037f98b0c44e9e4752c96c464c260419f`，正版 `MOX.SET` SHA-256 `bfd6855a41760b31156b96114b5b33c88f442ab8f8aae020c1740b3b486a3a80`，與原版 ZIP 根層 417 檔案；一次性 `golang:1.24-bookworm` 容器中以 dosgolem `workplace/moo2-probe` 自 LE entry 重播。第 295276 步於**重定位 LE 線性位址** `0x1101E1` 退出，主控台回 `Insufficient Memory!`。DPMI `0501h` 126 次、`0502h` 122 次，退出時只有兩個仍在配置的線性區塊，機器記憶體已長至 66,285,568 bytes，接近執行器 64 MiB 安全上限；未實作服務計數為空。私有 `workplace/moo2-probe-memory-audit.txt` SHA-256 `05a3295912c263601e75dcf1933fd6ad14022edebd9e3a072e4d6f47be165d`。這是合成環境收據，**不是**原版同狀態記憶體收據。
- **已證實，平台契約**：[DPMI 1.0 規格，`0501h`／`0502h`，PDF 第 101–102 頁](https://docs.pcjs.org/specs/dpmi/1991_03_12-DPMI_Spec_v10.pdf)規定 `0501h` 回傳至少段落對齊的線性位址與用於釋放的控制代號；`0502h` 以控制代號釋放，無效代號回 `8023h`。控制代號與位址是不同輸出，不要求數值相等。
- **已證實，現行執行器限制**：`internal/machine/dpmi.go` 的 `0502h` 只從帳本刪除區塊，配置游標 `brk` 單調增加；`0501h` 超過 `dpmiAddressLimit=64 MiB` 時回失敗。現有 `internal/machine/dpmi_test.go` 明文把不重用地址當作診斷取捨。既有 [`009-memory-allocator`](009-memory-allocator.md)已為 16 位元 DOS arena 採首次適配與相鄰區塊合併；本切片只處理另一個 DPMI 線性 arena。
- **強推論**：多次配置／釋放且存活區塊很少，搭配單調游標與 64 MiB 限額，足以使原合成路徑過早耗盡線性位址。`DOS space remaining 0` 的另一原因是 LE 映像與低位 DOS 記憶體共用地址空間，屬獨立阻塞。

## 擬議契約

對 `0501h` 的配置長度向上補齊到 16 bytes；保留現行 64 MiB 安全上限。優先從已釋放區間按線性位址升序首次適配，切出所需長度；找不到才從現有游標配置。`0502h` 驗證控制代號，成功後把該區間加入空閒清單並合併相鄰區間。每次配置分配不重複、非零的控制代號，使舊控制代號即使位址被重用也保持無效；活區塊不得重疊。重用區間清零以固定合成初始狀態；此值屬**平台規格近似**，原版新配置記憶體內容未知。零大小、位址／長度溢位、超上限與無效代號維持失敗即關閉；本切片不重用仍活著的地址，不改 `0100h` DOS 低位配置、實模式記憶體映射或原版資料。

## 驗收與邊界

1. 合成測試：兩個活區塊互不重疊；釋放後首次適配重用該線性位址，舊代號仍回 `8023h`，新代號可釋放；兩個相鄰空閒區合併後可服務較大的配置；重用內容受控清零；零長度與超上限拒絕。
2. 固定原檔的既有全套 Go 測試須通過。以同一正版資料重跑 `workplace/moo2-probe`，記錄 `0501h/0502h` 次數、活區塊、下一自然結果及退出訊息；不把前進步數當作原版玩法對拍。
3. `0100h` 的低位 DOS 記憶體游標與 LE 映像重疊問題維持獨立。DOSBox-X 輔助擷取已見原版首次 513 段落配置成功，但尚無完整同狀態收據；本規格即使通過也只代表執行器平台契約與合成路徑改善。

## READY 審查

已核對 `internal/machine/dpmi.go`：控制代號只用於 `blocks` 帳本及 `0502h` 查找，`Blocks()` 依位址排序；現有 `internal/machine/dpmi_test.go` 只要求回傳控制代號可用，未要求與位址相等。首次適配按起始位址排序、相鄰合併與單調不重複代號可在 64 MiB 上限內決定性執行，不需調整 MOO2 程式資料或猜測玩法語意。唯一待實作後檢驗的是完整資料下一個自然結果，已列為驗收而非行為規則；因此本 CPU／DPMI 工具切片可進入實作。正式收據仍必須標示平台契約近似，不可升格為原版同狀態 parity。
