# 015 — 位元碼觀測：`-bc-ring`／`-bc-seen`／`-bc-sub`（READY）

## 問題

被觀測的程式跑的是自己的位元碼虛擬機（源平合戰是這樣，同一族的
KOEI 引擎都是）。這時候 `CS:IP` 幾乎沒有資訊量——不管腳本在做什麼，
機器都在直譯器那幾十道指令裡打轉。「剛剛那句話是哪一支腳本印的」
用一般的斷點答不出來。

## 三個旗標

| 旗標 | 收什麼 | 回答什麼 |
|---|---|---|
| `-bc-ring <seg>:<off>[:N]` | 執行到 `seg:off` 時的 `DS:SI`，留最後 N 筆相異值 | 剛剛在跑哪幾段位元碼 |
| `-bc-seen <seg>:<off>:<起>-<迄>` | 同上，但收成**集合**，照第一次看到的順序印 | 這段時間**有哪些**位元碼位址跑過 |
| `-bc-sub <seg>:<off>:<起>-<迄>[:N]` | 執行到 `seg:off` 時的 `DS:BX`，**變了才記一筆** | 那些位址**屬於誰**、誰換給誰 |

三個都掛在同一個掛鉤點（每道指令之前），旗標沒給時只多一個比較。

## 為什麼是 `DS:SI` 與 `DS:BX`

直譯器用 `lods al,ds:[si]` 取下一個位元組，所以 **`DS:SI` 就是位元碼的
程式計數器**。而描述子呼叫（源平合戰的 `8B`–`90`）用 `xlat` 去查
「這一支副程式的對照表」，`xlat` 讀的是 `DS:BX`，所以 **`BX` 是目前這一
支副程式的識別**——換了一支，`BX` 就換。

## 兩個會讓結果看起來很正常、其實是空的坑

**掛錯地方會收到空集合，而空集合看起來像「這段時間沒有腳本跑」。**
要掛在**主分派迴圈**上，不是任何一個看起來像分派的位址。判準：拿一段
`-ip-log` 比對閒置與事件兩個時段——閒置時整台機器就在主分派那一圈裡
打轉（源平合戰是 `3121:0CA0`–`0CEC`，前十二萬筆指令只有 885 個相異的
`CS:IP`），離開那一圈的那一刻就是腳本開始跑的那一刻。
（源平合戰的 `3121:13F8` 在 1,700 萬道指令裡只被打到五次；拿它當分派點
收到的永遠是那幾個複製位元組的小函式。）

**`-bc-ring` 會被最內圈的緊迴圈灌滿。** 一個複製位元組的小函式跑幾千圈
就把環形記錄清空了，外層是誰完全看不到。要看「這段時間有哪幾支跑過」
用 `-bc-seen`，要看「誰換給誰」用 `-bc-sub`。

## 驗收

在源平合戰劇本一的開局事件上，`-bc-sub 3121:0CA0:421700000-421983400`
印出 26 筆換手，最後五筆依序是訊息組字、對話框、搬字元——與畫面上
那個對話框出現的順序一致。同一條命令重跑兩次逐位元組相同。
