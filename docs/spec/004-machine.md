
## 2.2 BIOS 計時器 stub 的還原順序（`int 08h` → `int 1Ch`）

`int 08h` 的預設處理是 StubSeg 裡一段真的程式碼（`machine.biosTimerOff`）。
它的**還原順序**要照 IBM PC BIOS 的 `TIMER_INT`：

```
push ds / push ax / push dx
mov ax,40h / mov ds,ax
inc word [6Ch] / jnz +4 / inc word [6Eh]
int 1Ch
pop dx / pop ax / pop ds
iret
```

**還原在 `int 1Ch` 之後，不是之前。** `int 1Ch` 的處理常式是應用程式掛的，
它弄髒 DS／AX／DX 都由 BIOS 這三個 `pop` 收拾。80186 之後常見的寫法是
`pusha`／`popa`，而**那兩道不含段暫存器**——掛 1Ch 的程式因此可以
理直氣壯地 `mov ds, 自己的段` 而不還原。

反面（在 `int 1Ch` 之前就 pop 完）沒有任何錯誤訊息：DS 漏回被中斷的
程式，它接著用錯的段讀資料，照樣一路執行下去。

> 實例（源平合戰 `MAIN.EXE`，2026-09-06）：它的 1Ch 是
> `cli / pusha / mov ds,2A1E … popa / sti / jmp far 舊向量`。DS 漏回
> 位元碼直譯器之後，直譯器改從 `2A1E:SI` 抓位元碼（原本是 `336E:SI`），
> 執行了四百道別的模組的位元碼，物件型別查表取到第 82 項（表只有 27 項），
> `DS` 變成 0，再過十九萬道指令才走進低位記憶體結束。
> **症狀離成因十九萬道遠，而且畫面停在一個正常的對話框上。**
> 修好之後遊戲跑進主選單並開始輪詢滑鼠。

## 4.1 int 33h 的水平座標倍率隨模式而變

int 33h 的虛擬螢幕**永遠是 640 格寬**，不管實際模式多寬：320 寬的模式
（13h）回報值是像素的兩倍，所以 X 永遠是偶數；640 寬的模式（12h）一比一。

寫死 2 的話，640 寬畫面上點右半邊會回報成超出畫面的座標。遊戲判定
「不在任何按鈕上」而**安靜地什麼都不做**——沒有錯誤，畫面就是沒反應。

## 4.2 點擊要落在程式真的在輪詢的視窗裡

`cmd/probe -clicks "步數:X:Y,…"` 一次帶整串輸入，`-click-hold` 是按住的
指令數。挑步數之前先看報告裡的**輪詢分佈**：程式重畫畫面時可以兩千萬道
指令一次都不問滑鼠，點在那段等於沒點。

> 源平合戰 `MAIN.EXE` 從 TSR 常駐算起：#20M 點掉磁片提示，之後
> #23M–#60M 完全不輪詢（在畫主選單），#60M 之後才收得到主選單的點擊。

## 4.3 一次跑存好幾張畫面

`cmd/probe -shots "步數:路徑,…"` 在指定步數各存一張畫面色號（色盤存成
同名 `.pal`）。**要看中途的畫面不要重跑**——走到遊戲深處的畫面動輒
好幾億道指令，一次跑五分鐘，為了看中間一張再跑一次是純粹的浪費。

## 4.4 按鍵要在程式開始輪詢之後才送

`cmd/probe -keys` 是**一開始就排進佇列**，程式還沒開始輪詢就被吃掉了。
要在特定畫面送按鍵用 `-keys-at "步數:字串,…"`。

## 4.5 按住的長度要用「輪詢次數」算，不是指令數

`-click-hold` 是固定指令數，**在不同畫面之間不可移植**。同一支遊戲的
輪詢頻率可以差三個數量級：

> 源平合戰 `MAIN.EXE`：磁片提示每千萬道指令只問 12 次滑鼠（約 83 萬道
> 一次），讀檔選單每千萬道問一千次以上（約 1 萬道一次）。三百萬道的
> 按住在前者剛好夠一次，在後者會被讀成四千次連點——按下選單第二列
> 之後那四千次繼續打在下一個畫面上，遊戲以離開碼 255 結束，
> 看起來像「點那一列會讓遊戲關掉」。

`-click-polls N` 改成**按住到程式真的讀了 N 次滑鼠才放開**。預設用 3。
判準與畫面無關，寫死的步數則要每個畫面重調一次。

## 4.6 找「控制流在哪裡分岔」：`-ip-log`

`-ip-log 起:迄:路徑` 把那一段每一道指令的 `CS:IP` 以二進位寫出來
（每筆 4 bytes）。跑兩次只差一個輸入的執行，再拿 `cmp` 找第一個不同的
位元組，就是控制流第一次分岔的位置。

三百萬道指令的完整暫存器軌跡是三百 MB 的文字，同一段只記 `CS:IP` 是
12 MB；**先用它定位，再用 `-trace` 對那一小段抓暫存器**。

> 用法（源平合戰的設定畫面）：一次點在會回應的選項框、一次點在按不動的
> 「決定」鈕，其餘完全相同。兩份 `CS:IP` 在點擊後 8467 道分岔，位置是
> `336E:2A10`——一支 `pointInRect(x, y, x0, y0, x1, y1)` 的遠呼叫。
> 之後只要把它的參數印出來，畫面上註冊了哪些矩形就一覽無遺。

## 4.7 看「程式在比什麼」：`-call-args`

`-call-args CS:IP:字數:起:迄` 每次執行到那個進入點就把堆疊上的參數印出來。
位置取**進入點**（還沒 `push bp`），所以參數從 `SS:SP+4` 起算——遠呼叫的
返回位址佔 4 bytes。

控制流只告訴你「沒中」，參數才告訴你「拿什麼去比」。

## 4.8 記錄除以零的現場

C runtime 遇到除以零只印一句 `run-time error R6003` 就走人，離開碼 255，
**現場什麼都不留**。`cpu.CPU.DivErrors` 記下每一次除以零當下的 `CS:IP`
（最多 32 筆），probe 的報告會印出來。位址是**下一道**指令——8086 推的
返回位址指向下一道。

## 4.9 監看與讀檔紀錄都保留「最後」而不是「最前」

`-watch` 的寫入紀錄與讀檔紀錄都改成留最後幾筆。要找的通常是「誰最後
把它寫壞的」；砍後面那版會在開機階段就把配額用光，真正的兇手一筆都不留。
