# 203 — 疊字層：以畫面內容當觸發點（圖檔內嵌文字）

狀態：**READY**
日期：2026-09-18
前置：[`202-translation-overlay.md`](202-translation-overlay.md)（`xlate.Layer`、`Stamp`、指紋失效）

---

## 1. 問題

`202` 的疊字是在「原版印字」的那一刻建立的：攔到印字常式 → 知道印了哪一則、印在哪 → 蓋中文。

畫在圖檔裡的文字沒有這個時刻。圖被畫到畫面上的路徑不只一條（直接畫、先解到緩衝區再貼、由腳本決定位置），
每條都攔要讀完整套繪圖程式；而且同一張圖可能在不同畫面出現在不同位置。

需要的是另一種觸發點：**畫面上某塊像素等於已知的原版圖塊時，就把中文蓋上去。**
原版圖塊怎麼來是呼叫端的事（本例是解 `.PBL`），本規格只管「比對到就蓋、不見了就收回」。

## 2. 規格

### 2.1 `Watcher`

```go
type Watcher struct {
    Key   string   // 紀錄用
    X, Y  int      // 畫面座標（原版像素）
    W, H  int      // 區塊大小
    Want  []uint8  // 期望的色號，長度 W*H
    Probe []int    // 先比這幾個位置（Want 的索引）；空的話由 Layer 自己挑
    Make  func() []*Stamp // 比對到時要加的疊字（呼叫端自己決定文字、字型、格數）
}
```

- `Layer.Watch(w *Watcher)` 登記；`Layer.Unwatch(key string)` 移除。
- 每次 `Frame`：對每個「目前沒有活著的疊字」的 watcher，先比 `Probe`（預設由 `Want` 均勻取 8 點），
  全中才比整塊；整塊相同就呼叫 `Make()`，把回傳的疊字加進 `Layer`（`Add` 的重疊移除照舊）。
- watcher 加進來的疊字帶 `Owner = watcher.Key`；疊字被移除（失效、捲動出框、被覆蓋）之後，
  下一次 `Frame` 又會重新比對，畫面回到原樣時就再蓋一次。
- 一個 watcher 的疊字還活著時**不比對**（省成本，也避免同一塊重複加）。

### 2.2 成本

- `Probe` 先比 8 個點，不中就跳過：一個 watcher 的一般成本是 8 次比較。
- 全中才比 `W*H`；同一塊只在「剛出現」與「剛消失」的那一幀付這個成本。
- `Layer.Frame` 的既有工作（定色、指紋）不變。

### 2.3 與 `202` 的關係

- `Stamp` 加一個欄位 `Owner string`（預設空字串），只用來對應 watcher；快照與還原要保存。
- `Watcher` 本身不進快照（`Snapshot`／`Restore` 不含 watcher）：呼叫端在載入狀態之後重新登記，
  下一次 `Frame` 自然會補上。**還原後畫面上有的東西，watcher 會再比對一次。**

## 3. 驗收

1. `Watch` 一個 4×4 的區塊：畫面內容相符時 `Frame` 後疊字出現；內容改掉之後疊字消失（指紋失效），
   再改回來又出現。反向對照：內容從頭到尾都不相符時，`Make` 一次都沒被呼叫。
2. `Probe`：內容只有一個非 `Probe` 位置不同時，仍然不會建立疊字（先比 `Probe` 只是加速，不能影響結果）。
3. `Make` 回傳多筆疊字時全部加入，且都帶同一個 `Owner`。
4. `Unwatch` 之後不再比對；已經加上去的疊字不受影響（由既有的失效規則處理）。
5. 快照往返：`Owner` 保存；還原後重新 `Watch` 再 `Frame`，不會重複加疊字。

## 4. 不做

- 在畫面上搜尋位置（只比對登記的座標）。
- 縮放或旋轉比對。
- 圖檔格式（`.PBL` 等）的解碼：呼叫端提供 `Want`。
