## 原版證據

FD2.EXE，357074 bytes，MD5 b97caf2239a27a896069d03549d96e1e，
SHA-256 222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f。
IDA Pro 9.4 的 LE 線性位址 0x15C59，原始指令為 d1642408。
保留 IDA operand：shl [esp+20h+var_18], 1。var_18 僅供導覽。
指令解碼為 SHL dword ptr [ESP+8],1；此位址與 bytes 已證實。
正式 dosgolem 原版收據在 relocated LE 0x15C59 拒絕 ModRM64。
來源：fd2_re/docs/data/ida/fd2_ch17_oracle_d1_20261002.json。
目前不附加遊戲欄位語意。

## 契約

支援無前綴 D1 /4 的 r/m32，以既有 decodeAddress32 處理記憶體形式。
包含暫存器、SIB、disp8、disp32；不把規則寫死為本章 ESP+8。
ESP／EBP 基址沿用 SS，其餘沿用 DS。完整操作數寬度為4 bytes。
指令沒有 immediate；消費完有效位址即指向下一指令。

count固定1。結果為原值左移一位，超過32位的位元捨棄。
CF為原bit31，OF為結果bit31 XOR CF。SF／ZF／PF由結果決定。
IF／DF與其他控制旗標保留。AF依Intel為未定義；本實作沿用既有
setLogicFlags的確定性清零政策，不宣稱AF的硬體逐旗標一致。

先完成讀取與目的寫入，成功後才更新旗標。越界、不可寫及缺少來源拒絕。
新增形式不改既有16位暫存器位移、RCL／ROR與其他已支援形式。
其餘D1記憶體群組、segment／repeat／operand prefix維持既有拒絕政策。

來源：[Intel SDM Volume 2B，SAL/SAR/SHL/SHR章節，4-582至4-585](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf)。
有效位址沿用已驗證address32 decoder，規則與測試見address32.go／address32_test.go。

## 驗收

- 原版四bytes的ESP+8形式，SS與DS基址不同，驗結果、寬度及EIP。
- 暫存器與記憶體：零值、正負號跨越、CF、OF、ZF、SF及PF，控制旗標保留。
- SIB縮放索引、負disp8、disp32與無基址形式；有效位址不可寫、超界、
  指令截斷及未支援群組，驗資料／旗標沒有被發布。
- 整個cpu386與既有machine／FD2 oracle套件回歸。
- 修正提交後，乾淨FD2專用執行器以同槽、同計畫重跑，118點起手前綴不變，
  越過原版第一次敵方回合。原失敗保存；完整章仍由#88驗收。
