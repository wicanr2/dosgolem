## 1. 範圍

**Intel 8086／8088 real mode 的整數指令集**，含前綴、字串指令、中斷、旗標。

不做（做了也驗不了，而且 `RUN_full.EXE` 用不到——`001` §3）：

- x87 浮點。程式裡的浮點全部走 `INT 34h–3Dh` 進 binary 自帶的模擬器。
- 186／286／386 以上的指令、保護模式、分頁、32 位元運算元。
- **匯流排週期精確**（prefetch queue、`cycles` 陣列）。測資裡有，但比對時忽略。

## 2. 介面

```go
type Bus interface {
    Read8(addr uint32) uint8          // addr 是 20 位元線性位址
    Write8(addr uint32, v uint8)
    In8(port uint16) uint8
    Out8(port uint16, v uint8)
}

type CPU struct {
    R     [8]uint16   // AX CX DX BX SP BP SI DI（**8086 的編碼順序**）
    Seg   [4]uint16   // ES CS SS DS（同上）
    IP    uint16
    Flags uint16
    Bus   Bus
    // Hook 讓上層攔 INT；回傳 true 表示已處理，不走真正的向量表。
    IntHook func(c *CPU, n uint8) bool
    Halted  bool
}

func (c *CPU) Step() error   // 時序不在 MVP-A 範圍，見 docs/spec/001 §5
```

**暫存器順序照 8086 的編碼**（`AX CX DX BX SP BP SI DI`／`ES CS SS DS`），
不是照人念的順序。ModRM 的 3 位元欄位就是這個索引——照抄比翻譯不容易錯。

8 位元暫存器索引 `AL CL DL BL AH CH DH BH`：低 4 個是 `R[i]` 的低位元組、
高 4 個是 `R[i-4]` 的高位元組。

## 3. 旗標

| 位元 | 旗標 |
|---:|---|
| 0 | CF |
| 2 | PF |
| 4 | AF |
| 6 | ZF |
| 7 | SF |
| 8 | TF |
| 9 | IF |
| 10 | DF |
| 11 | OF |

**8086 的保留位元是固定值**：bit 1 恆為 1、bit 3／5 恆為 0、bit 12–15 恆為 1。
所以任何寫入旗標的地方都要套

```
Flags = (v & 0x0FD5) | 0xF002
```

`PUSHF`／`POPF`／`IRET`／`SAHF` 與中斷都經過它。**這一條不套，
SingleStepTests 會整批紅**，而且錯的是「看起來對的值」。

### 3.1 各運算的旗標語意（confirmed，Intel 8086 手冊）

| 運算 | CF | OF | AF | SF ZF PF |
|---|---|---|---|---|
| `ADD` | 進位 | 兩運算元同號、結果異號 | bit3 進位 | 依結果 |
| `ADC` | 同上（含 CF）| 同上 | 同上 | 依結果 |
| `SUB`／`CMP` | 借位 | 兩運算元異號、結果與**被減數**異號 | bit3 借位 | 依結果 |
| `SBB` | 同上（含 CF）| 同上 | 同上 | 依結果 |
| `INC`／`DEC` | **不動** | 同 ADD／SUB | 同上 | 依結果 |
| `AND`／`OR`／`XOR`／`TEST` | 0 | 0 | **未定義** | 依結果 |
| `NEG` | 運算元 ≠ 0 | 運算元 ＝ 符號位最小值 | bit3 借位 | 依結果 |
| `MUL`／`IMUL` | 高半部非零（IMUL：非符號延伸）| 同 CF | **未定義** | **未定義** |
| `DIV`／`IDIV` | **全部未定義** | | | |
| 移位 1 位 | 移出的那一位 | 見 §3.2 | **未定義** | 邏輯類依結果；`ROL`／`ROR`／`RCL`／`RCR` **不動** SF ZF PF |
| 移位 CL 位 | 同上；**CL ＝ 0 時完全不動旗標** | **未定義** | 未定義 | 同上 |
| `DAA`／`DAS` | 見 §3.3 | **未定義** | 見 §3.3 | 依結果 |
| `AAA`／`AAS` | 見 §3.3 | 未定義 | 見 §3.3 | **未定義** |
| `AAM`／`AAD` | 未定義 | 未定義 | 未定義 | 依結果 |

「未定義」不是「可以亂寫」——SingleStepTests 的 `metadata.json` 每個 opcode
帶一個 `flags-mask`，比對時把那些位元遮掉。**遮罩要從 metadata 讀，不要自己列**
（群組 opcode 的遮罩在 `reg` 子鍵底下，逐個 `/r` 不同）。

### 3.2 移位的 OF

⚠ **手冊說只有「移 1 位」時有定義，實機不是**——每一圈都重算，
最後一圈的值勝出（§4 第 5 點）。下面這張表是**每一圈**的算法：

```
SHL/SAL : OF = (結果最高位) XOR CF
SHR     : OF = 運算元的最高位
SAR     : OF = 0
ROL     : OF = (結果最高位) XOR CF
ROR     : OF = 結果最高兩位相異
RCL     : OF = (結果最高位) XOR CF
RCR     : OF = 運算元最高兩位相異（在移入 CF 之後算）
```

### 3.3 BCD 調整

> ### `[HARD]` 這四支的手冊版本是錯的，以語料為準
>
> SingleStepTests 是**硬體產生的**。它與 Intel 手冊衝突的兩處都已經
> 用整份語料（每支 10,000 筆）反推並驗證過，**各 0 筆不合**。

```
AAA: IF (AL & 0Fh) > 9 OR AF THEN
         AL = (AL + 6) & 0FFh          ; ★ 8 位元，**進位不進 AH**
         AH = (AH + 1) & 0FFh
         AF = 1; CF = 1
     ELSE AF = 0; CF = 0
     AL &= 0Fh
AAS: 同上但 AL -= 6、AH -= 1

DAA: old = AL; oldCF = CF; oldAF = AF
     IF (AL & 0Fh) > 9 OR oldAF THEN AL += 6; AF = 1 ELSE AF = 0
     IF high(old, oldCF, oldAF) THEN AL += 60h; CF = 1 ELSE CF = 0
DAS: 同 DAA 但用減法

high(old, oldCF, oldAF) =
     oldCF  OR  old > 9Fh  OR  (old > 99h AND NOT oldAF)      ; ★
```

**★ 兩處與手冊不同：**

1. **`AX += 106h` 是錯的。** `AL + 6` 溢位時進位**不會**跑進 `AH`；
   照手冊寫會在 `AL ≥ FAh` 時讓 `AH` 多加一次。
   語料：`37.json.gz`／`3F.json.gz` 各 10,000 筆。
2. **第二段的條件不是 `old_AL > 99h OR old_CF`。** 實機在
   `old_AL` 落在 **9Ah–9Fh 而且進來時 `AF` 已經是 1** 的那六個值上
   **不做**第二段調整。這是從 `27.json.gz`／`2F.json.gz` 各 10,000 筆
   反推出來的（先按 `(old_AL, old_CF)` 分群找出六組互相矛盾的，
   再看 `AF` 把它們分開），兩檔套上這條規則之後各 0 筆不合。

`AAM`／`AAD` 的 `CF`／`AF`／`OF` 在語料裡被遮掉（`flags-mask` ＝ `F7EE`），
所以實作清成 0 是**我們挑的確定值**，不是實機保證——要在註解裡講明白。

**`AAM` 的除數是 0 時**：`AX` 完全不動，但旗標照「結果 0」設一次
（`ZF=1 PF=1 SF=0 CF=0 AF=0 OF=0`、`DF` 保留）**才進 `INT 0`**。
那個值會被推上堆疊，所以不是無關緊要的細節——`D4.json.gz` 裡 47 筆
`aam 0h` 的記憶體比對會抓到。

## 3.4 除法的旗標：`DIV` 已解、`IDIV` 未解

手冊說除法的旗標「全部未定義」，SingleStepTests 也把它們遮掉——
**但溢位那條路會把旗標推上堆疊**（`INT 0`），而堆疊是逐位元組比對的。
所以「未定義」在這裡不等於「隨便」。

### `DIV`（已解，confirmed）

```
旗標 ＝ 內部第一次比較「被除數高半部 − 除數」留下來的
       位元組：sub8(AH, 除數)      字組：sub16(DX, 除數)
```

溢位就是這一次比較成立（高半部 ≥ 除數），所以迴圈一次都沒跑，
旗標停在那次比較上。`F6.6` 的 1,439 筆與 `F7.6` 的 1,372 筆暫存器型
溢位樣本**全中**，兩個檔全綠。

### `IDIV`（未解）

`IDIV` 先把被除數與除數取絕對值再跑無號除法迴圈，**溢位是在迴圈中途才
偵測到的**，旗標因此來自比較晚的一次內部減法。試過的模型與命中率
（`F6.7` 的 1,912 筆暫存器型溢位樣本）：

| 模型 | 命中 |
|---|---:|
| `sub8(AH, 除數)`（照 `DIV`）| 468／1912 |
| `sub8(\|AH\|, \|除數\|)` | 889／1912 |
| `sub8(\|AX\|>>8, \|除數\|)` | 1235／1912 |
| **重跑 CORD 迴圈、取最後一次比較** | **1602／1912（84%）** |

**方向對了**——CORD 迴圈的模型已經到 84%，差的是符號修正那一段
與溢位確切的偵測點。下一步是把 8086 的除法微碼完整寫出來。

現況：程式碼照 `DIV` 那條規則寫，`F6.7`／`F7.7` 兩個檔以
**`knownGaps` 的上限計數**盯著（6,218／10,000 與 6,371／10,000）。
**那不是「跳過」**：每一輪照跑照數，超過上限就紅，所以它擋得住退步。

> 數字大是正常的——`F6.7` 有 **75%** 的測資會觸發溢位。
> 這是「還沒實作」，不是「誤差」。

## 4. 五個 8086 專屬、後代機型沒有的行為

**這五條不照做，跑得動的程式會安靜地跑錯。**

1. **`PUSH SP` 推的是「已經減 2 之後」的 SP。** 286 以上推的是舊值。
2. **移位／旋轉的位移量不遮罩成 5 位元。** 8086 用整個 CL（0–255），
   所以 `SHL AX, CL` 在 CL=32 時會把值移光；286 以上是 `CL & 31`。
3. **除法例外（`INT 0`）推的返回位址指向下一道指令**，不是指令本身。
4. **`D0`–`D3` 的 `/6` 不是 `SHL` 的別名，是未公開的 `SETMO`**：把目的地
   整個設成 1（`D2`／`D3` 的版本 `SETMOC` 在 `CL` ＝ 0 時什麼都不做）。
   186 以上才把 `/6` 當成 `/4`。語料 `D0.6`–`D3.6` 四個檔的指令名就叫
   `setmo`；四個檔的 `flags-mask` 都是 `F72A`——**六個算術旗標全部被遮掉**，
   所以實作設的旗標是我們挑的確定值，不是實機保證。
5. **移位／旋轉的 `OF` 每一圈都重算**，不是只有「移 1 位」時才有定義。
   手冊說移多位時 `OF` 未定義，但實機的微碼每一圈都做同樣的事，
   **最後一圈的值勝出**。`D2.3`（`RCR` by `CL`）的 `flags-mask` 是
   **`FFFF`——一個位元都沒遮**，照手冊寫會整批紅。

其他要照抄的角落：

- 前綴可以疊，**最後一個生效**；`REP` 與段前綴同時出現時，
  **8086 的字串指令被中斷打斷後只會保留最後一個前綴**（本 MVP 不模擬
  中斷插入字串指令中間，所以不受影響，但不要「順手修正」成別的行為）。
- `0F` 在 8086 是 `POP CS`，不是雙位元組前綴。
- `D6` 是未公開的 `SALC`（`AL = CF ? 0xFF : 0x00`）。
- `82` 是 `80` 的別名；`F6 /1`、`F7 /1` 是 `/0`（TEST）的別名；
  `FF /7` 是 `/6` 的別名。
- 除以 0、或商溢位 → `INT 0`。
- `LOCK`（`F0`）與 `HLT`（`F4`）照收，不做事。

## 5. 驗收

```sh
tools/fetch_cputests.sh          # 抓 SingleStepTests/8088 v2 到 testdata/（gitignore）
tools/go.sh test ./internal/cpu -run TestSingleStep
```

判準：**323 個 opcode 檔全部通過**，每檔 10,000 筆。

比對規則：

1. 以 `initial` 建機器；`final` 只列**變動過的**欄位，所以預期值 ＝
   `initial` 疊上 `final`。
2. 比 8 個通用暫存器、4 個段暫存器、`IP`、`Flags`（遮掉 `flags-mask`）。
3. 比 `final.ram` 列出的每一個位址。**還要比 `initial.ram` 裡沒有出現在
   `final.ram` 的位址有沒有被亂改**——只比 final 會漏掉「多寫了一個位元組」。
4. **忽略** `queue` 與 `cycles`（本 MVP 不做匯流排週期）。
5. `status` 是 `undefined` 的 `/r` 變體照跑，只比暫存器與記憶體；
   `status` 是 `fpu` 的整檔跳過（`001` §3 第 2 點）。

> ### `[HARD]` 驗收判準是「全部通過」，不是「大部分通過」
>
> CPU 的錯不會報錯，只會讓上層在幾百萬個指令之後畫錯一個像素，
> 而那時候沒有任何線索指回這裡。**99.9% 通過等於沒通過。**
