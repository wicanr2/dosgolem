# 009 — EXEC（AH=4Bh）與程式鏈

狀態：**READY**（量測證據見 `008` §4 與本檔 §5）
日期：2026-09-06
前置：[`008`](008-tsr-resident.md)（行程疊與記憶體回收）

---

## 1. 範圍

- `int 21h AH=4Bh AL=00h`：load-and-execute。**只實作 AL=00h**；
  AL=01h（load only）與 AL=03h（overlay）記一筆不實作——
  殼鏈（Genpei.com）只用 AL=00h（`008` §4）。
- `int 21h AH=4Dh`：取子行程回傳碼。
- 監督佇列：第一支程式結束後由誰載入下一支（§4）。

## 2. AH=4Bh AL=00h 的語意

呼叫端：`DS:DX` → 檔名（NUL 結尾），`ES:BX` → 參數區塊：

| 位移 | 內容 |
|---|---|
| +0 | 環境區塊段（0 ＝ 繼承父行程的） |
| +2 | 命令列尾（PSP+80h 格式）的偏移 |
| +4 | 命令列尾的段 |

行為（對應真 DOS）：

1. 檔名照 `internal/dos/files.go` 的規則解析（basename、大小寫不分）；
   找不到 → `AX=2`、設 CF，**不動行程疊**。
2. 壓一格進程框進行程疊：父行程的全部暫存器、段、IP、FLAGS、PSP。
3. 子行程 PSP ＝ `freeSeg + 1`（`freeSeg` 那一格寫假 MCB，與
   `AH=48h` 的既有慣例一致）。記憶體需求 ＝ PSP（10h 段）＋ 映像段數；
   超過 `MemTop` → `AX=8`、設 CF、彈掉剛壓的框。
4. 子 PSP 照 `003` §3 填，外加：
   - PSP+16h ＝ 父行程 PSP；
   - PSP+2Ch ＝ 參數區塊給的環境段，0 則抄父行程 PSP+2Ch；
   - PSP+80h ＝ 參數區塊指的命令列尾（拷貝長度位元組＋內容，上限 126，
     補 CR）。參數區塊的命令列指標是 0:0 就給空尾（長度 0＋CR）。
5. 載入：檔頭是 `MZ` 就走 MZ 載入器（含重定位），否則當 .COM
   （與 `cmd/probe` 的既有分派一致——**副檔名不是判準**）。
6. CPU 切到子行程進入點：CS/IP/SS/SP 來自載入器，DS=ES=子 PSP，
   其餘暫存器歸零（真 DOS 不保證它們的值，歸零是決定性選擇；
   AX=0 表示「驅動器代號有效」）。
7. `freeSeg` 推到子行程映像之後。

**回傳**：父行程等到子行程結束（`AH=4Ch`／`AH=31h`／`int 20h`）才
繼續——在本實作裡就是「行程疊彈回」的那一刻。彈回時還原父行程的
完整上下文，然後清 CF（EXEC 成功）。父行程的 `AH=4Bh` 呼叫因此
「看起來」是一次很長的中斷。

⚠ 子行程繼承父行程開著的檔案 handle（真 DOS 如此）；我們的 handle
表是全域的，天然繼承，不用做事。

## 3. AH=4Dh：取回傳碼

- 回 `AX`：`AL` ＝ 最近一次子行程的離開碼（`AH=4Ch`／`AH=31h` 的 AL，
  `int 20h` 視為 0），`AH` ＝ 0（正常結束；不做 Ctrl-Break／嚴重錯誤
  的種類碼）。
- 可重複讀（不清掉）。殼是每次 EXEC 後讀一次（`008` §4），
  這個語意對它沒差別；選「不清」是因為清了會讓第二次讀到 0——
  一個看起來合理但假的值（`004` §1.3）。

## 4. 監督佇列（COMMAND.COM 的位置）

第一支程式（疊底）結束時行程疊是空的。真 DOS 此時回到 COMMAND.COM；
我們沒有 COMMAND.COM，所以由服務層提供一個**監督佇列**：

- `dos.Enqueue(name, args)` 排入一支待跑程式；
- 行程疊空了就 shift 出一支來跑（當新的疊底，PSP 從 `freeSeg` 起，
  命令列尾寫進它的 PSP+80h）；
- 佇列也空了才設 `Exited` 並停 CPU。

用途是啟動鏈的「DOSJP 常駐 → 再跑 Genpei.com」：DOSJP 用
`AH=31h` 常駐之後佇列推出 Genpei.com，記憶體自然落在 DOSJP 之上
（`008` §2.1）。

**沒有排佇列時行為完全不變**（一支程式跑完就停）——rich2 的
所有既有測試不受影響。

## 5. 量測證據

- Genpei.com：`AX=4B00h` ×4，參數區塊固定在 0574h（環境段 0 ＝
  繼承），目標依序 FMDRV.COM／GRPDRV.EXE／OPEN.EXE／MAIN.EXE／
  END.EXE；每次後 `AH=4Dh` 並與 2 比較。
  出處：`yuan/workplace/boot-20260906-01/genpei-com.dis`（6F9h–761h
  與 6ABh/6CFh 的 `mov ah,4Dh`）。
- 回傳碼慣例：MAIN.EXE 正常跑完回 2 才會接 END.EXE（殼裡的比較），
  這是**遊戲層的**慣例，機器層只負責把 `AH=4Ch` 的 AL 傳到
  `AH=4Dh` 的 AL。

## 6. 不做的事

- `AH=4Bh AL=01h/03h/05h` 不實作（記一筆）。
- 不做環境變數的內容（維持 `003` §4 未定案：空環境＋程式路徑）。
- 不做 `AH=26h`（建 PSP）、`AH=55h`（建子 PSP）。
