## 1. 為什麼要做

第二個案例（SSI《Pool of Radiance》）畫的是 EGA mode 0Dh：320×200、16 色、
**四個位元平面疊在同一段位址**。目前 `Machine.Indexed()` 寫死 mode 13h 的
「A0000 起 64000 bytes ＝ 320×200 的色號」，拿去對拍 Pool 只會得到一團
互相蓋掉的垃圾——**而且它看起來像一張正常的圖**，不像壞掉。

## 2. 量到什麼（`workplace/vgaprobe`，6000 萬道指令）

| 觀測 | 值 |
|---|---|
| 寫過的顯示相關埠 | **只有 `3C4` 與 `3C5`** |
| `3C4`（序列器索引）寫入次數 | 102，**每一次都是 `02`** |
| `3C5`（序列器資料）寫入次數 | 35334，值只有 `01`／`02`／`04`／`08`／`0F` |
| `3CE`／`3CF`（圖形控制器）| **一次都沒寫** |
| `3C0`／`3C2`／`3D4`／`3D5` | 一次都沒寫 |
| `int 10h AH=00`（設模式）| **一次都沒呼叫** |
| 實際呼叫的 `int 10h` | `AH=0Fh` ×2、`AH=11h` ×1、`AH=08h` ×1 |
| BDA 的視訊模式 | 從頭到尾 `03h` |
| `A0000..AFFFF` 的寫入 | 38464 次，**全部落在 `A0000..A1FFF`** |
| `A0000..AFFFF` 的讀取 | **0 次** |

### 2.1 這推翻了 findings/003 的一句話

`findings/003` 寫「遊戲是直接寫 `3C4`／`3C5` 設 EGA」。**不成立**：
`3C4` 只被設成索引 `02`（Map Mask），`3C5` 收到的只有
`01`／`02`／`04`／`08`／`0F` ——那是**逐平面選擇**，不是設模式。
設模式的碼一次都沒跑到（`START.EXE` 整支只有一個 `CD 10`，`GAME.OVR` 一個也沒有）。

**遊戲怎麼進到 mode 0Dh 的還沒解。** 這一份規格不處理那件事——
它只處理「已經在平面式模式裡的時候，寫入要怎麼落地」。

### 2.2 為什麼確定是平面式

`320 × 200 ÷ 8 = 8000` bytes，一個平面。寫入全部落在 `A0000..A1FFF`
（8192 bytes）而不是 mode 13h 的 64000 bytes；而 Map Mask 依序是
`01 02 04 08`——四個平面各寫一次同一段位址。目前沒有平面式 VRAM，
所以四次寫互相蓋掉，只有最後一個平面留下來。

### 2.3 讀取側不必做

`A0000..AFFFF` 被讀 **0 次**，而且圖形控制器（`3CE`／`3CF`）一次都沒設
——沒有 Read Map Select，也不可能用到寫入模式 1（latch 複製）。
**這是這一支程式的觀測，不是 EGA 的通則**：別的程式會讀。
所以讀取側先不做，但要留一個明說的缺口，不要讓它看起來像做完了。

## 3. 契約

1. `Machine` 多四個平面，每個 `0x10000` bytes，對應 `A0000..AFFFF`。
2. 寫入 `A0000..AFFFF` 時：**只寫 Map Mask 打開的平面**。
   Map Mask 是序列器索引 `02` 的低四位，位元 n 對應平面 n。
   重置值是 `0Fh`（四個都開），與 mode 13h 的線性寫入相容。
3. 同一次寫入**照舊也寫進 `Mem`**。mode 13h 的 `Indexed()` 因此完全不變，
   這一份規格不會動到第一個案例（`rich2`）的任何行為。
4. `IndexedEGA()` 把四個平面組成 320×200 的色號陣列：
   第 `y` 列第 `x` 行的色號是四個平面同一個位元的疊加，
   位元編號是 `7 - (x mod 8)`，平面 n 貢獻第 n 位。
   回傳複本。
5. `EGAPlanarActive()` 回報「Map Mask 曾被寫成不是 `0Fh` 的值」。
   **這是判斷用的訊號，不是模式暫存器**——真正的模式沒被設過（§2.1），
   所以沒有比它更硬的依據。呼叫端要自己決定信不信。
6. 序列器索引與 Map Mask 的目前值要看得到（`SequencerIndex()`／`MapMask()`），
   否則「畫面不對」時分不出是遮罩錯還是組裝錯。

## 4. 不做什麼

- 圖形控制器（`3CE`／`3CF`）：寫入模式、set/reset、bit mask、latch、
  Read Map Select 全部不做。這一支程式一個都沒用到。
- 屬性控制器（`3C0`）的 16 色調色盤：沒被寫過，色號→RGB 由呼叫端決定。
- CRTC（`3D4`／`3D5`）：捲動起點、分割畫面都不做。
- 模式設定本身（`int 10h AH=00` 走到 0Dh 時要不要改變定址）：
  **BDA 的模式位元組不參與判斷**，因為這支程式從來沒設過它。

## 5. 驗收

1. 單元測試：Map Mask `01`／`02`／`04`／`08` 各寫一次同一位址，
   `IndexedEGA()` 要組出對應的色號；Map Mask `0Fh` 時四個平面同值。
2. 單元測試：`Indexed()`（mode 13h）在同一串寫入之後**不變**。
3. 實測：跑 Pool 6000 萬道指令，`EGAPlanarActive()` 為真，
   `IndexedEGA()` 的非零像素數 > 0 且四個平面各自有內容。
