# 196 — MOO2 入口的 16 位元絕對位址比較

狀態：**CONFORMED**（僅通用 CPU 指令形狀；MOO2 入口判讀已撤回）
日期：2026-09-30

固定 MOO2 1.31 `ORION2.EXE` SHA-256 `4e11be14217b4aafa1839f333bf5eba037f98b0c44e9e4752c96c464c260419f`；`LoadLEAt(0x292E4)` 的重定位線性入口 `0x10FF18`，原始指令 bytes `66 3B 15 96 19 02 00`。`66` 指定 16 位元運算，`3B /r` 以暫存器為左運算元；`modrm=15h` 指向 `DS:[0x21996]`，目標暫存器為 `DX`。目前 CPU 在第 0 步以「word CMP 僅支援暫存器」失敗。位址 `0x10FF18` 是 dosgolem 重定位 LE 線性位址，`0x292E4` 是原檔偏移。

新增的形狀只接受無其他前綴的 `66 3B /r`、`mod=00, rm=101`；解出 disp32，從 DS descriptor 讀 word，呼叫既有 `sub16` 更新減法旗標，不修改暫存器與記憶體。讀取越界失敗即關閉；其他尚未支援形狀仍拒絕。這是公開 x86 指令語意，不把它當 MOO2 玩法 RE。

驗收包含小於、等於、大於與 descriptor 越界四種合成邊界；固定 MOO2 原檔自然越過第一道指令，並記錄下一個 stop。此切片的完成不表示啟動、畫面或玩法對拍完成。

驗收結果：`go test ./internal/cpu386` 通過；MOO2 原版自然越過首指令並執行至第 5,359 步。`0x10FF18..0x10FF30` 是逐次增加 EDX 的 8 個站點迴圈；到 `0x10FF43` 的 `POP EDX` 時，ESP 仍是 object 2 頂端 `0x1CDCD0`，讀取失敗。前一段 bytes 為 `5A 5B C3`，顯示此路徑會返回外層執行脈絡；缺少的呼叫／堆疊啟動契約尚未證實，不在本 CPU 指令規格內。

## 2026-09-30 勘誤

上述 `66 3B 15` 及 5,359 步來自以原檔零點錯誤載入的資料頁，不是 MOO2 原版 LE 入口。通用 x86 指令的合成測試仍有效；MOO2 真正入口為 `EB 76 WATCOM`，載入契約及第 11 步的新停點見 [197](197-bound-mz-le-file-base.md)。先前的堆疊脈絡假說已被資料頁基址反例推翻。
