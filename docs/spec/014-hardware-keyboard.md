# 014：硬體鍵盤（IRQ1 ＋ 埠 0x60）

狀態：`READY`

## 1. 契約

- `Machine.PushKey(scan)` 把一次**按下 ＋ 放開**排進硬體佇列。
- 每道指令檢查一次：佇列非空、`IF` 打開、且距上一次中斷已隔
  `KeyIRQEvery` 道指令時，把掃描碼鎖進埠 `0x60` 並送 `int 09h`。
  放開事件的掃描碼是 `scan | 0x80`。
- 埠 `0x60` 讀回鎖住的掃描碼；`0x61` 讀得回自己寫進去的值；
  `0x64` 的 bit0 反映佇列還有沒有東西。
- 中斷關著（`CLI`）時**擺著不丟**。初始化期間 `CLI` 很長，丟掉就等於沒按。

`[HARD]`：按下與放開都要送。只送按下的話，會等放開的程式停在那裡，
而只看按下的程式毫無影響——症狀因程式而異，而且都不像鍵盤的問題。

## 2. 為什麼 `int 16h` 不夠

BIOS 的 `int 16h` 不是唯一的鍵盤入口。遊戲常常自己裝 IRQ1 處理常式、
直接從埠 `0x60` 讀掃描碼。這種程式在只有 `int 16h` 的執行器上**不會報錯**：
它照樣輪詢、照樣播動畫、照樣等，只是永遠等不到鍵。

智冠《三國演義》的主選單就是這樣。它的 ISR（執行期 `0B01:0108`）：

```
in   al,0x60          ; 掃描碼
test al,0x80
jne  結束             ; 放開鍵不理
mov  es:[0004],al     ; 0000:0004 ← 掃描碼
mov  es:[0005],1      ; 0000:0005 ← 「有鍵」旗標
in   al,0x61 / or 80h / out 0x61,al / and 7Fh / out 0x61,al   ; 鍵盤 ack
mov  al,0x20 / out 0x20,al                                     ; EOI
iret
```

它把掃描碼存在 `0000:0004`——那是 `INT 1` 的向量槽，被拿來當暫存區。

**同一支程式也呼叫 `int 16h AH=01`（`_bios_keybrd(1)`）六十七萬次。**
所以「BIOS 鍵盤有被呼叫」不能拿來證明鍵是從 BIOS 進去的。
只看服務統計會得到「它在用 BIOS 讀鍵，但一次都沒讀走」這個
自洽而錯誤的結論。

沒有硬體鍵盤時 `in al,0x60` 回 `0xFF`，而 `0xFF` 的 bit7 是「放開」，
所以 ISR（就算被呼叫）也會把每一次都當成放開而忽略。**兩層安靜。**

## 3. 兩條路都要餵

餵鍵的一方要同時送字元佇列與掃描碼：哪一條才對是程式決定的，
而它不會說。`cmd/probe` 的 `-keys`／`-keys-at` 兩條一起送。

副作用要知道：字元佇列的頭被一個程式不要的鍵卡住時，**後面的鍵全部進不去**
（`int 16h AH=01` 只看不取）。這與真機一致——BIOS 緩衝區也是這樣——
但拿它餵測試腳本時，多送的鍵會擋住後面的。

## 4. 驗收

`AA.EXE` 在主選單按 `1`（掃描碼 `0x02`）之後，畫面從「主選擇單」
換成「選擇年代」六個劇本（中平六年／興平二年／建安六年／建安十三年／
建安二十年／黃初元年）。

## 5. 這一版沒做的

- 擴充鍵（方向鍵、功能鍵）的 `E0` 前綴。掃描碼表只收得下 `ScanCode` 列的鍵。
- 修飾鍵狀態（Shift／Ctrl／Alt）與 BDA `0040:0017` 的旗標位元組。
- 8042 控制器的命令埠 `0x64` 寫入（重置、A20、鍵盤禁用）。
- PIC 的 in-service／mask 暫存器：`out 0x20,0x20` 的 EOI 收下但不記狀態。
