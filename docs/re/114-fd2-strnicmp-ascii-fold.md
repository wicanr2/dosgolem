# RE 114 — `strnicmp` 的 ASCII 大寫折疊

日期：2026-09-06  
證據等級：**已證實**（指令形狀、資料流與 caller）；IDA 的 `strnicmp` 名稱僅作導覽

## 輸入與工具

- `FD2.EXE`：大小 `357074`；MD5
  `b97caf2239a27a896069d03549d96e1e`；SHA-256
  `222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`。
- IDA Pro 9.4.0.260610，映像 `ida-pro-9.4-idapython:locked-v1`。
- 本文位址均為 IDA 線性位址；保留原始函式邊界 `0x46BFF..0x46C4C`。

## 原始控制流

- `0x46C03..0x46C09` 分別由 stack 載入兩個字串指標與長度。
- `0x46C14 8A 0A`、`0x46C16 8A 28` 讀取目前兩個字元至 CL／CH。
- `0x46C18..0x46C20` 以 `41h`、`5Ah` 篩選 CL 的 ASCII 大寫範圍；命中時
  `0x46C22 80 C1 20` 執行 `add cl,20h`。
- `0x46C25..0x46C2D` 對 CH 做相同篩選；命中時 `0x46C2F 80 C5 20` 執行
  `add ch,20h`。
- `0x46C32 38 E9` 比較折疊後的 CL／CH；不同時由 `0x46C36..0x46C3C`
  形成差值，相同時則於 `0x46C40` 檢查 NUL，否則遞減長度並前進兩個指標。
- caller `0x3F451..0x3F459` 傳入長度 7、`"DRIVER"` 與目前 INI key；固定
  雜湊 FD2 自然執行已抵達 `0x46C22`。

因此 `0x46C22` 是有界、不分 ASCII 大小寫字串比較中的第一個大寫轉小寫
步驟；其 CPU 必要形狀為無前綴 `80 /0`、`mod=3` 的 byte register immediate ADD。
這不證明其他語系的大小寫規則，也不授權一般化其他 `80 /0` 記憶體形狀。
