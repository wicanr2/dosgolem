# 記憶體：傳統、EMS、XMS、VCPI

四種記憶體介面在 DOS 上並存，程式會**依序偵測**再挑一種用。缺一種的症狀
多半不是報錯，而是程式改走另一條路（於是行為與原版不同），或是判定
「記憶體不夠」然後安靜地少載一些東西。

## 傳統記憶體（`int 21h AH=48h`／`49h`／`4Ah`）

dosgolem 有完整的 arena 配置器：first fit、釋放合併、MCB 鏈同步到客體記憶體
（程式會自己走鏈算「我構得到多少段」）。

| 缺 | 影響 | 優先序 |
|---|---|---|
| UMB（`AH=58h` 的配置策略與 UMB 連結） | 想把 TSR 載進上位記憶體的程式；沒有 UMB 就全部落在傳統區 | P2 |
| `AH=58h` 的策略（first／best／last fit） | 只影響配到哪一塊，不影響成功與否 | P2 |

DOSBox-X 對照：`src/dos/dos_memory.cpp`，MCB 的形狀與我們一致
（`M`／`Z` 簽章、owner PSP、段數）。

## EMS（`int 67h`，LIM EMS 4.0）

dosgolem 有 `40h`／`41h`／`42h`／`43h`／`44h`／`45h`／`46h`／`47h`／`48h`／
`4Bh`／`4Ch`／`58h`，512 頁、四個實體頁、page frame 在 `D000h`。

| 缺 | 服務 | 誰會踩到 | 優先序 |
|---:|---|---|---|
| `4Eh`／`4Fh` | 取／設分頁對映（整份、部分） | 中斷處理常式借用 page frame 的另一種慣用法（比 `47h`／`48h` 新） | P2 |
| `50h`／`51h` | 一次映射多頁／改變 handle 頁數 | EMS 4.0 的程式 | P2 |
| `53h`／`54h` | handle 命名／取得清單 | 診斷用 | P3 |
| `5Ah` | 配置 raw pages | | P3 |
| `DEh` | **VCPI** | 只有要走「跑真的 extender」那條路才需要，見 `030` | 未定 |

⚠ **錯誤碼 87h／88h 的分界要對**：87h 是「要的比整台機器有的還多」，
88h 是「機器有但現在不夠」。回同一個碼的話，程式的「降級成較小的配置」
那條路走不到（它只在 88h 時重試）。dosgolem 目前把「要 0 頁」也回 87h，
**與 LIM 手冊的 89h 不符**，標為假說待驗（`internal/dos/ems.go` 的註解）。

## XMS（`int 2Fh AX=4300h` 偵測 ＋ far call 進入點，XMS 3.0）

dosgolem 有 `00h`（版本）、`08h`（查可用）、`09h`（配置 EMB）、`0Ah`（釋放）、
`0Bh`（搬移）。

| 缺 | 服務 | 誰會踩到 | 優先序 |
|---:|---|---|---|
| `01h`／`02h`／`03h` | 取得／釋放 HMA、開關 A20 | 想用 HMA 的程式；沒有 HMA 就退回傳統記憶體 | P2 |
| `05h`／`06h` | 本地開關 A20 | 同上 | P2 |
| `0Ch`／`0Dh` | 鎖定／解鎖 EMB（取線性位址） | 要 DMA 的程式（音效卡） | P2 |
| `0Eh`／`0Fh` | 取 handle 資訊／改變大小 | | P3 |
| `10h`–`12h` | UMB 配置 | 與傳統記憶體的 UMB 是同一件事 | P2 |

DOSBox-X 對照：`src/ints/xms.cpp:494` 的 `XMS_Handler()`，偵測走
`multiplex_xms()`（`:395`）。

## 偵測順序（程式那一側）

這一段決定「缺哪一個會改變行為」：典型的 DOS 程式啟動時依序問

1. **XMS**：`int 2Fh AX=4300h` → 回 `AL=80h` 就拿 far call 進入點；
2. **EMS**：開 `EMMXXXX0` 或比對 `int 67h` 向量段的簽章；
3. **VCPI**：`int 67h AX=DE00h`（只有 extender 與 DPMI 主機會問）；
4. 都沒有就只用傳統記憶體。

⚠ **偵測回「有」之後就要真的能用。** 回 `AL=80h` 卻沒實作 `09h`（配置），
程式會在配置失敗時走「記憶體不足」那條路——而那條路多半是**少載素材**
或**降低音質**，不是報錯。從外面看是「畫面少了東西」。
