# 保護模式與 DOS/4GW：兩條路線

DOS/4GW（與 CauseWay、PMODE/W、DOS32A 這一類 extender）把程式跑在 32 位元
保護模式，DOS 服務靠 extender 轉譯回實模式。要讓這種程式在 dosgolem 上被觀測，
路線只有兩條，而它們的成本差一個量級。

## 路線 A：跑真的 extender（DOSBox-X 走的路）

DOSBox-X **沒有實作 DPMI 主機**——原始碼裡沒有任何 `int 31h` 的處理常式。
它做的是把底下鋪好，讓真的 extender 自己跑起來：

| 元件 | DOSBox-X 的位置 | 用途 |
|---|---|---|
| 386 保護模式 CPU（描述子、分頁、例外、V86） | `src/cpu/`（`cpu.cpp`、`paging.cpp`、四種核心） | extender 切模式之後的每一道指令 |
| VCPI（`int 67h AH=DEh`） | `src/ints/ems.cpp:1164` | EMM386 存在時，extender 靠它進保護模式 |
| XMS | `src/ints/xms.cpp:494` | 延伸記憶體 |
| `int 15h AH=87h/88h/89h` | `src/ints/bios.cpp:7080` 起 | XMS 之前的搬移與模式切換 |
| CWSDPMI（真的執行檔，內建一份） | `src/builtin/cwsdpmi_exe.cpp` | 需要 DPMI 主機時直接跑真的那一支 |

**代價**：要一顆會分頁、會丟例外、能在 V86 與保護模式之間切換的 CPU。
**回報**：之後每一支 extender 程式都不必再做事——連 extender 的版本差異
都自動涵蓋。

## 路線 B：跳過 extender，直接跑 LE 映像（dosgolem 現在走的路）

`internal/machine/le.go` 解析 MZ 外殼裡的 LE，`internal/cpu386` 直接跑
32 位元程式碼，`FD2StartupDOS`（`internal/machine/le_startup.go`）冒充
extender 提供的服務。

**代價**：extender 的行為要自己冒充，而**冒充的部分目前綁死在一支程式上**：

- `FD2StartupDOS.Handle` 用 `s.calls` 計數器當狀態機：第 0 次 `int 21h`
  必須是 `AH=30h` 且 `EBX='PHAR'`，否則整條路不成立。
- selector 值寫死（`0x0160`／`0x0028`／`0x0020`／`0x0030`），
  `SegmentLoadOK` 是一個 per-program 的白名單閉包，不是描述子表。
- 檔案服務（open／read／seek／IOCTL）在 `le_startup.go` **又實作了一次**，
  與 `internal/dos` 那一份平行存在；兩份的錯誤碼與 handle 配置各走各的。
- DPMI 只有 `AX=0200h`（取實模式中斷向量）一支。

**回報**：不必寫保護模式 CPU 的分頁與例外，也不必跑 extender 那幾萬道
初始化指令——`FD2.EXE` 從 LE entry 直接進 `main` 只要 1094 步。

## 換第二支 DOS/4GW 程式的成本

這是判斷「要不要擴充 MVP」的關鍵數字。路線 B 目前的三樣東西都要重來：

1. **啟動握手**：`calls` 狀態機與 `PHAR` 判斷是 FD2 的形狀，別支不會一樣。
2. **selector 配置**：寫死的四個值換一支程式就不同。
3. **DOS 服務**：`le_startup.go` 只有五支函式（`3Dh`／`3Fh`／`42h`／`44h`／
   `35h`／`25h`）；別支要的那些得再補一輪，而且補在**第二份實作**上。

386 指令面倒是可以累積：`internal/cpu386` 是通用的解碼器，
177 份 `docs/spec/0NN-cpu386-*` 是逐指令的收據。**指令面會攤提，服務面不會。**

## 建議：路線 B ＋ 三件一般化（不做路線 A）

dosgolem 的定位是「無頭、決定性、可程式化觀測的執行器」，不是通用模擬器。
為了跑 extender 的初始化而實作分頁與例外，成本落在**與觀測目標無關**的地方。
但現在這種「一支程式一組 shim」的作法在第二支程式就會複製一次全部。

建議把保護模式那一半一般化成三塊，每一塊都與程式無關：

| # | 要做的事 | 為什麼 | 規模（估） |
|---:|---|---|---|
| 1 | **DOS 服務只留一份**：`internal/dos` 支援 32 位元呼叫慣例（暫存器寬度、平坦位址），`le_startup.go` 那五支刪掉改為轉呼 | 兩份實作的錯誤碼、handle 配置、診斷紀錄各走各的，差異只有在對拍時才會顯現 | 中：介面改動 ＋ 既有測試 |
| 2 | **描述子表當一等公民**：把 `SegmentLoadOK`／`SegmentRead8` 這類 per-program 閉包換成真的 GDT／LDT 模型（selector → base/limit/權限），LE 載入器自己填平坦描述子 | 換程式不必改碼；`docs/spec/014-dos4gw-flat-descriptors` 已經有規格 | 中 |
| 3 | **DPMI 通用子集**：`int 31h` 的 `0000`／`0001`（配置／釋放描述子）、`0006`／`0007`（取／設 base）、`0008`（設 limit）、`0200`／`0201`（實模式向量）、`0300`（模擬實模式中斷）、`0501`／`0502`（配置／釋放線性記憶體）、`0600`（鎖定）、`0900`／`0901`（IF） | 這是 extender 對客戶端的公開契約，**與哪一支程式無關**；DOSBox-X 沒得抄，契約來源是 DPMI 1.0 規格 | 中大 |

做完之後接第二支 DOS/4GW 程式的成本，從「重做一組 shim」降到
「補它用到的 DPMI 功能與 386 指令」——而那兩樣都會攤提到第三支。

## 已經做到哪裡（2026-09-07）

第 1 塊做了一半、第 3 塊做完了大部分，第 2 塊沒動（見
`docs/spec/184-mvp-scope-review` 的批次表）。

**`int 31h` 目前實作的**：`0000`／`0001`（描述子）、`0003`（selector 間隔）、
`0006`–`000A`（base／limit／權限／別名）、`0100`／`0101`／`0102`（DOS 記憶體）、
`0200`／`0201`／`0204`／`0205`（實模式與保護模式向量）、`0400`（版本）、
`0501`／`0502`（線性記憶體）、`0600`／`0601`（鎖定）、`0900`–`0902`（IF）。

**沒做的**：`0300`（模擬實模式中斷）、分頁與例外。`0300` 要一份 50 byte 的
暫存器結構加上一條「誰來服務這個中斷」的路；**等有程式踩到再開規格**，
踩到的時候 `Unimplemented[0x0300]` 會留下痕跡，不會安靜地走錯路。

### 位址空間切成兩半

`AX=0100h`（DOS 記憶體）必須同時給得出**實模式段號**，而段號只有 16 位元，
所以那塊記憶體一定要落在 1 MB 之內。因此位址空間以 1 MB 為界：

| 區間 | 誰在用 | 游標 |
|---|---|---|
| 映像尾端 – 1 MB | `AX=0100h` 的 DOS 記憶體 | `dosBrk` |
| 1 MB 以上 | `AX=0501h` 的線性記憶體 | `brk` |

兩個游標分開是必要的。合成一個的話，程式先配一大塊線性記憶體再要 DOS
記憶體，拿到的位址會超過 1 MB——**段號截斷之後指到映像頭上**，
寫下去就把自己的碼改了，而症狀是「跑一跑跳進亂碼」。

## 契約來源

- **DPMI 1.0 規格**（Intel／Microsoft 等，1991）：`int 31h` 的功能號與回傳約定。
- **LE／LX 格式**：IBM OS/2 的 Linear Executable 文件；dosgolem 的解析在
  `internal/machine/le.go`，欄位名照原文。
- **VCPI 1.0**：只有走路線 A 才需要。
- DOSBox-X 在保護模式這一段**只能當「底下要鋪什麼」的參考**，
  不能當 DPMI 的契約來源——它根本沒有那一層。
