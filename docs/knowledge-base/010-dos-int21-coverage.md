# `int 21h` 涵蓋表

對照基準：DOSBox-X `src/dos/dos.cpp` 的 `DOS_21Handler()`（commit `5fcf624`）
實作 `AH=00h`–`6Fh` 加 `71h`／`73h`，共 114 個子功能；dosgolem 目前 46 個。

數量差不代表能力差：DOSBox-X 是通用模擬器，要跑得動 1981 年以來的所有東西，
FCB 那一整批（`0Fh`–`28h`）在 1990 年代的 C 程式裡幾乎不出現。下面把缺的
68 項按「會不會擋住程式」分級，而不是按號碼順序。

## 批次 2a：P2 那一批已經補上（2026-09-07）

實作在 `internal/dos/dosinfo.go`，契約測試在 `internal/dos/dosinfo_contract_test.go`。

| AH | 服務 | 做法與明確的取捨 |
|---:|---|---|
| `0Ch` | 清輸入緩衝再讀 | 清 BDA 環與 `DOS.Keys`，**不清 `DOS.Stdin`**（見下） |
| `32h` | 取 DPB | 回 `AL=FFh`（無效磁碟機）並記一筆，**不偽造 DPB** |
| `34h` | 取 InDOS 旗標 | 指到 `StubSeg:0450`，值恆為 0 |
| `37h` | 取／設 switch 字元 | 預設 `/`；`AL=02h`／`03h` 的裝置可用性照 DOS 5 回 0 |
| `58h` | 配置策略／UMB 連結 | first／best／last fit **都真的實作**；UMB 連結只記狀態並記一筆 |
| `5Ah` | 建暫存檔 | 流水號命名（`TMP00000`…），檔名接回呼叫端緩衝區 |
| `5Ch` | 鎖定／解鎖區段 | 單行程，一定拿得到；但 handle 不對要失敗 |
| `60h` | 正規化路徑 | 大寫、吃掉 `.`／`..`、退過根目錄停在根目錄 |
| `6Ch` | 延伸開檔 | `CX` 回報實際做了哪一件（1 開啟／2 建立／3 覆寫） |

三個要記下來的判斷：

- **`AH=0Ch` 不清 `Stdin`。** BDA 環與 `Keys` 是模擬的鍵盤，清掉對得起語意；
  `Stdin` 是回放管道（probe 的 `-keys`、oracle 的 `SendKeys`），裝的是
  「這一輪要餵的整串輸入」。跟著清的話，程式呼叫一次就把後面所有按鍵吃光，
  而回放會停在一個看起來像「程式自己不動了」的地方。這是與真 DOS 的明確差異。
- **`AH=32h` 不偽造 DPB。** DPB 裡是 FAT 起始磁區、每叢集磁區數、裝置驅動程式的
  far 指標——程式會沿著那個指標走進「驅動程式」，或照那些數字自己算磁區位置。
  **編得越像，它走得越遠才炸。** 回 `FFh` 讓它就地放棄，錯誤停在問的地方。
- **`AH=58h` 的策略要真的生效。** 策略決定程式拿到哪一段，而段位址是它看得到的
  （寫進自己的資料結構、比大小、算距離）。只記不用等於在 `AL=00h` 回報一件
  沒有發生的事。

順帶修掉一個位址重疊：`int 15h AH=C0h` 的系統設定表原本放在 `StubSeg:0500`，
而 `StubSeg`（0x0080）與 `EnvSeg`（0x00D0）只差 0x50 段——**位移 0x500 就是
`EnvSeg:0000`**，寫下去會把 `COMSPEC=` 的前 8 個 byte 蓋掉，而程式讀自己的
環境只會看到亂碼，不會有任何錯誤。現在表在 `StubSeg:0440`，
`TestInt15SystemConfigTableIsSafe` 改成前後比對兩個鄰居的內容，
不再只檢查位址落在哪一段。

## 缺口 P3：FCB 時代，1990 年代的 C 程式幾乎不用

`0Fh`–`18h`、`21h`–`24h`、`26h`–`28h`（FCB 開關讀寫、循序／隨機存取、
建立 PSP）、`1Dh`–`1Eh`（未文件）、`03h`／`04h`／`05h`（AUX／PRN）、
`50h`（設 PSP，我們有 `51h` 取）、`53h`／`54h`／`55h`（BPB 轉換、verify 旗標、
建立 PSP）、`5Dh`–`5Fh`（伺服器／網路重導向）、`61h`／`64h`–`66h`／`69h`／`6Bh`
（保留、未文件、代碼頁）。

**要做的判準是「有程式踩到」**，不是「表上有洞」。缺這些的症狀通常是
`Unimplemented` 統計裡出現一筆——那是有訊號的，不是安靜的失敗。

## 實作時的注意事項（從 DOSBox-X 讀出來的）

- **`59h` 的錯誤碼要與前一次失敗一致。** DOSBox-X 用 `dos.errorcode`
  在每一次失敗時設值（`src/dos/dos.cpp:348` 的 `DOS_SetError`）。分開記兩份的話，
  程式問到的原因與實際失敗的原因會對不上。
- **`45h`／`46h` 複製出來的 handle 要共用檔案指標。** DOSBox-X 的
  `DOS_DuplicateEntry`（`src/dos/dos_files.cpp:1509`）讓兩個 JFT 項指向同一個 `DOS_File`；各自一份的話，
  程式對複本 seek 之後從本尊讀，位置是舊的。
- **`4Eh`／`4Fh` 的狀態存在 DTA 裡，不是存在 DOS 裡。** 程式會在兩次呼叫
  之間換 DTA（`1Ah`）來同時跑兩個搜尋；狀態放服務層的話第二個搜尋會把
  第一個的進度洗掉。DOSBox-X 把搜尋狀態編碼進 DTA 的前 21 bytes
  （`DOS_DTA::SetDirID`／`GetDirID`，用處見 `src/dos/drive_local.cpp:1795`、`:1847`）。
