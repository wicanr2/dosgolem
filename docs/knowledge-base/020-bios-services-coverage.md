# BIOS 服務涵蓋表（`int 10h`／`13h`／`15h`／`16h`／`1Ah`／`33h`）

對照基準：DOSBox-X commit `5fcf624`。每一節列「dosgolem 有什麼、缺什麼、
缺的那些誰會踩到」。

## `int 10h`（視訊）

DOSBox-X 的 `INT10_Handler()`（`src/ints/int10.cpp:64`）分派 60 幾個 AH，
含 VESA（`AH=4Fh`，`int10_vesa.cpp`）與 PC-98 的分支。

**dosgolem 有**：`00h` 設模式、`02h`／`03h`（游標位置，收下）、`05h` 選頁、
`06h`／`09h`／`0Ah`（捲動與寫字元，收下）、`0Eh` TTY 輸出、`0Fh` 取模式、
`10h` 調色盤（含 DAC 區塊寫入）、`11h` 取字型指標、`12h` EGA/VGA 替代選擇、
`1Ah` 顯示卡組合碼、`1Bh` 功能／狀態資訊表。

| 缺 | 服務 | 誰會踩到 | 優先序 |
|---:|---|---|---|
| `0Ch`／`0Dh` | 寫／讀單一像素 | 少數程式用 BIOS 畫點（慢，但存在）；缺了畫面整片不出現 | P2 |
| `13h` | 寫字串 | 文字模式的訊息輸出 | P2 |
| `01h` | 設游標形狀 | 只影響外觀，我們沒有真的游標 | P3 |
| `08h` | 讀游標位置的字元與屬性 | 文字模式擷取畫面的程式 | P3 |
| `4Fh` | VESA | 640×480 以上的 SVGA 程式 | 未定：要有目標程式才開 |

⚠ **`00h` 之外的模式設定不一定走 BIOS。** EGA／VGA 程式直接寫
`3C0h`–`3CFh`／`3D4h` 就能換模式（`docs/spec/007-ega-mode-0dh-planar-vram` 的
Pool of Radiance 就是），所以 `VideoMode()` 停在 03h 不代表還在文字模式。
判斷畫面在哪要看埠寫入，不是看 BDA。

## `int 13h`（磁碟）

dosgolem 只讓 `AH=00h`／`01h`／`04h` 回成功，其餘回逾時（`AH=80h`）並記一筆。
DOSBox-X 有完整的磁碟 BIOS（`src/ints/bios_disk.cpp`）含真正的磁區讀寫。

**缺的是「真的讀磁區」**（`AH=02h`／`03h`）。踩到的是**自製防拷**：程式讀
一個刻意壞掉的磁區來驗光碟／磁片。目前回失敗是誠實的做法——回假成功會
讓程式拿沒填過的緩衝區當資料。要做的前提是先有磁碟映像的模型（我們現在
只有目錄，沒有磁區）。優先序：**未定**，要有目標程式。

## `int 15h`（系統服務）

dosgolem 只實作 `AH=50h AL=00h`（DOS/V 取字型指標），其餘記一筆。
DOSBox-X 的 `src/ints/bios.cpp` 實作了 `87h`（延伸記憶體區塊搬移）、
`88h`（取延伸記憶體大小）、`89h`（切換到保護模式）、`C0h`（取系統設定表）、
`86h`（等待）等。

| 缺 | 服務 | 誰會踩到 | 優先序 |
|---:|---|---|---|
| `88h` | 取延伸記憶體大小（KB） | XMS 之前的程式問記憶體；回 0 會被讀成「沒有延伸記憶體」 | P2 |
| `87h` | 延伸記憶體區塊搬移 | 同上，沒有 XMS 驅動時的搬運路徑 | P2 |
| `86h` | 等待 n 微秒 | 動畫節奏；我們是指令數模型，接了要決定換算 | P3 |
| `C0h` | 取系統設定表 | 判斷機型 | P3 |
| `89h` | 切換到保護模式 | 見 `030-protected-mode-and-dos4gw` | 未定 |

## `int 16h`（BIOS 鍵盤）

dosgolem 有 `00h`／`01h`／`02h`／`10h`／`11h`／`12h`／`13h`，走 BDA 環形緩衝
（`docs/knowledge-base/010` 的鍵盤那一節與 `internal/machine/bda.go`）。

| 缺 | 服務 | 備註 | 優先序 |
|---:|---|---|---|
| `05h` | 把一個鍵塞進緩衝區 | 巨集／自動輸入的程式自己塞鍵 | P2 |
| `03h` | 設 typematic 速率 | 收下即可 | P3 |
| `09h`／`0Ah` | 取支援的功能 | 少見 | P3 |

## `int 1Ah`（時刻）

dosgolem 有 `00h`（取 tick）、`01h`（設 tick）、`02h`／`04h`（RTC 時分秒／年月日，
回 CF 表示沒有 RTC）。缺 `05h`–`07h`（設 RTC 鬧鐘）與 `0Bh`——**沒有目標程式
踩過**，優先序 P3。

⚠ `02h`／`04h` 回 CF 是刻意的：編一組時間出來比較危險，程式可能拿它當亂數種子，
那會讓對拍變成不決定性的。

## `int 33h`（滑鼠）

dosgolem 有 `00h`–`08h`、`0Ch`（事件回呼）、`0Fh`（mickey/pixel 比例，收下）。
DOSBox-X 的 `INT33_Handler()`（`src/ints/mouse.cpp:1620`）另有游標圖形、
相對位移與靈敏度那一整組。

| 缺 | 服務 | 誰會踩到 | 優先序 |
|---:|---|---|---|
| `0Bh` | **讀相對位移（mickey 計數）** | 用相對位移轉視角／捲動的程式（第一人稱、地圖拖曳）；`03h` 的絕對座標對它們沒用 | **P1** |
| `09h`／`0Ah` | 設圖形／文字游標形狀 | 我們不畫游標，收下即可；但程式會**檢查回傳** | P2 |
| `10h` | 條件式隱藏游標 | 程式在畫面更新前呼叫，缺了不影響邏輯 | P2 |
| `1Ah`／`1Bh` | 設／取靈敏度 | 與 `0Fh` 同一組 | P2 |
| `24h` | 取驅動版本 | 偵測驅動能力 | P2 |

⚠ **`0Bh` 與我們的絕對定位模型有摩擦。** dosgolem 的滑鼠是絕對座標
（腳本說「點 (x,y)」），mickey 是相對量；目前 `MoveMouse` 已經把位移填進
事件回呼的 SI/DI（一個邏輯 pixel 當一個 mickey），`0Bh` 要用同一個來源，
**而且讀過要歸零**——那是它的定義（「自從上次呼叫以來移動了多少」）。
