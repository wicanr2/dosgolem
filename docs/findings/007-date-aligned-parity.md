# 007 — 把取樣點寫成遊戲日期，殘留的 110 點歸零

日期：2026-09-05
狀態：通過

---

## 1. 結果

載入原版存檔、用 `until:196/4/20` 把遊戲日期對齊到原版擷取的那一刻，
再開「據點」「人事」「軍團」三張彈出選單，對臥龍傳專案的原版擷取：

| 選單 | banner | command | map | minimap | faction |
|---|---:|---:|---:|---:|---:|
| 據點 | 0 | 0 | 0 | 0 | 0 |
| 人事 | 0 | 0 | 0 | 0 | 0 |
| 軍團 | 0 | 0 | 0 | 0 | 0 |

**十五個比較全部 0 px**，含大地圖底圖。選單框在 `map` 區內，
所以 `map` 0 px 就表示框、字與反白全部逐點相同。

## 2. 日期對齊值多少

同一組比對，只改對齊點：

| 對齊到 | `banner` |
|---|---:|
| 不對齊（載入即開，4月16日）| 110 px |
| `until:196/4/18` | 52 px |
| `until:196/4/19` | 55 px |
| **`until:196/4/20`** | **0 px** |

那 110 點是**橫幅上的日期數字**。臥龍傳專案的
`docs/playtest/60`／`61` 把它記成「原版 4月20日、remake 4月1日」的殘留，
一直留在那裡——因為 DOSBox 那條路只能用 `wait:N` 秒去逼近。

⭐ **即時制的取樣點寫成日期之後，這一項就不是殘留了，是可以歸零的。**

選單開著時遊戲時鐘停住（`until` 之後開選單，截圖時仍是 4月20日 19時），
所以「先跑到某一天再開選單」是可重現的。

## 3. 熱區圖把座標從「量的」變成「讀的」

指令列八格的位置不是量出來的，是從熱區圖讀的：

```
# 11  x   0..431  y  32.. 63   ← 指令列整條
# 12  x  24..407  y  40.. 55   ← 八個指令格
```

八格各 48 px、起點 24 ⇒ 進言 24、人事 72、財政 120、編成 168、
軍團 216、據點 264、武將 312、勢力 360。

⚠ **彈出選單一定要用 `Tap` 不能用 `Click`。** 長按會在選單開起來的那一瞬間
被下一次 `AX=5` 輪詢看到，用當時的游標位置立刻選走第一列
（`docs/spec/010` §2）。

## 4. 這一輪比的是什麼

三張選單走同一支繪製常式，位置與字數是各自的立即值。
**這一次是原版對原版**（dosgolem 跑的就是 `KI.EXE`），
所以 0 px 驗的是 dosgolem 這一層——VGA 平面模式、字型服務、熱區、輸入模型
與時鐘全部對得上，才有可能三張都零。
