# 008 — 彈出選單的選列是滾輪，不是熱區

日期：2026-09-05
狀態：已解，第二列第一次被選中

---

## 1. 症狀

「軍團」彈出選單有兩列：位置確認／行軍指示。把游標移到第二列的畫面座標
（y=95）再瞬按——**選到的永遠是第一列**。試過 y=79／88／95／100，
四個結果**逐像素相同**（0 px），所以不是差一點，是完全沒有作用。

臥龍傳專案那邊也一樣：`docs/playtest/60` 的未解表寫著
「位置確認／行軍指示選完之後的兩條流程**都沒有對拍**」——
**第二列從來沒有被選中過**，DOSBox 那條路也沒有。

## 2. 成因：`sub_10414` 是一個滾輪

```asm
loc_1044C:
    mov ax, 3 / call 滑鼠層            ; 取游標與鍵狀態
    test bx, 1 / jnz → 左鍵 → 回 al = [bp+0Eh]（選中的列）
    test bx, 2 / jnz → 右鍵 → stc（取消）
    cmp dx, 83h / ja  → 往下
    cmp dx, 64h / jae → 回 loc_1044C   ; 64h ≤ y ≤ 83h：留在原地
往上: 游標設回 y=83h ; 選擇往上一格 ; 回圈
往下: 游標設回 y=64h ; 選擇往下一格 ; 回圈
```

| 游標 y | 行為 |
|---|---|
| 100–131 | 什麼都不做 |
| **> 131** | **選擇下移一格**，游標被設回 131 |
| **< 100** | **選擇上移一格**，游標被設回 100 |

**帶的位置是寫死的，與選單畫在哪裡無關。** 選單框在 y 66–106，
所以「第二列的畫面座標」是 88–103——**整段都在 100 以下**，
於是迴圈把選擇往上推，永遠停在第 0 列。

⇒ 之前的作法**方向就是反的**，不是差幾個像素。

## 3. 作法

```
tap:240,47,10000     開選單（第 0 列反白）
move:240,200         y > 131 → 第 1 列反白
press                原地按下去 → 選中
```

驗證：按下之後狀態列出現 **TALK #2「請選擇進行行軍指示之軍團。」**，
與臥龍傳專案 `docs/re/22` §3.3 記的 `al = 1 → 行軍指示：sub_18853(cx=2)` 對上。
（第 0 列是 TALK #22「將游標移動至軍團的現在位置。」）

## 4. 為什麼是 dosgolem 才問得出來

三件事缺一不可，而且都不是「看畫面」看得到的：

1. **攔 `sub_1E453`**：確認點擊有被看到、位置卻是 (0,0)——
   排除掉「座標算錯幾個像素」這個方向。
2. **讀 `int 33h AX=7`／`AX=8` 的範圍**：發現大地圖的範圍是 6144×4128，
   於是知道滑鼠座標是世界座標。
3. **讀熱區圖**：確認彈出選單**沒有登記任何熱區**——所以它一定不是用
   熱區選列的，剩下的就只有「從游標算」，而那條路在機器碼裡只有一段。
