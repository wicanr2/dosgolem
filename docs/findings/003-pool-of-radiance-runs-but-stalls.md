# 003 — 《Pool of Radiance》跑得動，但停在一個兩道指令的迴圈裡

日期：2026-09-05
狀態：量測結果，還沒動手修

## 一句話

第二個案例（SSI《Pool of Radiance》DOS 版）的 `START.EXE` **載得進來、跑得動**
——500 萬道指令沒有崩、沒有非法指令——但它停在一個兩道指令的自旋迴圈裡，
還沒設圖形模式、也還沒開任何檔案。

## 為什麼值得記

它證明了 CPU 那一層**不是只跑得動 MS BASIC**：Pool 是 Borland Turbo Pascal
編出來的，帶 `TPOV` overlay 容器與 `INT 3Fh` overlay 管理器，指令組合與
`RUN_full.EXE` 完全不同族。跑到自旋迴圈代表**卡住的是系統服務或中斷遞送，
不是指令解碼**——那是可以逐項排除的。

## 量到什麼

```
DOSGOLEM_ORIG=<Pool 的 DOS 目錄> tools/go.sh run ./cmd/probe \
    -exe /orig/start.exe -root /orig -steps 5000000 -trace 40
```

| 項目 | 值 |
|---|---|
| 停止原因 | 跑滿上限，程式還活著 |
| CS:IP | `0622:0071` ↔ `0622:0074` 兩道指令來回，AX 一直是 0、SP 不動 |
| 視訊模式 | `03h`（文字），從來沒設過圖形模式 |
| 開過的檔 | 0 |
| 沒實作的服務 | 只有 `int 10h AH=08`（讀游標處的字元與屬性），呼叫 1 次 |
| 滑鼠輪詢 | 0 次 |
| 寫過的 I/O 埠 | 0 |

## 下一步（依懷疑程度排序）

1. **IRQ0 有沒有真的送進程式自己掛的處理常式。** 迴圈只有兩道指令、不碰
   I/O、不呼叫服務，最像「等一個由中斷處理常式改的旗標」。`machine` 有 PIT
   與 `irq0Pending`，要確認的是**遞送**那一段在 `IF` 與 PIC 遮罩下成不成立。
2. **`int 10h AH=08` 的回傳值**。目前完全沒實作，回去的是垃圾。真機上它回
   游標位置的字元與屬性；Turbo Pascal 的 CRT 單元會用它。它只被呼叫一次，
   所以不太可能是自旋的原因，但要補。
3. **`int 1Ah` 整支沒有**（BIOS 時鐘）。目前沒被呼叫到，補之前先確認 1。

## 順手發現的一個限制

`cmd/probe` 的 `-peek` 說是吃「IDA 線性位址」，但那個換算是 **rich2 專屬**的
（拿 Pool 的位址進去，回報的執行期位址是 `FFFF1100`，內容全 0）。probe 本身
是通用工具，這個旗標卻不是——接第二個程式時會誤導人。要嘛讓換算可設定，
要嘛把旗標改成直接吃 `seg:off`。
