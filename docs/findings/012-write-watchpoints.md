# 012 — 記憶體寫入監看：「誰寫了這個位址」用觀測回答

日期：2026-09-05
狀態：已用，一跑就解掉一個靜態掃不出來的問題

---

## 1. 靜態掃描的兩個盲區

「誰寫了這個位址」是逆向裡最常問的問題，而交叉參考掃描對兩種寫法是盲的：

| 寫法 | 為什麼掃不到 |
|---|---|
| `mov ds:9896h, ax` | 段值由 `mov ax, cs / mov ds, ax` 設，IDA 沒把它傳播進來 ⇒ **不建 xref**，也不是 `[reg+disp]` 位移 |
| `ptr = &x` 之後 `es:[di] = v` | 間接寫入，來源與目標之間沒有靜態關聯 |

⚠ **兩支工具都回 0 的時候，形狀與「真的沒有人寫」一模一樣。**
臥龍傳專案為此推過一個錯的假說（「一定是指標間接寫」），繞了一整輪。

## 2. 作法

```go
m.WatchWrites(lo, hi, fn)          // internal/machine：Write8 裡一道範圍判斷
o.OnWrite(lo, hi, func(o, hit))    // oracle：把 hit.At 換成 IDA 位址
```

`shot` 的動作：

```
wwatch:LIN:N          盯 IDA 線性位址起 N 個 byte
unitwatch:側,隊,位     盯某個兵的座標欄位（臥龍傳專用）
unwatch               收掉
```

## 3. ⚠ 指令位址不能用 `CS:IP`

取指令會把 `IP` 推進，所以**在記憶體寫入發生的當下**讀 `Seg[CS]:IP`
拿到的是**下一道**指令的位址。要回答「誰寫的」一定要用
`cpu.Op()`（本道指令的起點，`opCS:opIP`）——它本來就存在，
除法例外與中斷都靠它。

## 4. 一跑就解掉的問題

臥龍傳的「開場的兵擺在哪裡」：`sub_19AF4` → `sub_19B6D` 寫體力、戰力、
命令——**就是沒寫座標**，而座標欄位是段內偏移（沒有交叉參考）。
掛上監看，一跑三行：

```
#46398899 寫 744D6 ← 00（X）    來自 19ADF   ← 清零
#46422756 寫 744D8 ← 1C（Y）    來自 19C61   ← ★
#46422762 寫 744D6 ← 01（X）    來自 19C7B   ← ★
```

`sub_19C45` 因此定案：X 寫死在戰場邊界、Y 是 `亂數 & 0x1F + 0x10`、
不查佔用。詳見臥龍傳專案 `docs/re/87`。

## 5. 邊界

- 只盯 `Write8`。`Write16` 走兩次 `Write8`，所以一個字的寫入**會叫兩次**。
- 一次只能盯一段。要盯多段就自己在回呼裡分流。
- 範圍是**線性位址**（`Addr.Linear()`），不是 IDA 位址；
  而回報的 `At` 是 IDA 位址，因為那是拿去查筆記的那一個。
