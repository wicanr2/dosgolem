# 010 — 走到罕見畫面很貴，所以要從快照分岔

日期：2026-09-05
狀態：已用，戰術畫面的 20 個熱區一次問完

---

## 1. 問題

走到臥龍傳的戰術畫面要 **4.57 億道指令**（載入存檔 → 編成 → 等 AI 打過來，
35 個遊戲日）。牆上時間約 25 分鐘。**每問一個問題就重跑一次是不可行的**——
「點側欄第三列會怎樣」這種問題有二十個。

## 2. 作法

`oracle.State` 早就在（`docs/spec/005` §5），缺的是腳本這一層的入口。
加了兩個動作：

```
save:NAME       記下目前的機器狀態
restore:NAME    倒回去
```

於是一次執行變成一棵樹：

```
runto:11B5A,600000000   ← 一次，4.57 億道指令
steps:6000000
save:b
tap:40,384;shot:a1;restore:b      ← 每個分支 500 萬道指令
tap:510,287;shot:b1;restore:b
…
```

⚠ **不落地成檔案。** 快照裡是原版的整份記憶體映像，寫到磁碟等於散布它
（`oracle.State` 的說明）。所以分支只能在**同一次執行裡**展開——
而那正好夠用。

⭐ **指令數會一起倒回去**，所以分支之間真的互不影響：實測每個分支
`restore` 之後都回到 `463309447`，八個分支的起點完全相同。
這也是最便宜的正對照：數字不一樣就表示快照漏了東西。

## 3. 一次問完的東西

戰術畫面的熱區圖（`hotspots`）與八個分支的逐區差異，在**一次執行**裡拿到：

| 分支 | 動作 | 只有這一區變了 |
|---|---|---|
| a1 | 點底列第一格 | `bottom` 90 px（選取框）|
| b1 | 點「突擊」兩次 | `sb-command` 93 px |
| c1 | 點 `▶▶` 列 | `sb-arrow` 81 px |
| d1 | 點陣形帶 | `sb-formation` 94 px |
| e1 | 點「城壁」 | `sb-command` 92 px |
| f1 | 點右側陣線格 | `sb-command` 86 px |
| g1 | 點小地圖 | `sb-minimap` ＋95 px |
| h1 | 點「退却」 | `sb-command` 63 ＋ `sb-arrow` 27 px |

**每個熱區只改自己那一區**——這是側欄分區切得對的執行期證據。

⚠ 順帶量到一件對拍很重要的事：**小地圖會隨時間變**。
純等待兩千萬道指令、以及上面每一個分支，`sb-minimap` 都是同樣的 488 px。
它不是穩定區，拿它當「有沒有變」的判準會一直誤報。
