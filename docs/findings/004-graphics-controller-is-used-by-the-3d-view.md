## 一句話

`spec/007` §4 寫「圖形控制器（`3CE`／`3CF`）…全部不做。**這一支程式一個都
沒用到**」。那句話在寫下來的當天是對的——當時程式停在標題畫面。
補上鍵盤（`008`）與寫檔（`009`）之後它走到第一人稱視野，
`3CE` 立刻被寫 2,745 次。

## 量到什麼（`cmd/shots`，鍵序走到導覽結束）

| 埠 | 次數 | 值 |
|---|---|---|
| `3C4` 序列器索引 | 6,966 | 全部是 `02`（Map Mask）|
| `3C5` 序列器資料 | 314,014 | `01 02 04 08 0F` |
| **`3CE` 圖控索引** | **2,745** | `00 01 02 03 04 05 07 08` |
| **`3CF` 圖控資料** | **2,790** | `00 01 02 0F FF` |

索引 `00`／`01` 是 Set/Reset 與 Enable Set/Reset，`03` 是 Data Rotate／
邏輯運算，`04` 是 Read Map Select，`05` 是模式暫存器，`08` 是 Bit Mask。
**整組都用上了**，不是零星幾個。

## 症狀

第一人稱那一框畫出來是**黑底加白色線框**：透視的輪廓在，顏色與填色不在。
`docs/reference` 那邊的 DOSBox 基準圖同一格是天空、水面與棕色木棧道。
逐格比 88×88 只有 18.93% 相同。

畫面其餘部分（繩索外框、文字、標題美術、選單）**都是對的**——
所以這不是平面式 VRAM 壞掉，是少了 Set/Reset 那一條路：
沒有它的時候 CPU 寫進去的位元組直接落到每一個開著的平面，
於是每一格不是全 0 就是全 1，也就是黑與白。

## 教訓（寫成規則，不是寫成事件）

**「這支程式沒用到 X」這種斷言的有效範圍，是量測當下程式跑到的地方。**
它會隨著程式走得更遠而失效，而失效的時候不會有人來通知——
畫面照樣畫得出來，只是畫錯。所以：

1. 「不做什麼」那一節要寫**憑什麼現在不用做**，不要寫成「這支程式不用」。
2. 每一次讓程式走得更遠（補輸入、補存檔、補時序），**重量一次同一批埠**。
   `cmd/shots` 每一輪都印顯示埠統計就是為了這件事。

同一個坑的第三次：`007` §2.3 的「VRAM 讀取側不必做」、
`008` §2.1 的「遊戲的鍵盤輸入不走 `int 16h`」，都是把一支程式某一刻的觀測
寫成了通則。
