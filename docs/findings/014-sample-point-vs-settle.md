# 014 — 「點一下」不是零成本：預設 settle 六百萬道指令 ＝ 二十幾個節拍

日期：2026-09-06
狀態：已用，靠它把狀態層對拍的 272 個假差異降到 0

---

## 1. 症狀

拿原版執行期記憶體裡的三張表（勢力／據點／武將）跟 remake 的狀態逐欄比，
得到 **272 個不同欄位**——全部集中在**編號 118–141 這一段連續據點**的
三個欄位（上昇值、防災值、城兵數）。

「一段連續的編號」是線索：規則分歧不會挑編號相鄰的物件下手，
**巡迴游標**才會。

## 2. 成因

`Click` 放開之後預設再跑 `DefaultHold` 道指令讓遊戲把畫面畫出來。
對回合制那是「等畫面」，對**即時制**那是**遊戲時間**：

```
六百萬道指令 ÷ 約 25 萬道/節拍 ≈ 二十幾個節拍
```

而內政的巡迴游標一個節拍處理一個據點——正好掃過二十幾個。

⇒ **兩邊的取樣點差了三個遊戲小時**，而那看起來完全像規則分歧。

## 3. 作法

`click:X,Y,N` 的第三個參數是 settle（`oracle.Settle`）：

```
click:300,151,300000    載入存檔，放開之後只跑 30 萬道指令
```

實測落在「載完了、內政還沒動」那一段。兩邊的時鐘都停在
`196年4月16日 10時`，272 個差異歸零、**5,502 個欄位一個都不差**。

## 4. ⚠ 不要用「跑幾天之後」的狀態比

把兩邊都推到三天後再比，差異變成 582 個，而且**方向兩邊互見**
（有的原版大、有的另一邊大）。那是天災與內政帶亂數、兩邊各自擲骰——
不是規則分歧。

**動態欄位只在同一個時刻可比。** 要比跨時刻的行為，比的是規則的形狀
（誰在什麼條件下改了什麼），不是數值。

## 5. 可以搬去哪

任何「即時制 ＋ 用輸入動作定位狀態」的 oracle。判準是：
**送一個輸入之後，程式自己的時間走了多少？** 那個數字要問得到、
而且要能調小。問不到的話，「同一個狀態」這句話就沒有意義。
