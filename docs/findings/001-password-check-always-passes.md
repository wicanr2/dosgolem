## 結論

`cmd/solvepw` 三題連過，而且**怎麼點都過**。一開始把它記成 dosgolem 的
行為差異；查了 `rich2/docs/re/171` 之後定性為**正確重現原版**。

原版的判斷式被短路（`1BEC2`–`1BF24`）：

1. `1BEC2` 從答案表算出正解，`1BEE7` **把它存進 `ds:F1Eh`**
   ——玩家的答案就在這一刻被蓋掉；
2. `1BEF9` 再算一次同一個正解，`1BF1B` 拿它跟 `ds:F1Eh` 比，
   **兩邊必定相等**，於是 `1BF24` 一律 `ds:668h = 1`；
3. `1BEED`（答錯該做的記帳）**沒有任何進入邊**——全影像掃過九種跳躍，
   一個都沒落在那裡。

所以三題的儀式照跑，但答案不影響結果。

## 這裡量到的邊界

| 實驗 | 結果 |
|---|---|
| 三題都選綠色 | 全過 |
| 三題都選藍色 | 全過 |
| 不點留白區，改點立繪上的空白處 | 全過 |
| **完全不點，跑 1.4 億道指令** | **畫面完全不動**，還是第一題 |

最後一列排除了「換題是計時器驅動的」：**點擊確實有被處理**，
只是顏色與位置不影響判定——與指令層讀出來的完全一致。

## 它回答了一個待驗的問題

`rich2/docs/re/171` §6 把「答什麼都算對是不是原版行為」列為待驗，
建議的驗法是「在 DOSBox 上第一題故意點錯的顏色」。

dosgolem 這邊等於做了那個實驗，而且更徹底（連「不點留白區」都試了）。
