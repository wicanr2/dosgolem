# 011 — 把原版當函式庫用：兩個靜默的坑

日期：2026-09-05
狀態：已用，臥龍傳的戰術畫面第一次「指定要開哪一場」

---

## 1. 問題

有些畫面只有在遊戲**自己決定**要開的時候才出現。臥龍傳的戰術畫面要等
AI 打過來——**4.57 億道指令、35 個遊戲日**，而且打哪一場不由人。
兩邊要開同一場仗來對拍，就更不可能。

## 2. 作法

遊戲自己那一支長這樣：

```
sub_14ADE(si ＝ 攻方軍團記錄, di ＝ 據點記錄)   ; near call
```

它自己會把該寫的全域寫好、配好堆疊暫存區、挑出守方。**擺好兩個暫存器
叫下去就行**——成本降到 4,380 萬道指令。

`oracle.CallNear(addr, ret, regs)` 做這件事：推一個假的 near 返回位址、
擺暫存器、把 CS:IP 設過去。

## 3. 坑一：段不能用正規化的段

`IDA(linear)` 回的是 `Addr{linear >> 4, linear & 0xF}`——**正規化的段**。
讀寫記憶體用它沒問題（線性位址一樣），但**跳進去執行就不行**：

> 常式裡每一個 `cs:xxxx` 的**絕對定址**都會偏掉。

臥龍傳那一支開頭就是 `mov al, cs:byte_10CFF`（玩家的勢力編號）。
段偏掉之後它讀到別塊記憶體，於是判定「兩邊都不是玩家」→ 直接自動判定，
**戰術畫面不會開，而且沒有任何錯誤**。

⇒ `oracle.IDAIn(seg, linear)`：段給**程式自己現在的 CS**。

## 4. 坑二：要從一個已知的靜止點叫下去

第一版從「上一個 `steps` 停在哪」就叫下去，結果畫出一個**內容是雜訊的
訊息框**然後卡住——因為那一刻可能停在某支繪圖常式中間，視窗狀態不一致。

⇒ 先 `RunUntil(At(sub_1E453))`。那是命中測試，主迴圈每一圈都會進，
**進到那裡就表示遊戲正閒著等輸入**。

⭐ 這個修法順帶把**堆疊平衡**也解決了：假返回位址挑 `sub_14ADE` 自己的
`retn`，它會再彈一次——彈掉的正好是 `sub_1E453` 的返回位址，
於是遊戲回到閒置迴圈，像那一圈的命中測試回來了一樣。

## 5. 結果

臥龍傳專案拿它對拍：同一份存檔、同兩支軍團、同一座城，
**九區裡七區逐像素相同**，`field` 0.10%（那 180 px 是原版畫的滑鼠游標
與旗的揮舞相位）。詳見該專案的 `docs/playtest/72`。

## 6. 什麼時候不要用

`CallNear` **不適合當函式呼叫**——返回位址是假的，回來那一跳會比原本多
吃掉呼叫端堆疊上的一個字。它適合「叫下去之後就在裡面」的用途
（開一個畫面、進一個迴圈）。要真的呼叫並拿回傳值，得另外做一個
會停在返回點的版本。
